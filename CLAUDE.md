# my-university — project guide for Claude

Self-study web app (formerly "QA Academy") with a **catalog of IT professions**: the learner picks a course on the main menu (`/`) and goes from zero to their first job. Courses: QA Automation Engineer — TypeScript + Playwright (complete: 20 core modules + module 33 "Specialist Skills" as an extra last track), QA Automation Engineer — Python + pytest + Playwright (complete: Python modules 21–32 + the shared QA, web, Git, SQL and job modules + module 34 "Specialist Skills for Python QA" as an extra last track), Manual QA Engineer, Python Developer, Frontend Developer, Backend Developer (Node.js). Single learner, runs locally, no backend, no accounts, no paid APIs. The owner may sell the courses later: write all content from official docs and own knowledge — **never** copy or paraphrase other course providers' materials (e.g. Mate Academy).

- **UI language:** English. **Lesson content:** Ukrainian, with English technical terms (`string`, test case, severity…). Code identifiers, test names and model answers for QA artifacts in English.
- **Address the learner gender-inclusively** (owner's rule): every past-tense verb or adjective that refers to the learner — after «ти», in imperative hints, checklists, sample answers in the learner's voice — uses the inclusive form: `писав(ла)`, `знайшов(ла)`, `навчився(лася)`, `звик(ла)`, `сам(а)`, `готовий(а)`. Never only masculine or only feminine. Forms with another subject (тест упав, розробник закрив, сторінка показала) and quotes addressed to someone else stay as they are; inside code blocks / diagrams prefer an impersonal wording (`якщо обрано`).
- Owner is a beginner: explanations must assume zero background, be concrete, QA-flavoured.

## Commands

```bash
npm install
npm run dev        # http://localhost:5173 (also serves the Gadgetly mock API at /api)
npm run validate   # validates ALL content + proves every code task is solvable — run after every content change (web page tasks run in the Chromium of lab/.browsers: npm run lab:setup once; without it they are skipped with a warning)
npm run validate:lab  # runs every Playwright task (reference must pass + catch all bugs, starter must not pass) in real Chromium — run after changing Playwright tasks or playground pages
npm run lab        # the learner's own Playwright practice tests in lab/tests (npm run lab:report, npm run lab:setup = install Chromium)
npm run lab:python-setup  # Python lab, once: lab/.venv with pinned lab/python/requirements.txt (pytest, pytest-playwright, playwright == the @playwright/test version, FastAPI…) + Chromium in lab/.browsers
npm run lab:py     # the learner's Python practice tests in lab/python/tests (app must be running); npm run lab:py-codegen -- <url> / lab:py-trace -- <trace.zip>
npm run lab:py-api # the learner's own FastAPI app lab/python/api/main.py with fastapi dev on http://127.0.0.1:8000 (/docs = Swagger UI); no app or browser needed
npm run lab:py-django -- runserver   # manage.py of the Django practice project lab/python/django_site (app "library"; also migrate, createsuperuser, makemigrations, shell, check; db.sqlite3 is gitignored)
npm run typecheck  # tsc on src/ and scripts/
npm test           # the sync merge rules (scripts/check-sync-merge.ts) — run after changing src/features/sync or ProgressData
npm run build      # typecheck + production build
```

Windows note: Node is installed at `C:\Program Files\nodejs` — if `node` is not on PATH in a shell, prefix with `$env:Path = "C:\Program Files\nodejs;" + $env:Path`.

Launcher: `Start my-university.cmd` (CRLF line endings, ASCII only) + desktop shortcut `my-university.lnk` with icon `launcher/qa-academy.ico` (both were "QA Academy" before the rename; the shortcut points at the .cmd by path, so renaming the .cmd means updating the shortcut). It opens http://localhost:5173 if a server is already listening, otherwise runs `npm install` (first time), `npm run lab:setup` (Chromium into lab/.browsers, no-op when present) and `npm run dev -- --open`.

**Playwright browsers and the Claude app:** Claude's shell runs inside the Claude desktop app package, so anything it writes to `%LOCALAPPDATA%` (e.g. the default `ms-playwright` folder) lands in a *virtualized* copy (`…\Packages\Claude_*\LocalCache\Local\…`) that the owner's own processes cannot see. That is why the lab keeps its browser in the project: `npm run lab:setup` (scripts/lab-setup.ts) installs Chromium into `lab/.browsers` (gitignored), `lab/playwright.config.ts` sets PLAYWRIGHT_BROWSERS_PATH to it when it exists (workers inherit it), and `/__lab/status` checks it first. The project drive (D:\) is not virtualized, so installs done by Claude are visible to the owner's dev server. The Python lab follows the same rule: its venv is `lab/.venv` (gitignored; `npm run lab:python-setup` creates it from the owner's own Python via `py -3`), and Python `playwright` is pinned to the same version as `@playwright/test`, so both labs share the Chromium in `lab/.browsers` — bump both together.

The dev port is pinned (`strictPort`, `DEV_PORT` in vite.config.ts) because localStorage progress is tied to that origin — never change the port.

## Website (GitHub Pages) and phones
- The same app is published as a static website for learning on a phone: **https://czszwxy.github.io/taqc-course/**. `.github/workflows/deploy-site.yml` builds it on every push to `main` with `VITE_BASE=/taqc-course/` and `VITE_STATIC_SITE=1`, copies `index.html` to `404.html` (deep links) and deploys to Pages (repo Settings → Pages → Source: GitHub Actions). Local rehearsal in Git Bash needs `MSYS_NO_PATHCONV=1` before the env vars (otherwise `/taqc-course/` becomes a Windows path).
- `src/site.ts`: `IS_STATIC_SITE`, `ROUTER_BASENAME` (BrowserRouter basename), `withBase(path)`. Raw `<a href>` / `<iframe src>` / `window.open` to app routes must use `withBase('/playground/…')`; router `<Link>`s are fine. Files the app loads itself use `import.meta.env.BASE_URL` (Pyodide in python.worker.ts).
- No server on the website: `src/site/mockApi.ts` intercepts `fetch` to `/api` and `/api-fixed` and answers with `handleApiRequest()` from `server/mock-api.ts` — the **same** code the dev-server middleware uses (keep mock-api.ts free of Node-only APIs outside the middleware: no `Buffer` in handlers). Playground pages keep calling absolute `/api/...`. Orders created on the website live in memory until reload. Playwright tasks show "This task runs on your computer" (lab client returns `SITE_LAB_MESSAGE`, Run/Check disabled). DevTools Network hunts are PC-only (intercepted requests do not show in the Network tab).
- Progress is per device (localStorage per origin). Two ways to share it: Settings → Export / Import, or **sync** (`src/features/sync/`): the learner pastes their own GitHub token (classic, only the `gist` scope) into Settings on each device; the app keeps one secret gist `my-university-progress.json` and syncs on start, ~8 s after changes and on visibility changes. `merge.ts` (pure) never loses progress: solved stays solved, counters take the max, lessons / checked links are united, the newer draft wins (`draftTimes` in ProgressData). Undoing "theory read" or "I checked it" leaves a tombstone (`undone`: `theory:<lessonId>` / `link:<url>` → time; links hold the time they were checked, older files `true`), and on each key the newer of done / undone wins — otherwise the other device's copy brings the item back. A gist file that exists but cannot be read (bad download, not progress JSON) stops the sync with an error instead of being overwritten. Import and Reset with sync on start a new **epoch** (their time, saved in `my-university:sync` at once, so it also wins after an offline reset) and push with `replace`: a device that sees a newer epoch in the gist takes the gist's progress plus only its own changes made after that time (`changesSince` in merge.ts) — otherwise the other devices would merge the old progress back. Connecting a device joins the gist's epoch (connect = combine). When the saved gist is gone, sync reads the gist found or created instead of overwriting it. Tested end to end against a fake GitHub API (two and three browser contexts) — never with a real token. The token lives in localStorage `my-university:sync` only — never in exported progress; Claude never handles the token.
- Phone layouts: code / Python / Playwright task views stack on small screens (statement first, page scrolls; `lg:` keeps two columns). `src/components/CodeEditor.tsx` = Monaco on computers (lazy `MonacoCodeEditor.tsx`, so phones never download it) or a simple touch editor (textarea, line numbers, auto-indent, Backspace / ⇤ remove an indent level, a row of keys; insertions go through `execCommand('insertText')` so fast typing and undo work); `editorMode` (auto / full / simple) in Settings. Table tasks render one card per row below `md`. Fields are 16px on touch screens (no iPhone zoom). Check new UI at 375 px wide. Nothing may be wider than the screen (the owner saw lesson pages drift sideways on the phone): inline code in lessons wraps (`overflow-wrap: anywhere`, never `nowrap`), long unbreakable text (paths, URLs, file names in flex rows) gets `[overflow-wrap:anywhere]` + `min-w-0`, and `<main>` is `overflow-x-hidden overscroll-none` (html / body `overscroll-behavior: none`) as a safety net. To audit, compare `#main.scrollWidth` with its `clientWidth` on every route at 375 px.
- The site is a manifest-installable web app (`public/manifest.webmanifest`, icons rendered from `favicon.svg`): "Add to Home screen" opens it full screen.

## Code style (enforced by a TS-patterns hook on edits)
No nested ternaries (use a small function or a Record lookup), no magic numbers (named consts, e.g. `formatModuleNumber` in `src/lib/format.ts`), prefer `map/filter/reduce` over raw loops in app code. Content task files (`content/**`) are learner exercises and intentionally use loops.

## Theme ("QA Notebook")
The app's own look (chosen by the owner so it does not resemble other course platforms): light = **grid paper** with ink, a yellow **highlighter** and a red **pen**; dark = a **blueprint** (navy paper, light grid). Colors are CSS variables in `src/index.css` (`:root` = light, `.dark` = dark), exposed to Tailwind as `bg-canvas / bg-surface / bg-hover / bg-sunken / border-line / text-fg / text-muted / text-faint / *-accent* / text-accent-on / *-ok* / *-bad* / *-warn* / bg-highlight + text-highlight-fg / text-pen / *-track*`. Layering: canvas < surface < hover (hover is always *lighter* in dark mode). Body text targets ~12:1 contrast, secondary ≥ 4.5:1. Text on `bg-accent` uses `text-accent-on` (never hard-coded white — the dark accent is light).
- Fonts are bundled locally via `@fontsource-variable/*` (imported in `src/main.tsx`; all with Cyrillic): Manrope (`font-sans`, UI and body), Lora (`font-display`, page titles and lesson headings), Caveat (`font-hand`, short handwritten notes in pen colour — use sparingly), JetBrains Mono (`font-mono`, code and the Monaco editors). Code never uses ligatures (beginners must see `===`, `>=`).
- Notebook helpers (index.css components): `.page` (solid paper card for long reading on top of the grid), `.marker` (highlighter behind a word; full marker in dark mode), `.hand` (handwritten red-pen note), `.sticky-note`, `.track-tab` + `track-1…6` (coloured divider tab per course track; `trackClass(i)` / `TrackTab` in `components/ui.tsx`, `trackIndexOf(moduleSlug)` in `src/app/tracks.ts`). Callouts render as notes: TIP = sticky note with tape, NOTE = index card, WARNING = dashed box, IMPORTANT = red-pen box, QA = ink-bordered card; labels in the handwritten font.
- Icons: app chrome uses the ink line icons of `src/components/icons.tsx` (`<Icon name="bug" />`, stroke = current text colour), never emoji (they differ per device; flag emoji show as letters on Windows). Emoji stay only as content (course icons) and in feedback texts of task views. Callout labels are plain handwritten words.
- Small print: inside the app chrome (`.app` on the Layout root) `text-xs` is 13px; playground pages sit outside it and keep 12px. Light `--c-faint` passes 4.5:1 on `bg-hover` too.
- Task pages (`/learn/:m/:l/:task`): the top bar spans the full width and `<main>` is plain canvas (no grid under the task text). Code inside lesson tables never breaks mid-word (the table scrolls sideways instead).
- Course map = **route** (`src/app/RouteMap.tsx`, chosen by the owner over module cards): the course is a transit line on a `.page` card from the first module to the terminal station "First job". Each track is a line in its track colour with an interchange (ink capsule + numbered line badge) where it starts; modules are stations (filled = done, big ring + yellow "you are here" = the module of the last visited page in this course, otherwise the first unfinished one; tinted = started; ring = ahead; dashed on a dotted line = coming soon); lessons are small stops next to the station with a count ("2 of 8 done" / "8 lessons"). On phones the stops wrap under the title. The same line continues on the module page (lessons are stations on the module's stretch, "you are here" = the last visited lesson of this module, otherwise the first unfinished one; built from `Rail` / `StationMarker` / `HereLabel` exported by RouteMap.tsx), in the catalog (each profession card shows a mini route: one dot per module in the same states, the "First job" terminal at the end, no button inside the card link), in the lesson menu (`LessonMenu`: compact rows, `size="compact"` of `Rail` / `StationMarker` / `linePosition`) and on task pages (`TaskStops` in TaskPage.tsx: the lesson's tasks as numbered stops — filled = solved, tinted = tried, outlined = the open task). Screen readers get the state as hidden text (`STATE_LABEL`), since the markers are `aria-hidden`.
- Task pages: split views (code, Python, Playwright, web) fill the window; every other task type is wrapped in `.task-sheet` by TaskPage, which turns the view's own centred column into a `.page` paper sheet. On phones the lesson tabs hide the resources count so the three tabs fit 375 px.
- Motion (few, purposeful, `transform` / `opacity` only): `--ease-out` in `:root` is the strong ease-out `cubic-bezier(0.23, 1, 0.32, 1)` (it also replaces Tailwind's `ease-out`). `.enter` (index.css, `@starting-style`) eases in content that appears on request — revealed hints, opened `Collapsible` panels, check results (`Callout`, `FailureList`), the self-review checklist, the phone lesson menu — 180 ms, 4 px down + fade; reduced motion keeps only the fade. Theme switches go through `switchTheme()` (src/app/theme.ts): a View Transitions cross-fade (browser default 250 ms; instant where unsupported; it waits for a painted frame, so it stalls in a hidden preview pane). `.station-here` pings twice on arrival on the course map and the module page only (not the lesson menu); off with reduced motion. Stops and station markers change colour with `transition-colors duration-200`. Also: every new page fades up 6 px in 200 ms (`.route-enter` on a wrapper in Layout keyed by pathname — tabs and `?v=` do not replay it; the wrapper is `h-full`, so split task views keep their height); the lesson tab panel eases in (`.enter` keyed by tab); a task solved during the visit pops its checkbox and draws the tick (`StatusIcon celebrate`, TaskPage remembers the status on arrival); catalog cards rise in 50 ms apart (`.rise` + `--i`) and lift 2 px on hover with a deeper paper shadow (`.lift`, hover-capable pointers only); the big route maps draw their line and pop their stations as rows scroll in (`.rail-line` / `.rail-mark`, scroll-driven `animation-timeline: view()` inside `@supports`; rows already on screen are drawn; without support everything is static). Reduced motion: fades only, no ping, no line drawing, no lift. Text the learner reads never moves for decoration.
- **Workdesk** (`src/features/workdesk/`, approved by the owner from a mockup): once the learner has any progress, `/` shows it instead of the welcome hero (the professions grid stays below). Cards: Continue where you stopped (last visited lesson of the current course — or the next one when it is finished — with a mini route of the module and "about N min left"), Today's goal (ring of tasks solved today; goal 1 / 3 / 5 in its own persisted store `my-university:goal`, goal.ts — to be moved into synced settings by the accounts work), Day streak (two-week Monday-first habit grid; a day counts when a task was first solved that local day — `solvedAt`), Sticker book (`STICKERS` in stats.ts: milestones from solved task types, counts, streaks, lessons / modules done — counted over every profession and never against the goal setting, so an earned sticker never goes away), Rank (Beginner → Explorer → Practitioner → Almost there → Job-ready by course percent). All numbers are pure functions of ProgressData in stats.ts (`npm test` checks streaks, the grid and ranks). Motion: cards `.rise` + `.lift`; the ring and the rank bar fill (WAAPI) from what this device showed last time (`my-university:workdesk-seen`, per device, never synced); reaching the goal pops the ring (`.goal-pop`), the first solve of the day draws today's tick, new stickers land (`.sticker-land`); stickers lie crooked (`--rot`) and straighten on hover. Phone: one column, Continue then the goal.
- Brand wording: the app is "my-university" (lowercase, one hyphen; logo = "my-" + "university" under the highlighter). The catalog lists **professions** — the nav link, its page and the back links all say "Professions"; "course map" is the map of one profession. `<meta name="theme-color">` follows the theme (App.tsx copies `--c-surface`), so a phone's browser bar matches the top bar.
- Layout: a top bar (`src/app/Layout.tsx`: logo, Professions, Bug Playground, theme, settings; the lessons counter only on course / module / lesson pages) — no global sidebar, no course link in the bar (the owner found it redundant; module and lesson pages link back to their course map). Opening a module of another course makes it the current course (`useCourseForModule`), so the counter and map links follow the page. `/course/:id` is the **course map** (the route: tracks → module stations with one stop per lesson). Lesson pages show `LessonMenu` (the current module's lessons, `src/app/LessonMenu.tsx`) as a sticky column on ≥lg and a collapsible menu on small screens. Status icons are notebook checkboxes (`StatusIcon`).
- Monaco themes `qa-dark` / `qa-light` in `src/monaco/setup.ts` mirror the palette. Playground pages keep their own fake-product look (PlaygroundShell) and are not themed.

## Stack

Vite 6 + React 19 + TypeScript, React Router 7, Tailwind CSS v4 (CSS-variable tokens in `src/index.css`, dark mode via `.dark` class), Zustand (+ persist → localStorage), Zod (content schemas), react-markdown + remark-gfm + rehype-highlight, Monaco (`@monaco-editor/react`, bundled locally — no CDN), real `typescript` compiler in a Web Worker, `sql.js` (SQLite in WebAssembly, wasm bundled locally via `?url`) for SQL tasks, **Pyodide** (CPython in WebAssembly, npm `pyodide`; vite.config.ts serves its 5 files at `/pyodide/` in dev/preview and emits them into `dist/pyodide/`) for Python tasks, plus bundled package wheels from `vendor/pyodide-packages/` served and emitted next to them (SQLAlchemy 2.0 + typing_extensions; list in `src/runner/python-packages.ts`). Dev-only: `jsdom` (validator checks selector tasks), `tsx`, `esbuild` (scripts/web-node.ts bundles the web-task checker for Chromium).

## Architecture

```
content/                     ← ALL course content (data only, no code changes needed to add lessons)
  databases/<name>.sql       ← SQLite setup scripts for sql tasks (gadgetly.sql = clean shop data; gadgetly-anomalies.sql = defects applied on top)
  courses/<id>.json          ← one profession each (catalog fields + tracks → modules). Modules are a SHARED POOL: a course lists module slugs; one module (Git, SQL, testing theory, Getting Hired, Python basics…) can be in several courses and its progress counts in all. A module entry needs `lessons` (planned titles) only when the module is not built yet. Modules without a folder show as "coming soon". Module numbers shown in the UI are positions inside the course; folder prefixes (`21-…`) are pool ids (unique, two digits).
  modules/<NN-slug>/module.json
  modules/<NN-slug>/lessons/<NN-slug>/lesson.json   ← title, minutes, summary, resources[]
  modules/<NN-slug>/lessons/<NN-slug>/lesson.md     ← theory (Markdown, callouts)
  modules/<NN-slug>/lessons/<NN-slug>/tasks/<NN-slug>/task.json (+ starter.ts / solution.ts / tests.ts for code tasks)
src/
  content/schema.ts          ← Zod schemas = the content format contract (source of truth)
  content/loader.ts          ← import.meta.glob discovery; builds Course tree; lazy-loads lesson.md and task .ts files
  runner/compiler.ts         ← pure: real TS compiler over in-memory FS (strict, ES2022 libs, CommonJS emit)
  runner/harness.ts          ← pure: Jest-like describe/it/expect + CommonJS loader + console capture
  runner/harness-dts.ts      ← globals the compiler sees (console, timers, fake fetch, describe/it/expect, hooks, captureConsole); TEST_GLOBALS_DTS is also added to Monaco
  runner/fake-fetch.ts       ← pure: offline fake fetch (Gadgetly API at https://api.gadgetly.test) for async/fetch lessons
  runner/mutation.ts         ← pure: tests-mode checking (learner tests vs subject.ts and mutants)
  runner/client.ts           ← main-thread API: checkCode / runCode (compile worker reused; exec worker per run, 5 s timeout)
  runner/*.worker.ts         ← Web Workers
  runner/python/qa_runner.py ← Python test runner (runs inside Pyodide): test_* functions and Test* classes without __init__ (fresh instance per test, names `TestCart::test_add`), assert messages like pytest ("assert 4 == 5"), docstring = hint, fixtures (yield, scopes, autouse, conftest.py; detected strictly — Mock objects in a test module are not fixtures), parametrize (ids, pytest.param with id/marks), marks (skip / skipif / pytest.skip → "(skipped: …)", xfail → "(xfail)", strict XPASS fails, usefixtures, class marks), @mock.patch arguments skipped like pytest, capsys, monkeypatch (undone after each test), tmp_path (fresh folder per test under /tmp/qa-tmp, wiped each run); run_program for the Run button
  runner/python/pytest_shim.py ← offline pytest subset written into the task folder as pytest.py (raises, approx, fail, skip, param, mark.parametrize, mark objects for skip / skipif / xfail / usefixtures / custom markers, fixture with scope / name / autouse)
  runner/python.worker.ts    ← loads Pyodide once from /pyodide/ and runs jobs; python-client.ts = main-thread API (5 s per run after Python loaded; a timeout kills the worker) + checkPythonSolution / checkPythonTests (mutants) + evaluatePythonRules
  runner/python-packages.ts  ← bundled Pyodide packages (wheels in vendor/pyodide-packages, from the Pyodide release matching npm `pyodide`): the worker and scripts/python-node.ts load a package only when a job's files import it, then run its warm-up import BEFORE posting "started" (SQLAlchemy's first import takes ~1.3 s in Node, so it never counts against the 5 s limit). Adding a package: download its wheel + missing deps (names / sha256 in pyodide-lock.json) and add an entry, dependencies first
  runner/python-lab-client.ts ← "runtime": "lab" python tasks: POSTs jobs to /__lab/python/run (status: /__lab/python/status); on the website returns `unavailable` (Run / Check disabled, "This task runs on your computer")
  runner/python-rules.ts     ← pure code-rule helpers for Python (shared by the app, the validator and Playwright grading); a learner file ending in .html (a Django template) is checked without stripping "#" comments
  runner/web.ts              ← web page tasks: checkInFrame renders the page in an off-screen iframe with sandbox="allow-same-origin" (no scripts run, this window reads its DOM / styles / layout) and runs tests.js through the harness with the page's globals; checkWebTask adds code rules. Bundled by scripts/web-node.ts for the validator — one code path
  runner/web-page.ts         ← pure string helpers: starter.html → index.html names (LEARNER_FILE_OF), buildPage (styles.css replaces its <link>), linksStylesheet, evaluateWebRules (HTML / CSS comments stripped, default flags "im")
```

## Content format

### lesson.json

### Web page task conventions (Frontend course, module 48+)
- Globals in `tests.js`: `document` / `window` of the page, `$` / `$$` (querySelector / array of querySelectorAll), `text(el)` (whitespace-collapsed textContent), `must(value, message)` (a clean "Missing: …" failure instead of a TypeError on null), `css(el, prop)` (computed style), `box(el)` (getBoundingClientRect), `role(el)`, `accessibleName(el)`, `accessibleDescription(el)`, `isHidden(el)`, `headings()` (`[{ level, text }]`), `await setViewport(width, height?)` (resizes the page; a test that calls it should set it back), `color(el, prop = "color")` and `rgb(cssColor)` (both give "rgb(r, g, b)" / "rgba(…)", so compare `color(el)` with `rgb('#1d4ed8')`), `contrast(el)` (WCAG ratio of the text with the background behind it), `cssRules()` (`[{ selector, style, media }]` — for states a check cannot create: `:hover`, `:focus-visible`, `prefers-reduced-motion`), `simulateFocus(el)` (returns `release()`; shows the element with the page's focus styles). Compare primitives (strings, numbers, arrays of them) — a failing `toBe(element)` prints the element.
- Never use `instanceof HTMLElement` in checks: the page is another window (cross-realm, always false).
- A page in an iframe never switches to quirks mode (srcdoc rule), so check the doctype with `document.doctype`, not `document.compatMode`.
- `minlength` / `maxlength` only flag values typed by the user — checks set `.value` from code, so they assert the attributes (`input.minLength`), while `required`, `type="email"` and a `<select required>` with an empty first option do work with `form.checkValidity()`.
- Checks may change the page (fill fields, tick boxes, set ARIA attributes, override custom properties on `document.documentElement.style` to prove a token is used): every Check renders a fresh page.
- CSS checks (module 49+): the checker hides the page's scrollbar (`scrollbar-width: none` on <html>) — Windows' classic 15px scrollbars otherwise change every width measured at narrow viewports; layout checks compare boxes with ±1px (fonts differ between devices) and prefer relations (same top, left of, gap = 16) over absolute positions; never move the real focus (it only paints when the window has focus and steals focus from the editor) — use `simulateFocus` (it also switches off transitions on the element, so no waiting is needed); nothing in a check may wait for `requestAnimationFrame` or long timers — browsers pause them in background tabs (`setViewport` forces layout synchronously instead); the OS "reduce motion" setting reaches the page, so check transitions through `cssRules()`, not computed styles. `document.elementFromPoint` works in the hidden frame (used for z-index / sticky checks). Verified in headless Chromium **and** in desktop Chrome: run the reference + starters through `/src/runner/web.ts` in the dev page (loader's `loadWebTaskFiles`) after changing checks.
- Responsive checks (module 50+): `rem` and `em` in media queries follow the browser's default font size, which the learner may have changed — checks read it from a probe with `font-size: medium` (not a hard-coded 16) and test breakpoints at `40 * em - 1` / `40 * em`; "the user doubles the font" = `document.documentElement.style.setProperty('font-size', 2 × medium px)`, restored in `finally`; WCAG Text Spacing = an injected `<style>` removed afterwards. The OS dark theme reaches the page (the owner's system is dark): theme checks copy the custom properties of the `:root` rules (from `cssRules()`, in file order) onto `<html>` inline instead of trusting the current theme. `matchMedia('(hover: hover)')` is true on a computer and false on a phone — hover rules are checked through `cssRules()`. A `<picture>` picks its source before the hidden frame has its size, so `<picture>` / `srcset` tasks check attributes, not `currentSrc` or art-directed layout (broken images still keep the width / height ratio). Overflow tasks use a `sticksOut()` helper (every element whose box leaves the viewport, except inside an `overflow-x: auto / scroll` ancestor) plus `clipped()` (elements with `overflow: hidden / clip` whose content is wider) so hiding the overflow never passes. Long words that must overflow need a token without break opportunities — Chrome wraps URLs at `/` and `?`.
- The learner's `<script>` and inline handlers never run (no allow-scripts): HTML / CSS modules only. Scripting tasks (module 51 DOM, React) need a new runner decision.
- Theory examples use a library / news site / recipes / photo gallery; tasks use Gadgetly pages. Starters: the content is already there (plain text or broken markup) — the learner adds structure. Statements list exact texts and attribute values the checks compare.
- Before release, run plausible wrong versions of each solution (each must fail) and "ok-" alternatives (implicit labels, rel="noopener noreferrer", aria-labelledby…) that must pass.

### SQL task conventions
- Database facts the tasks rely on are listed in the header comment of `content/databases/gadgetly.sql` (users 7, 9, 10 have no orders; product 6 never ordered; user 9 city NULL; prices are integer UAH; dates are TEXT `YYYY-MM-DD`). Change the seed only together with the tasks — the validator will catch most breakages.
- Prompts name the exact columns in order; ask for "0, not NULL" explicitly when COALESCE is needed; avoid ties when `orderMatters` (add a tie-breaker to the prompt).
- sql.js returns no result set for a 0-row SELECT, so "no rows" and "not a SELECT" compare equal — fine for verify queries that should become empty.
- Use `rules` to stop hard-coded answers where the technique matters (e.g. require `left\s+join|not\s+(in|exists)` for "rows without a match", `<=\s*0` for "0 or less").
- Writing task JSON through a bash heredoc strips backslashes in regexes — write content with the Write tool (bundles) instead.

### Playwright task conventions
- Specs use relative URLs (`page.goto('/playground/login')`); baseURL is the app (port 5173). Lab timeouts: test 15 s, expect 3 s, action 5 s.
- Bug variants: each project's browser user agent gets `qa-lab-bugs=<none|bugId>` appended (lab/playwright.config.ts) — a learner's own `storageState` or new tabs/contexts keep it; pages read it through `withLabMode(getBugs(fixed))` (PlaygroundShell; localStorage `qa-lab:bugs` is only a fallback). It wins over `?fixed`. Every new playground page must wrap its flags the same way and list them in `bugIds` (registry.ts) in the same order. A page's bug count shown in the Playground is `bugIds.length` (registry derives it).
- API tasks: the `request` fixture (and `browser.newContext`) inherit the project's user agent, so the marker also reaches `server/mock-api.ts`, which applies it to its own bug flags (`applyLabBugs` + `labBugsFromUserAgent` in server/lab-types.ts) — API bugs are graded like page bugs (`bugIds` of the `api` page). Mutant ids may come from any page's `bugIds` (API + UI tasks mix them); `playground` only picks the "Open page" link.
- The mock API store is shared by all projects of a run (and by the owner's API console): API specs must create their own data, address it by id, clean it up, and never assert global counts or call `/reset`.
- Visual tasks: if the spec contains `toHaveScreenshot(`, the runner first runs the correct project with `--update-snapshots` (baseline), then all projects; graded runs share one snapshot folder (`snapshotPathTemplate`).
- The dev app runs React StrictMode: effects (and their fetches) run twice on mount — mocks in references must not rely on call counters (use a flag that the test flips).
- Starters: imports + one complete example test + `// твій код тут`; they must pass on the correct page but miss some bugs (or break a code rule) — `validate:lab` enforces that the starter does not pass.
- Prefer user-facing locators in references (getByRole/getByLabel/getByText, getByTestId when needed). Watch for partial label matches (`getByLabel('Password', { exact: true })`) and for requirement-panel text when using getByText.
- A Check runs ~5–20 s; keep 2–6 mutants per task.
- Python tasks (`"language": "python"`): `from playwright.sync_api import Page, expect`, test functions take `page`, relative `page.goto("/playground/...")`; starters = imports + one complete example test + `# твій код тут`; `codeRules` are checked on the code without `#` comments. `validate:lab` needs the dev server already running on 5173 for Python tasks (only the TS config starts it itself). On the login page the yellow requirements panel repeats the error texts — check messages through `get_by_role("alert")`, not `get_by_text`. Extra contexts in references use the `new_context` fixture (it carries `--base-url` and the lab timeouts); a session fixture that signs in once uses `browser.new_context(base_url=base_url)` + `tmp_path_factory`. First checks on a new tab get `timeout=10_000` (a cold page under a parallel Check). Dialog texts collected by a handler are asserted after the next `expect(...)`, not right after `click()`. `validate:lab -- <filter>` matches a substring of the task id. API tasks (module 29) may be pure `requests` modules (the validator accepts `import requests` instead of a playwright import): fixtures `api` (= `f"{base_url}/api"`), `auth` / `token` (session login), a yield `order` fixture that deletes what it created; every request with `timeout=`; mutants from the `api` page bugIds. The account page signs in without the form via `page.add_init_script` putting the token into localStorage `gadgetly:token`.
