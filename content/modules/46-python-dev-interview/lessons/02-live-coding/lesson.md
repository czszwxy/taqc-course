# Live coding: алгоритми й маленькі класи

Live coding — частина співбесіди, де ти пишеш код **при інтерв'юері**: у спільному онлайн-редакторі або у своїй IDE з демонстрацією екрана, 30–45 хвилин. Джуну дають задачі рівня модуля «Algorithms & Data Structures» або просять «спроєктувати маленький клас». Головне, що тут оцінюють, — **як ти думаєш**, а не чи знаєш напам'ять розв'язок.

## Що оцінюють

| Що | Як це виглядає |
|---|---|
| Комунікація | ти проговорюєш, що робиш і чому, а не мовчиш 10 хвилин |
| Уточнення | питаєш про вхідні дані, порожні випадки, помилки до того, як писати |
| Робочий код | простий правильний розв'язок важливіший за «оптимальний» недописаний |
| Перевірка | проганяєш приклад руками, називаєш крайні випадки |
| Складність | можеш сказати `O(...)` за часом і пам'яттю і чому |
| Якість | зрозумілі імена, маленькі функції, без копіпасти |
| Реакція на підказки | чуєш підказку і використовуєш її, а не сперечаєшся |

Порядок дій ти вже бачив(ла) в модулі про алгоритми: **уточнити → приклади → простий розв'язок → покращити → перевірити**. Тут — що змінюється, коли поруч людина.

## Родини задач

Більшість задач для джуна — варіації кількох ідей. Упізнав(ла) родину — половина справи.

| Родина | Ознака в умові | Інструмент |
|---|---|---|
| Підрахунки й групування | «найчастіші», «згрупуй за…» | `dict`, `Counter`, `defaultdict(list)` |
| Інтервали | «перекриваються», «вільний час», «злий» | сортування за початком + один прохід |
| Два вказівники, вікно | «підмасив», «послідовність без повторів» | два індекси, що рухаються |
| Стек | «дужки», «скасувати», «вкладеність» | `list.append` / `pop` |
| Черга, BFS | «найкоротший шлях», «по черзі» | `deque` |
| Пошук у відсортованому | «знайди позицію», «скільки менших» | `bisect` |
| Топ-K | «k найбільших», «найближчі» | `heapq.nlargest` / `nsmallest` |
| «Спроєктуй клас» | «реалізуй кеш / лічильник / чергу» | словник + структура для порядку |

## Стандартна бібліотека — твоя перевага

Інтерв'юер у Python-команді радий бачити, що ти знаєш стандартну бібліотеку, — якщо можеш пояснити, що вона робить усередині.

```python
import heapq

due_dates = [("Dune", 14), ("Kobzar", 3), ("Solaris", 9), ("Emma", 1)]
heapq.nsmallest(2, due_dates, key=lambda book: book[1])
# [("Emma", 1), ("Kobzar", 3)] — дві книжки, які повернути найшвидше
```

- `heapq.nsmallest(k, items)` — `O(n log k)`, швидше за повне сортування, коли `k` маленьке;
- `deque.popleft()` — `O(1)`, а `list.pop(0)` — `O(n)` (зсуває всі елементи);
- `bisect.bisect_left(sorted_list, x)` — позиція за `O(log n)`;
- `OrderedDict.move_to_end(key)` і `popitem(last=False)` — `O(1)`, основа LRU-кешу.

Якщо інтерв'юер просить «без бібліотек» — це не пастка: він хоче побачити структуру даних. Почни з бібліотечного рішення одним рядком, а потім напиши власне.

## «Спроєктуй клас»

Такі задачі перевіряють, чи вмієш ти вибрати структури даних під вимоги. Порядок:

1. **Інтерфейс**: назви методів, що вони повертають, які помилки кидають. Запиши як приклад використання.
2. **Вимоги до швидкості**: «`get` і `put` за `O(1)`» одразу підказують словник.
3. **Що ще треба знати**: порядок? мінімум? час? — це друга структура поруч зі словником.
4. **Код** і приклад використання як тест.

Приклад для служби підтримки — «шина подій»: модулі підписуються на події, інші їх публікують.

```python
from collections import defaultdict

class EventBus:
    def __init__(self):
        self._handlers = defaultdict(list)

    def subscribe(self, event, handler):
        self._handlers[event].append(handler)

    def publish(self, event, payload):
        for handler in self._handlers[event]:
            handler(payload)
```

Далі інтерв'юер зазвичай питає продовження: «а якщо обробник кинув виняток?», «а як відписатися?», «а якщо обробників тисячі?». Відповідай словами, перш ніж змінювати код.

## Як говорити з інтерв'юером

Співбесіди часто англійською. Кілька фраз, що рятують:

| Ситуація | Фраза |
|---|---|
| Уточнити | "Can I assume the input is sorted?", "What should happen if the list is empty?" |
| План | "I'll start with a simple solution and then improve it." |
| Складність | "This is O(n log n) because of the sort; the loop itself is linear." |
| Перевірка | "Let me walk through the example by hand." |
| Застряг(ла) | "I'm stuck on the merge step — let me think out loud." |

## Перевір себе вголос

Після коду не кажи «готово». Пройди приклад рядок за рядком і назви крайні випадки: порожній вхід, один елемент, дублікати, межі (`<` чи `<=`?), дуже великий вхід. Для інтервалів класична межа — **дотичні** інтервали `(9, 10)` і `(10, 11)`: зливати чи ні — питання до інтерв'юера, а не здогадка.

> [!TIP]
> Тренуйся з таймером і вголос, навіть сам(а). Запиши себе на відео один раз — побачиш, де мовчиш найдовше.

## Типові помилки

- Почати писати, не уточнивши умову, — і розв'язати іншу задачу.
- Мовчати, поки думаєш. Краще: «Зараз думаю, як не сортувати двічі…».
- Відразу шукати ідеальний розв'язок і не встигнути жодного.
- Змінювати вхідний список (`.sort()` замість `sorted()`), коли цього не просили.
- Не перевірити код на прикладі — і пропустити помилку, яку інтерв'юер бачить одразу.

## Підсумок

- Оцінюють процес: уточнення, комунікацію, робочий код, перевірку, складність.
- Упізнавай родину задачі: підрахунки, інтервали, вікно, стек, черга, пошук, топ-K, «клас».
- Знай `Counter`, `defaultdict`, `deque`, `heapq`, `bisect`, `OrderedDict` і їхню складність.
- «Спроєктуй клас»: інтерфейс → вимоги до швидкості → структури даних → код з прикладом.
- Після коду — прохід прикладу руками і список крайніх випадків.
