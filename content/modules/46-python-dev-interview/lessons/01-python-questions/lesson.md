# Питання з Python на співбесіді розробника

Технічна співбесіда на Junior Python Developer зазвичай має кілька частин: питання про мову, live coding (задача з кодом при інтерв'юері), питання про бекенд і бази даних, іноді тестове завдання вдома і розмова про твої проєкти. Цей модуль проходить усі частини по черзі. Загальні теми — резюме, історії за STAR, англійська, пошук роботи — у модулі «Getting Hired».

Почнемо з мови. Інтерв'юер не перевіряє, чи ти завчив(ла) визначення. Він перевіряє, чи **розумієш, що відбувається**, коли код виконується, і чи можеш пояснити це колезі.

## Як відповідати

Сильна відповідь має чотири частини і триває 30–90 секунд:

1. **Визначення одним реченням** — своїми словами.
2. **Маленький приклад** — два-три рядки коду, які можна сказати вголос.
3. **Де це важливо** — з твого проєкту або з типової задачі бекенду.
4. **Пастка** — що ламається, якщо цього не знати.

Порівняй дві відповіді на питання «чим генератор відрізняється від списку?»:

| Слабка | Сильна |
|---|---|
| «Генератор — це коли `yield`» | «Генератор видає значення по одному, коли їх просять, і не тримає всі в пам'яті. `(row for row in reader)` над CSV на 2 ГБ займає кілобайти, а список — гігабайти. Пастка: генератор проходиться **один раз** — другий `for` по ньому нічого не дасть» |

Якщо не знаєш відповіді — скажи, що знаєш поруч, і поміркуй уголос: «Точно не пам'ятаю, але якщо `dict` — хеш-таблиця, то ключ мусить мати незмінний хеш, тому…». Мовчання гірше за чесне міркування.

## Типи, імена й копії

Змінна в Python — це **ім'я, що вказує на об'єкт**, а не «коробка» зі значенням. Звідси половина питань.

| Питання | Коротка відповідь |
|---|---|
| Змінювані й незмінні типи | `list`, `dict`, `set`, більшість класів — змінювані; `int`, `float`, `str`, `tuple`, `frozenset`, `bytes` — ні |
| Чому `list` не може бути ключем `dict` | ключ має бути **хешованим**: хеш не змінюється, поки об'єкт живе; список можна змінити — його хеш «поплив би» |
| `is` чи `==` | `==` порівнює значення (`__eq__`), `is` — чи це **той самий об'єкт**; `is` — лише для `None` і сигнальних об'єктів |
| Поверхнева і глибока копія | `list(x)` / `x.copy()` копіюють лише зовнішній список — вкладені списки спільні; `copy.deepcopy` копіює все |

> [!WARNING]
> `a = 256; b = 256; a is b` у CPython дає `True`, а для більших чисел може дати `False`: інтерпретатор кешує малі цілі. Це **деталь реалізації**, а не правило мови. Правильна відповідь на співбесіді: «порівнюю числа через `==`, а `is` — лише з `None`».

## Функції

**Змінюваний аргумент за замовчуванням.** Значення за замовчуванням обчислюється **один раз** — коли виконується рядок `def`. Тому `def add(tag, tags=[])` ділить один список між усіма викликами. Виправлення: `tags=None` і `if tags is None: tags = []`.

**Області видимості (LEGB):** ім'я шукається в локальній області, потім в охопній функції, потім у модулі, потім серед вбудованих. Присвоєння всередині функції робить ім'я локальним — щоб змінити змінну охопної функції, потрібен `nonlocal`.

**Замикання** пам'ятає **змінну**, а не значення на момент створення. Класичний приклад з бібліотеки:

```python
handlers = {}
for genre in ["fantasy", "poetry"]:
    handlers[genre] = lambda: f"shelf for {genre}"

print(handlers["fantasy"]())   # shelf for poetry
```

Обидві лямбди читають ту саму змінну `genre`, а після циклу в ній `"poetry"`. Виправлення — зафіксувати значення аргументом: `lambda genre=genre: ...`.

**`*args` і `**kwargs`** збирають зайві позиційні аргументи в кортеж і іменовані — у словник. У виклику `f(*items, **options)` вони, навпаки, розпаковують.

## Ітерація, генератори, декоратори

- **Ітерований** об'єкт уміє дати ітератор (`iter(x)`), **ітератор** видає наступне значення (`next(it)`) і кидає `StopIteration` у кінці. `for` робить саме це.
- **Генератор** — функція з `yield` або вираз `(... for ...)`: лінивий ітератор. Він проходиться один раз.
- **Декоратор** — функція, що приймає функцію і повертає нову. `@functools.wraps` зберігає ім'я й docstring оригіналу (без нього логи й трасування показують `wrapper`).
- **Контекстний менеджер** — об'єкт з `__enter__` / `__exit__` (або `@contextmanager`): гарантує прибирання — закриття файлу, `commit` / `rollback` — навіть після винятку.

Детально все це було в модулі «Python in Depth» — на співбесіді посилайся на свої розв'язки звідти.

## Класи

| Питання | Відповідь |
|---|---|
| Що таке dunder-методи | спеціальні методи (`__len__`, `__eq__`, `__iter__`, `__repr__`…), через які клас працює з `len()`, `==`, `for`, `print` |
| `__eq__` без `__hash__` | Python ставить `__hash__ = None` — об'єкти стають нехешованими і не можуть бути в `set` чи ключами `dict` |
| `@classmethod` і `@staticmethod` | `classmethod` отримує клас (`cls`) — для альтернативних конструкторів `from_dict`; `staticmethod` нічого не отримує — просто функція в просторі імен класу |
| Навіщо `@dataclass` | генерує `__init__`, `__repr__`, `__eq__`; `frozen=True` — незмінний і хешований, `slots=True` — менше пам'яті |
| Атрибут класу vs атрибут екземпляра | атрибут класу спільний для всіх екземплярів — змінюваний атрибут класу (список) ділять усі об'єкти |

## Як CPython виконує код

- Код компілюється в **байткод**, який виконує інтерпретатор.
- **Пам'ять**: кожен об'єкт має лічильник посилань; коли він падає до нуля, об'єкт звільняється одразу. Цикли посилань (об'єкт посилається сам на себе через інший) прибирає окремий **збирач сміття** (модуль `gc`).
- **GIL** (Global Interpreter Lock) у звичайній збірці CPython дозволяє лише одному потоку виконувати байткод Python у кожен момент. Потоки однаково корисні для **очікування** (мережа, диск): під час очікування GIL відпускається. Для **обчислень** на кількох ядрах беруть процеси (`ProcessPoolExecutor`) — це було в модулі про async.
- **Free-threaded збірка** (без GIL) з'явилася як експериментальна в 3.13, а з 3.14 офіційно підтримується (PEP 779). Але це окрема збірка інтерпретатора, звичайна збірка досі має GIL.

> [!TIP]
> Питання «Що нового в Python?» перевіряє, чи ти стежиш за мовою. Достатньо 2–3 пунктів: **3.12** — новий синтаксис узагальнень `def first[T](items: list[T]) -> T`; **3.13** — новий інтерактивний інтерпретатор, експериментальні free-threading і JIT; **3.14** — t-рядки (`t"..."`), відкладене обчислення анотацій, офіційна підтримка free-threaded збірки; **3.15** (жовтень 2026) — ліниві імпорти `lazy import json`, UTF-8 за замовчуванням, вбудований `frozendict`. І обов'язково: «у проєкті ми на 3.13, бо…».

## «Що надрукує цей код?»

Такі питання перевіряють модель виконання. Розв'язуй їх **кроками вголос**, як таблицю змінних:

```python
prices = {"book": 300}
backup = prices
prices["book"] = 250
print(backup["book"])   # 250: backup — те саме ім'я для того самого словника
```

Найчастіші теми: посилання замість копій, змінюваний аргумент за замовчуванням, пізнє зв'язування в замиканнях, вичерпаний генератор, `//` з від'ємними числами (округлення **вниз**: `-7 // 2 == -4`), `round` з «банківським» округленням (`round(0.5) == 0`), `0.1 + 0.2 != 0.3`, `and` / `or`, що повертають **один з операндів**, а не `True` / `False`.

## Типові помилки на співбесіді

- Визначення без прикладу — звучить завчено.
- «Python передає аргументи за посиланням» — точніше: функція отримує **посилання на той самий об'єкт**; змінювати його можна, а присвоєння новому імені всередині функції зовні не видно.
- Плутати `is` і `==`, генератор і список, `copy` і `deepcopy`.
- Казати «GIL робить потоки марними» — для мережевих викликів вони працюють.
- Ховати незнання. Краще: «не впевнений(а), але міркую так…».

## Підсумок

- Відповідь = визначення → приклад → де важливо → пастка.
- Змінна — ім'я для об'єкта: звідси копії, `is` / `==`, спільні списки.
- Значення за замовчуванням обчислюється один раз; замикання пам'ятає змінну, а не значення.
- `__eq__` без `__hash__` робить об'єкти нехешованими; `@dataclass(frozen=True)` — хешований.
- CPython: лічильник посилань + збирач циклів; GIL заважає лише обчисленням у потоках.
- Знай 2–3 новинки останніх версій і на якій версії твій проєкт.
