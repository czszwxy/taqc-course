# Контейнери та образи

Ти вже вмієш написати API на FastAPI чи Django і запустити його на своєму комп'ютері. Наступне питання — **як запустити той самий код деінде**: у колеги, у CI, на сервері. Там інша версія Python, немає потрібних бібліотек, інша операційна система. Docker розв'язує це просто: застосунок пакують разом з усім оточенням в **образ**, і цей образ запускається однаково будь-де, де є Docker.

> [!NOTE]
> Docker для задач модуля не потрібен: код задач перевіряється тут, у браузері чи в середовищі курсу. Команди з уроків можна спробувати в **Docker Desktop** — для Windows він працює через WSL 2 (посилання в ресурсах). Це необов'язково, але дуже корисно.

## Образ і контейнер

| Поняття | Що це | Приклад |
|---|---|---|
| **Image** (образ) | незмінний шаблон: файлова система з Python, бібліотеками й кодом + команда запуску | `helpdesk-api:1.0` |
| **Container** (контейнер) | запущений екземпляр образу: окремий процес з власною файловою системою й мережею | `helpdesk-api-1` |
| **Registry** (реєстр) | сховище образів, з якого їх завантажують | Docker Hub, GitHub Container Registry (`ghcr.io`) |
| **Tag** (тег) | назва версії образу після `:` | `python:3.13-slim` |
| **Volume** (том) | сховище даних поза контейнером | дані бази PostgreSQL |

Аналогія для розробника: образ — як **клас**, контейнер — як **об'єкт**. З одного образу можна запустити скільки завгодно контейнерів, і кожен матиме своє робоче місце.

Образ складається з **шарів** (layers): базовий шар з Debian і Python, потім шар з бібліотеками, потім шар з кодом. Шари спільні: якщо десять образів побудовано на `python:3.13-slim`, базовий шар завантажується один раз. Це знадобиться в наступному уроці, коли говоритимемо про швидке збирання.

> [!IMPORTANT]
> Контейнер **одноразовий**. Усе, що застосунок записав у файлову систему контейнера, зникає разом із ним після `docker rm`. Дані, які треба зберегти (база, завантажені файли), живуть у **томах** — про це в уроці про Compose.

## Перший запуск

```bash
docker run --rm -it python:3.13-slim python
```

Що відбулося:

1. Docker не знайшов образ локально і завантажив (`pull`) його з Docker Hub.
2. Створив контейнер і запустив у ньому команду `python` — відкрилась консоль Python.
3. `-it` — інтерактивний режим з терміналом, `--rm` — видалити контейнер, щойно вийдеш (`exit()`).

Тег важливий: `python:3.13-slim` — Python 3.13 на мінімальному Debian. Якщо тег не вказати, Docker візьме `latest` — це просто назва тегу, яку автор образу може будь-коли перенести на іншу версію. Для роботи завжди пиши конкретний тег.

## Застосунок у контейнері: прапорці `docker run`

Уяви, що служба підтримки вже має образ свого API `helpdesk-api:1.0`:

```bash
docker run -d --name helpdesk -p 8080:8000 -e LOG_LEVEL=INFO helpdesk-api:1.0
```

| Прапорець | Що робить |
|---|---|
| `-d` | запуск у фоні (detached), термінал вільний |
| `--name helpdesk` | ім'я контейнера, щоб звертатися до нього в інших командах |
| `-p 8080:8000` | **порт 8080 твого комп'ютера** → порт 8000 у контейнері |
| `-e LOG_LEVEL=INFO` | змінна середовища для застосунку |
| `--env-file .env` | багато змінних з файлу |
| `--rm` | видалити контейнер після зупинки |
| `-v pgdata:/var/lib/postgresql` | підключити том `pgdata` у папку контейнера |

### Порти: спершу комп'ютер, потім контейнер

Контейнер має власну мережу. API всередині слухає порт `8000` **контейнера**, і ззовні його не видно, доки порт не **опубліковано** через `-p`. Запис `-p 8080:8000` читай так: «відкрий `8080` на моєму комп'ютері й пересилай у `8000` контейнера». У браузері відкриваєш `http://localhost:8080`.

| Запис | Що означає |
|---|---|
| `-p 8000:8000` | однакові номери — найчастіший випадок |
| `-p 8080:8000` | у браузері `8080`, застосунок слухає `8000` |
| `-p 127.0.0.1:8080:8000` | доступно лише з цього комп'ютера (без IP — з усіх мережевих інтерфейсів) |
| `-p 8000` | Docker сам обере вільний порт на комп'ютері; подивитись — `docker ps` |
| `-p 5353:53/udp` | протокол UDP (за замовчуванням TCP) |

> [!WARNING]
> Усередині контейнера застосунок має слухати **`0.0.0.0`**, а не `127.0.0.1`. `127.0.0.1` у контейнері — це сам контейнер, і запити через опублікований порт до застосунку не дійдуть: браузер покаже «connection reset». Тому `fastapi dev` (слухає `127.0.0.1`) — лише для розробки, а в контейнері запускають `fastapi run` (слухає `0.0.0.0`) або `uvicorn --host 0.0.0.0`.

Також `EXPOSE 8000` у Dockerfile (наступний урок) **не** публікує порт — це лише документація для людей та інструментів. Публікує тільки `-p`.

## Щоденні команди

| Команда | Навіщо |
|---|---|
| `docker ps` / `docker ps -a` | запущені / всі контейнери (і зупинені) |
| `docker logs -f helpdesk` | вивід застосунку; `-f` — стежити наживо |
| `docker exec -it helpdesk sh` | відкрити shell усередині запущеного контейнера |
| `docker stop helpdesk` | зупинити (застосунок отримає сигнал SIGTERM) |
| `docker rm helpdesk` | видалити зупинений контейнер |
| `docker images` | образи на комп'ютері |
| `docker pull postgres:18` | завантажити образ наперед |
| `docker system prune` | прибрати зупинені контейнери й непотрібні образи |

## Типові помилки

- Переплутати порядок у `-p`: `-p 8000:8080` при застосунку на `8000` — у браузері нічого.
- Застосунок у контейнері слухає `127.0.0.1` — порт опубліковано, а відповіді немає.
- Писати дані в контейнер без тому — після перестворення вони зникають.
- `latest` у робочих командах — сьогодні одна версія, завтра інша.
- Шукати помилку «вгадуючи», замість `docker logs` — вивід застосунку майже завжди пояснює, що не так.

> [!TIP]
> Контейнер, що одразу зупиняється, — це майже завжди застосунок, який упав на старті (немає змінної, помилка імпорту). `docker ps -a` покаже код виходу, `docker logs <ім'я>` — traceback.

## Підсумок

- Образ — незмінний шаблон з Python, бібліотеками й кодом; контейнер — запущений екземпляр; реєстр зберігає образи, тег — версія.
- Контейнер одноразовий: дані, що мають жити довше, — у томах.
- `-p HOST:CONTAINER`: лівий номер відкриваєш у браузері, правий слухає застосунок; `EXPOSE` нічого не публікує.
- У контейнері застосунок слухає `0.0.0.0` (`fastapi run`), а не `127.0.0.1`.
- `ps`, `logs`, `exec`, `stop`, `rm` — щоденний набір; конкретний тег замість `latest`.
