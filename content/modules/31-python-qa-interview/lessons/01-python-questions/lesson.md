# Питання з Python на співбесіді

На позицію Python QA Automation мову перевіряють завжди. Junior не мусить знати внутрішню будову інтерпретатора, але мусить упевнено пояснити, **чому код поводиться саме так**: чому тест бачить чужі дані, чому `"false"` раптом істина, звідки береться `yield` у фікстурі.

> [!QA]
> Найкраща відповідь на питання з Python — **визначення + маленький приклад + де це в тестах**. «Декоратор — функція, що обгортає іншу функцію й додає поведінку. Я щодня користуюсь ними: `@pytest.fixture`, `@pytest.mark.parametrize`».

## Що найчастіше питають

| Тема | Типове питання | Що перевіряють |
|---|---|---|
| Типи | «Чим список відрізняється від кортежу?» | змінюваність, хешованість |
| Посилання | «Що буде з `a`, якщо змінити `b = a`?» | розуміння об'єктів і копій |
| Порівняння | «Чим `is` відрізняється від `==`?» | ідентичність проти рівності |
| Функції | «Що не так з `def f(items=[])`?» | змінюваний default |
| Аргументи | «Що таке `*args` і `**kwargs`?» | гнучкі сигнатури, білдери |
| Декоратори | «Напиши простий декоратор» | функції як значення, замикання |
| `with` | «Що таке контекстний менеджер?» | гарантоване прибирання |
| Генератори | «Чим `yield` відрізняється від `return`?» | лінивість, фікстури |
| Винятки | «Навіщо `finally`? Що таке `raise ... from`?» | обробка помилок |

## Посилання і копії: коротке нагадування

```python
row = [0] * 3
grid = [row] * 3        # три посилання на ОДИН список
grid[0][0] = 1
print(grid)             # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]

grid = [[0] * 3 for _ in range(3)]   # три різні списки
```

`b = a` не копіює; `a.copy()` чи `list(a)` — **поверхнева** копія (вкладені списки спільні); `copy.deepcopy(a)` — повна.

## `is` і `==`

`==` питає «чи рівні значення», `is` — «чи це **той самий** об'єкт». `[1, 2] == [1, 2]` — `True`, а `[1, 2] is [1, 2]` — `False`. `is` використовують лише з `None`: `if result is None:`.

## Декоратори

Декоратор — функція, яка приймає функцію і повертає нову, «обгорнуту». Запис `@log_calls` над `def` — це скорочення для `fn = log_calls(fn)`.

```python
import functools


def log_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}{args}")
        return func(*args, **kwargs)
    return wrapper


@log_calls
def add_to_cart(product_id, quantity):
    return {"productId": product_id, "quantity": quantity}


add_to_cart(3, 2)   # друкує: calling add_to_cart(3, 2)
```

| Частина | Роль |
|---|---|
| `log_calls(func)` | отримує оригінальну функцію |
| `wrapper(*args, **kwargs)` | нова функція: приймає будь-які аргументи й передає їх далі |
| `return func(...)` | не забути повернути результат оригіналу |
| `@functools.wraps(func)` | копіює `__name__` і docstring — інакше у звітах і помилках усі функції звуться `wrapper` |

У тестах декоратори всюди: `@pytest.fixture`, `@pytest.mark.parametrize`, `@allure.step`, `@mock.patch`.

## Контекстні менеджери

`with` гарантує, що «вихідна» частина виконається навіть після винятку: файл закриється, зміна відкотиться.

```python
import time
from contextlib import contextmanager


@contextmanager
def stopwatch(label):
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{label}: {time.perf_counter() - start:.2f}s")


with stopwatch("checkout flow"):
    run_checkout()
```

Код до `yield` — вхід, після — вихід, а `finally` спрацьовує навіть якщо всередині `with` щось упало. У тестах: `with open(...)`, `with pytest.raises(...)`, `with page.expect_popup() as popup_info:`, `with allure.step(...)`.

## Генератори

Функція з `yield` повертає генератор: значення видаються по одному, коли їх просять, а виконання «ставиться на паузу» між ними. Тому фікстура з `yield` — це генератор: pytest бере значення для тесту, чекає, поки тест завершиться, і продовжує функцію — виконує прибирання.

## Задачі «що надрукує цей код?»

```python
def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item("a"))
print(add_item("b"))
```

| Виклик | `items` | Друкує |
|---|---|---|
| `add_item("a")` | той самий список-default `[]` → `["a"]` | `['a']` |
| `add_item("b")` | **той самий** список → `["a", "b"]` | `['a', 'b']` |

Як розв'язувати: не вгадувати, а **трасувати** — таблиця змінних рядок за рядком, уголос.

## Типові помилки на співбесіді

- Визначення без прикладу: «декоратор — це патерн проєктування» — і тиша.
- `is` для порівняння рядків чи чисел — працює «через раз» і видає незнання.
- Декоратор, що не повертає результат `func(...)` — обгорнута функція повертає `None`.
- Вгадування відповіді на «що надрукує» замість покрокового трасування.

## Підсумок

- Відповідь = визначення + приклад + де це в тестах.
- Знай пастки: змінюваний default, `[row] * 3`, `is` проти `==`, поверхнева копія.
- Декоратор: функція → обгорнута функція; `*args, **kwargs`, `return func(...)`, `functools.wraps`.
- Контекстний менеджер: `with`, вихід гарантований; свій — через `@contextmanager` з `yield` у `try/finally`.
- Генератор: `yield` ставить функцію на паузу — так працюють фікстури з прибиранням.
