# Перший API на FastAPI

У модулі про HTTP ти **викликав(ла)** чужі API: надсилав(ла) запит — отримував(ла) JSON. Тепер ти по інший бік: пишеш сервер, який ці запити приймає. Python-розробник бекенду робить це щодня — мобільний застосунок, фронтенд чи інший сервіс питають «дай товари», «створи замовлення», а твій код відповідає.

**FastAPI** — один із найпопулярніших Python-фреймворків для API. Його сильні сторони: менше коду, перевірка даних на основі type hints, які ти вже знаєш, і автоматична документація.

## Що робить веб-фреймворк

HTTP-запит — це текст: метод, шлях, заголовки, тіло. Без фреймворку тобі довелось би розбирати його вручну. Фреймворк бере це на себе:

```text
GET /events/3 HTTP/1.1          ──►  Uvicorn (сервер)  ──►  FastAPI (маршрутизація)
                                                              │
                                                              ▼
HTTP/1.1 200 OK                 ◄──  JSON  ◄──  твоя функція get_event(3)
{"id": 3, "title": "PyCon"}
```

| Хто | Що робить |
|---|---|
| **Uvicorn** (ASGI-сервер) | слухає порт, приймає байти з мережі й віддає відповідь |
| **FastAPI** (фреймворк) | за методом і шляхом знаходить твою функцію, перетворює параметри, повертає JSON |
| **Твоя функція** (ендпоінт) | бізнес-логіка: знайти, порахувати, зберегти |

## Перший застосунок

Приклад — маленький API розкладу подій:

```python
from fastapi import FastAPI

app = FastAPI(title="Events")

EVENTS = [
    {"id": 1, "title": "Python meetup", "city": "Lviv"},
    {"id": 2, "title": "Testing day", "city": "Kyiv"},
]

@app.get("/")
def root():
    return {"message": "Events API"}

@app.get("/events")
def list_events():
    return EVENTS

@app.get("/events/count")
def count_events():
    return {"count": len(EVENTS)}
```

- `app = FastAPI()` — об'єкт застосунку. Сервер шукає саме його (за замовчуванням змінна `app`).
- `@app.get("/events")` — **декоратор маршруту** (ти вже знаєш декоратори з модуля «Python in Depth»): «на `GET /events` виклич цю функцію». Є також `@app.post`, `@app.put`, `@app.patch`, `@app.delete`.
- Функція повертає звичайні `dict` / `list` — FastAPI сам перетворить їх на JSON і поставить `Content-Type: application/json` та статус `200`.

> [!NOTE]
> Ендпоінти можна писати і як `def`, і як `async def`. Поки що пиши звичайні `def`: FastAPI запустить їх в окремому потоці й не заблокує сервер. Коли й навіщо потрібен `async def`, розберемо в модулі «Async Python».

## Запусти свій API

Сервери FastAPI працюють на твоєму комп'ютері, тож задачі цього модуля перевіряються не в браузері, а справжнім Python у середовищі курсу `lab/.venv`.

**Один раз** відкрий термінал у папці проєкту й виконай (Python 3.9+ має бути встановлений з python.org з галочкою «Add python.exe to PATH»):

```bash
npm run lab:python-setup
```

Якщо ти вже **налаштовував(ла)** лабораторію Python у курсі QA — команда просто доставить FastAPI. Тепер запусти навчальний API з файлу `lab/python/api/main.py`:

```bash
npm run lab:py-api
```

Відкрий у браузері `http://127.0.0.1:8000/docs`. Це **Swagger UI** — документація, яку FastAPI згенерував сам з твого коду: список ендпоінтів, параметри, кнопка **Try it out**, що надсилає справжній запит. Сирий опис у форматі OpenAPI лежить на `/openapi.json`. Змінюй `main.py` і зберігай — `fastapi dev` перезапускає застосунок автоматично. Зупинити сервер — `Ctrl+C` у терміналі.

> [!TIP]
> Swagger UI — найкращий спосіб «помацати» API. Фронтенд-розробник чи тестувальник твоєї команди відкриє `/docs` і побачить контракт ще до того, як ти щось поясниш.

## Виклик API з коду: TestClient

Відкривати браузер для кожної перевірки довго. `TestClient` надсилає запити прямо у твій застосунок — без сервера, без мережі:

```python
from fastapi.testclient import TestClient

client = TestClient(app)

response = client.get("/events/count")
print(response.status_code)   # 200
print(response.json())        # {'count': 2}
print(client.get("/nope").status_code)   # 404 — такого маршруту немає
```

`response` — той самий об'єкт, що й у бібліотеці `httpx` (схожий на `requests`): `status_code`, `json()`, `headers`, `text`.

Саме так курс перевіряє твої задачі: прихований `tests.py` імпортує `app` з твого `solution.py` і робить запити через `TestClient`. Кнопка **Run** виконує твій файл — додай унизу `print(TestClient(app).get("/events").json())`, щоб побачити відповідь.

## Типові помилки

| Помилка | Що побачиш | Як виправити |
|---|---|---|
| Забули `@app.get(...)` над функцією | `404 Not Found` | маршрут з'являється лише з декоратором |
| Шлях без `/` на початку: `@app.get("events")` | маршрут не знаходиться | завжди `"/events"` |
| Дві функції з однаковим шляхом і методом | працює лише перша | один метод + шлях = один ендпоінт |
| Повертаєш `set` або об'єкт власного класу | помилка серіалізації | повертай `dict`, `list`, `str`, числа (або моделі Pydantic — наступні уроки) |
| `uvicorn.run(...)` у файлі задачі | Run висить і зупиняється за таймаутом | для задач сервер не потрібен; для практики — `npm run lab:py-api` |

> [!QA]
> Тестувальник API бачить ту саму картину з іншого боку: метод + шлях + статус + тіло. Коли пишеш ендпоінт, одразу думай, як його перевірять: що буде з неіснуючим шляхом, порожнім списком, неправильним методом (`POST` на `GET`-маршрут дає `405 Method Not Allowed`).

## Підсумок

- Uvicorn приймає HTTP, FastAPI знаходить функцію за методом і шляхом, функція повертає дані — FastAPI робить з них JSON.
- `app = FastAPI()` + декоратори `@app.get / post / put / patch / delete`.
- `dict` і `list` автоматично стають JSON зі статусом `200`.
- `/docs` — Swagger UI, `/openapi.json` — опис API; свій API запускай `npm run lab:py-api`.
- `TestClient(app)` викликає API з коду — так перевіряються задачі модуля.
