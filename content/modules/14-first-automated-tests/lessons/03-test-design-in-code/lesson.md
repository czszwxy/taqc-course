# Техніки тест-дизайну в коді

У модулі 03 ти навчилася **вибирати** тестові значення: класи еквівалентності, граничні значення, правила таблиці рішень. Тепер ці значення стають тестами. Найчастіша помилка новачків в автоматизації — писати тести «навмання» (кілька довільних значень) і пропускати саме ті випадки, де живуть баги: межі й комбінації.

## EP → один тест на клас

Функція `passwordStrength`: коротший за 8 → `weak`; від 8 з цифрою **і** великою літерою → `strong`; від 8 без чогось із цього → `medium`.

| Клас | Приклад | Очікування |
|---|---|---|
| коротший за 8 | `'Ab1'` | `weak` |
| ≥ 8, цифра + велика | `'Secret123'` | `strong` |
| ≥ 8, лише цифра | `'secret123'` | `medium` |
| ≥ 8, лише велика | `'SecretPass'` | `medium` |
| ≥ 8, нічого | `'password'` | `medium` |

```ts
it('weak when shorter than 8', () => expect(passwordStrength('Ab1')).toBe('weak'));
it('medium without an uppercase letter', () => expect(passwordStrength('secret123')).toBe('medium'));
```

> [!TIP]
> Класи з умовою «**і**» (цифра і велика літера) завжди потребують окремих тестів для «є лише одне з двох». Саме там часто плутають `&&` з `||`.

## BVA → тести на межах

Вік 18–65 включно → значення **17, 18, 65, 66** (two-value BVA), плюс нецілі числа як окремий клас.

Зручно описати приклади **таблицею** і пройти її циклом — кожен рядок стане окремим тестом:

```ts
const cases: [number, boolean][] = [
  [17, false],
  [18, true],
  [65, true],
  [66, false],
];

for (const [age, expected] of cases) {
  it(`age ${age} → ${expected}`, () => {
    expect(canRegister(age)).toBe(expected);
  });
}
```

У справжніх фреймворках для цього є `test.each` / `it.each`; цикл робить те саме.

## Таблиця рішень → тест на правило

Доставка безкоштовна, якщо сума ≥ 3,000 **або** клієнт Plus **або** промокод FREESHIP. Кожен рядок таблиці рішень — окремий тест; особливо важливі **комбінації**, у яких розробник міг забути одну з умов (наприклад, Plus + інший промокод).

```ts
const rules: [number, boolean, string, number][] = [
  // subtotal, member, promo, expected fee
  [2999, false, '', 100],
  [3000, false, '', 0],
  [2999, true, '', 0],
  [2999, true, 'SAVE10', 0],
  [2999, false, 'freeship', 0],
];
```

> [!QA]
> Порівняй: це ті самі баги, які ти шукала руками на сторінці кошика в модулі 06 (межа 3,000, Plus + SAVE10, регістр промокоду). Різниця лише в тому, що тепер перевірка займає мілісекунди і запускається при кожній зміні коду.

## Скільки тестів достатньо?

Стільки, щоб **кожен** клас, межа й правило таблиці мали хоча б один тест. Зайві тести з середини того самого класу (`age 30`, `age 31`, `age 32`) нічого не додають. У завданнях уроку це видно наочно: мутанти «виживають» саме там, де бракує межі чи комбінації.

## Підсумок

- EP: по одному тесту на кожен клас еквівалентності (включно з невалідними).
- BVA: значення на межах і одразу за ними; нецілі та інші «дивні» значення — окремі класи.
- Таблиця рішень: тест на кожне правило, особливо на комбінації умов.
- Таблиця прикладів + цикл = компактні параметризовані тести.
