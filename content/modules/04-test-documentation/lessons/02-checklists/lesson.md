# Чеклісти

**Чекліст** (checklist) — список того, що треба перевірити, **без детальних кроків**. Кожен пункт — одна перевірка, яку досвідчений тестувальник знає, як виконати. Чеклісти — найпоширеніша тестова документація в Agile-командах: їх швидко писати й легко підтримувати.

## Приклад: чекліст сторінки логіну

**Позитивні:**

- [ ] Вхід з правильним email і паролем → сторінка профілю
- [ ] Email з великими літерами (`Olena@Example.com`) → вхід успішний
- [ ] Вхід натисканням Enter, а не лише кнопкою

**Негативні:**

- [ ] Неправильний пароль → повідомлення без підказки, що саме неправильне
- [ ] Незареєстрований email → те саме нейтральне повідомлення
- [ ] Порожні поля → повідомлення під полями
- [ ] 5 невдалих спроб → тимчасове блокування

**UI і безпека:**

- [ ] Пароль приховано зірочками, є кнопка «показати»
- [ ] Пароль не видно в URL і в Network-запиті як GET-параметр
- [ ] Посилання «Forgot password?» веде на відновлення

## Чекліст vs тест-кейс

| | Чекліст | Тест-кейс |
|---|---|---|
| Деталізація | що перевірити (одна строка) | як саме: передумови, кроки, дані, очікуваний результат |
| Час на написання | хвилини | значно більше |
| Хто може виконати | людина, яка знає продукт | будь-хто, навіть новачок |
| Повторюваність | різні люди можуть перевірити трохи по-різному | однакове виконання щоразу |
| Коли краще | швидка розробка, досвідчена команда, часті зміни | критичні сценарії, регресія, вимоги регулятора, база для автотестів |

> [!QA]
> На практиці їх поєднують: чекліст для широкого покриття фічі + детальні тест-кейси для критичних сценаріїв (оплата, реєстрація) і тих, що підуть в автоматизацію.

## Як писати хороший чекліст

- **Один пункт — одна перевірка.** «Перевірити логін і реєстрацію» — це два пункти.
- **Конкретно.** Не «перевірити пароль», а «пароль з 7 символів відхиляється».
- **Групуй** за областями: позитивні, негативні, UI, безпека, зручність.
- **Використовуй техніки**: EP і BVA дають пункти для полів, таблиці рішень — для правил.
- **Додавай досвід**: типові помилки (error guessing) — теж пункти.
- **Без очевидного шуму**: «сторінка відкривається» потрібно лише якщо це справді ризик.

## Універсальні чеклісти

Корисно мати набір перевикористовуваних чеклістів: для будь-якого текстового поля, для будь-якої форми, для будь-якої сторінки зі списком (сортування, фільтри, пагінація, порожній список), для мобільної версії. Вони накопичують досвід команди.

> [!TIP]
> Під час виконання позначай кожен пункт статусом: ✅ passed, ❌ failed (з посиланням на баг), ⏸ blocked, ➖ не застосовно. Так чекліст стає ще й звітом.

## Підсумок

- Чекліст — список перевірок без детальних кроків: швидко й гнучко.
- Тест-кейс детальніший і повторюваніший: для критичного й автоматизації.
- Хороший пункт: одна конкретна перевірка; групуй за областями.
- Наповнюй чекліст техніками тест-дизайну й досвідом.
