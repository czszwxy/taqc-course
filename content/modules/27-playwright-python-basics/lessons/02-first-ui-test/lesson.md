# Перший UI-тест з фікстурою page

Ти вже знаєш, що тест отримує фікстуру через параметр. pytest-playwright додає готові фікстури, які запускають браузер і дають тесту вкладку. Найважливіша — `page`.

## Фікстури плагіна

| Фікстура | Scope | Що дає |
|---|---|---|
| `playwright` | session | запущений Playwright: `playwright.chromium`, `playwright.devices`, `playwright.request` |
| `browser` | session | **один** запущений браузер на всі тести |
| `context` | function | новий «чистий профіль» для кожного тесту: свої cookies, localStorage, кеш |
| `page` | function | вкладка в цьому контексті — з нею працюють майже всі UI-тести |
| `base_url` | session | значення `--base-url` |
| `browser_context_args` | session | налаштування нових контекстів: розмір вікна, локаль, user agent… |

Запускати браузер дорого (секунда-дві), тому `browser` один на сесію. Контекст створюється за мілісекунди, тому кожен тест отримує **свій**. Що один тест записав у cookies чи localStorage, інший не побачить — тести не залежать один від одного і їх можна запускати в будь-якому порядку.

> [!NOTE]
> Контекст схожий на вікно «інкогніто»: окремий профіль у тому самому браузері. Закрив його — разом зникли cookies, сесія і збережені дані.

## Анатомія тесту

Приклад для сторінки замовлення Gadgetly (`/playground/order`):

```python
from playwright.sync_api import Page, expect


def test_new_order_has_status_created(page: Page):
    page.goto("/playground/order")

    expect(page.get_by_test_id("order-status")).to_have_text("Created")


def test_pay_moves_order_to_paid(page: Page):
    page.goto("/playground/order")

    page.get_by_role("button", name="Pay").click()

    expect(page.get_by_test_id("order-status")).to_have_text("Paid")
```

Кожен тест має три частини — як тест-кейс:

| Частина | Рядок | Як у тест-кейсі |
|---|---|---|
| Arrange (підготовка) | `page.goto("/playground/order")` | передумова: сторінка відкрита |
| Act (дія) | `...get_by_role("button", name="Pay").click()` | крок |
| Assert (перевірка) | `expect(...).to_have_text("Paid")` | очікуваний результат |

## Розбір: що відбувається під час `pytest`

| Крок | Що робить pytest / Playwright |
|---|---|
| 1 | pytest бачить, що `test_pay_moves_order_to_paid` просить `page` |
| 2 | ланцюжок фікстур: `page` ← `context` ← `browser` ← `playwright` |
| 3 | `playwright` і `browser` уже готові з попереднього тесту (session) — браузер не перезапускається |
| 4 | `context` — новий чистий контекст, `page` — нова вкладка в ньому |
| 5 | `page.goto(...)` відкриває адресу (`--base-url` + шлях) і чекає, поки сторінка завантажиться |
| 6 | `get_by_role(...)` лише **описує** кнопку; `.click()` знаходить її, чекає, поки її можна натиснути, і натискає |
| 7 | `expect(...).to_have_text("Paid")` перевіряє текст і **повторює** перевірку, доки текст не стане `Paid` (до 5 с) |
| 8 | після тесту плагін закриває контекст разом з усіма його даними |

## Локатор — це опис, а не елемент

```python
pay = page.get_by_role("button", name="Pay")
status = page.get_by_test_id("order-status")

pay.click()
expect(status).to_have_text("Paid")
```

Виклик `get_by_role(...)` нічого не шукає. Пошук відбувається в момент дії чи перевірки — і щоразу заново. Тому локатори можна зберегти у змінні на початку тесту, навіть якщо елемент з'явиться пізніше.

## Назви тестів

pytest показує назву функції у звіті, тож вона має пояснювати, **що** перевіряється і **що** очікується: `test_pay_moves_order_to_paid`, а не `test_1` чи `test_order`. Коли тест впаде, назва вже наполовину опише баг.

Підказка типу `page: Page` необов'язкова, але з нею VS Code підказує методи (`goto`, `get_by_role`…) і показує документацію.

## Типові помилки

| Помилка | Що станеться |
|---|---|
| немає жодного `expect` | тест «проходить» навіть на зламаній сторінці — він нічого не перевіряє |
| `page.get_by_role("button", name="Pay").click` без `()` | нічого не натиснеться, і Python не покаже помилки: це просто посилання на метод |
| `await page.goto(...)` | `SyntaxError: 'await' outside async function` |
| `def test_x():` без параметра `page`, а в тілі `page.goto(...)` | `NameError: name 'page' is not defined` |
| `get_by_label("Password")` на формі з чекбоксом «Show password» | знайдуться два елементи, дія впаде зі `strict mode violation` (урок про локатори) |

> [!IMPORTANT]
> Перед тим як здати тест, переконайся, що він **може впасти**: тимчасово зміни очікуваний текст (`"Paidd"`) і запусти. Червоний — отже перевірка справжня. Зелений — тест нічого не перевіряє.

## Підсумок

- `page` — нова вкладка в новому контексті для кожного тесту; браузер один на сесію.
- Тест = `page.goto` → дії → `expect`; як тест-кейс: передумова, кроки, очікуваний результат.
- Локатор — опис елемента; пошук відбувається під час дії чи перевірки.
- `expect` чекає й повторює перевірку; тест без перевірки нічого не тестує.
- Назва тесту пояснює, що перевіряється.
