# Дії

Знайти елемент — пів справи. Далі тест має зробити з ним те, що зробив би користувач: ввести текст, натиснути Enter, поставити галочку, вибрати країну зі списку. У Playwright для цього є методи локатора — **дії**.

## Основні дії

| Дія | Що робить | Приклад |
|---|---|---|
| `click()` | натискає елемент | `page.get_by_role("button", name="Create account").click()` |
| `dblclick()` | подвійне натискання | `row.dblclick()` |
| `fill(text)` | замінює значення поля одразу | `page.get_by_label("Full name").fill("Olena Kovalenko")` |
| `clear()` | очищає поле | `page.get_by_label("Email").clear()` |
| `press(key)` | натискає клавішу (чи комбінацію) | `page.get_by_label("Password", exact=True).press("Enter")` |
| `press_sequentially(text)` | друкує по одній літері | `field.press_sequentially("kyiv", delay=100)` |
| `check()` / `uncheck()` | ставить / знімає галочку | `page.get_by_label("Remember me").check()` |
| `select_option(...)` | вибирає варіант у `<select>` | `page.get_by_label("Country").select_option("Poland")` |
| `hover()` | наводить мишку | `page.get_by_role("link", name="Help").hover()` |
| `set_input_files(path)` | вибирає файл для завантаження | `page.get_by_label("Avatar").set_input_files("data/avatar.png")` |

Кожна дія спершу **чекає**, поки елемент можна використати: він є на сторінці, видимий, не рухається, не вимкнений (`disabled`). Це автоочікування — докладно в уроці 6. Тому між діями не потрібні паузи.

## fill чи press_sequentially

Розбір того, що робить `fill("Olena")`:

| Крок | Що відбувається |
|---|---|
| 1 | чекає, поки поле з'явиться і стане доступним для введення |
| 2 | фокусує поле |
| 3 | виділяє старий текст і замінює його на `Olena` одним рухом |
| 4 | генерує подію `input` — застосунок «бачить» нове значення |

`press_sequentially` натискає кожну клавішу окремо (`keydown` → `keypress` → `keyup` для кожної літери). Це повільніше, і потрібно рідко: для полів, що реагують на кожне натискання (підказки під час набору, маски номера телефону). У звичайних формах — `fill`.

## Клавіші

```python
field.press("Enter")         # відправити форму або додати рядок
field.press("Escape")        # скасувати редагування, закрити вікно
field.press("Tab")           # перейти до наступного поля
field.press("Control+A")     # комбінація клавіш
page.keyboard.press("Shift+Tab")   # клавіша для сторінки, без конкретного елемента
```

Назви клавіш пишуться як у документації: `Enter`, `Escape`, `ArrowDown`, `Backspace`.

## Чекбокси: check чи click

| | `click()` | `check()` |
|---|---|---|
| галочки немає | ставить | ставить |
| галочка вже є | **знімає** | нічого не робить |
| після дії | — | перевіряє, що галочка справді стоїть |

`check()` описує **бажаний стан**, а не рух мишки, тому тест не залежить від того, яким був чекбокс до нього.

## Випадаючі списки

```python
country = page.get_by_label("Country")
country.select_option("Poland")              # за value або за текстом варіанта
country.select_option(label="United Kingdom")
country.select_option(index=2)               # третій варіант (з нуля)
```

`select_option` працює лише зі справжнім `<select>`. Якщо «список» намальований із `div` (кастомний dropdown) — його відкривають `click()` і вибирають варіант теж `click()`.

## Навігація

```python
page.reload()       # перезавантажити сторінку — перевірити, що дані зберігаються
page.go_back()      # кнопка «Назад» браузера
page.go_forward()
```

> [!QA]
> Багато вимог перевіряються лише через дію «збоку»: перезавантажити сторінку, повернутися кнопкою Назад, натиснути Esc замість Cancel. Користувачі роблять це щодня — і саме там часто ховаються баги збереження стану.

## Типові помилки

| Помилка | Що станеться |
|---|---|
| `.click` без дужок | нічого не натиснеться, помилки не буде |
| `fill` у `<select>` | `Error: Element is not an <input>, <textarea> or [contenteditable] element` |
| `click()` по чекбоксу, що вже стоїть | галочка зникне — тест перевірятиме не те |
| `select_option("Ukraina")` з опечаткою | дія чекає, доки такий варіант з'явиться, і падає з timeout |
| `press("enter")` з малої літери | Playwright не знає такої клавіші: `Unknown key` |

## Підсумок

- Дії — методи локатора: `click`, `fill`, `press`, `check`, `select_option`, `hover`, `set_input_files`.
- Кожна дія сама чекає, поки елемент готовий; пауз не треба.
- `fill` замінює значення одразу; `press_sequentially` — лише для полів, що реагують на кожну клавішу.
- `check()` задає стан галочки, `click()` її перемикає.
- `reload()`, `go_back()` і клавіші (`Escape`, `Enter`) — дії, що часто знаходять баги збереження стану.
