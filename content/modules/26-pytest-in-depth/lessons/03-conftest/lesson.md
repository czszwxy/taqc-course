# conftest.py і спільні фікстури

Фікстура в одному файлі тестів доступна лише цьому файлу. Але клієнт API, тестовий користувач чи браузер потрібні **багатьом** файлам. Для цього є спеціальний файл `conftest.py`.

## Як працює conftest.py

```text
tests/
├── conftest.py          ← фікстури для ВСІХ тестів у tests/ і підпапках
├── test_cart.py
└── api/
    ├── conftest.py      ← фікстури лише для тестів у tests/api/
    └── test_orders.py
```

```python
# tests/conftest.py
import pytest

@pytest.fixture
def base_url():
    return "https://staging.example.test"
```

```python
# tests/test_cart.py — без жодного import
def test_cart_page_url(base_url):
    assert cart_url(base_url) == "https://staging.example.test/cart"
```

pytest сам знаходить `conftest.py` у папці тестів і всіх батьківських папках (до кореня проєкту) і робить їхні фікстури доступними. **Імпортувати conftest не потрібно і не можна** — це службовий файл pytest.

## Розбір: де pytest шукає фікстуру

Тест у `tests/api/test_orders.py` просить `client`:

| Крок | Де шукає |
|---|---|
| 1 | у самому файлі `test_orders.py` |
| 2 | у найближчому `tests/api/conftest.py` |
| 3 | у батьківському `tests/conftest.py` |
| 4 | серед вбудованих фікстур і плагінів (`tmp_path`, `capsys`…) |

Перша знайдена — і використовується. Тому фікстуру можна **перевизначити** для підпапки: `tests/api/conftest.py` може мати свою `base_url`, яка для API-тестів замінить загальну.

## Фікстура-фабрика

Часто тестам потрібні **різні** варіанти даних. Фікстура може повертати функцію:

```python
# tests/conftest.py
@pytest.fixture
def make_product():
    def build(**overrides):
        product = {"name": "Mouse", "price": 450, "in_stock": True}
        product.update(overrides)
        return product
    return build
```

```python
def test_free_product_cannot_be_ordered(make_product):
    assert can_order(make_product(price=0)) is False
```

Так поєднуються переваги обох підходів: фабрика доступна всім тестам без імпорту, а кожен тест будує стільки об'єктів і з такими полями, скільки потрібно.

## Що тримати в conftest

| У `conftest.py` | У файлі тестів |
|---|---|
| те, що потрібно багатьом файлам: клієнт API, базовий URL, користувачі, браузер | фікстури, потрібні лише цьому файлу |
| фабрики тестових даних | одноразові дані конкретного сценарію |
| autouse-«прибиральники» для всієї папки | — |

> [!QA]
> У тестовому фреймворку на pytest `conftest.py` — це «серце»: тут живуть фікстури логіну, клієнтів API і браузера. Коли на співбесіді питають «як влаштований твій фреймворк», розповідь про conftest і фікстури — сильна відповідь. Список усіх доступних фікстур показує `python -m pytest --fixtures`.

## Типові помилки

- `from conftest import user` — так робити не треба: pytest підключає conftest сам, а імпорт може створити дві копії модуля з різними фікстурами.
- Усе підряд в одному кореневому conftest — він розростається до тисяч рядків; краще conftest у підпапках за темами.
- Одна й та сама назва фікстури в різних conftest без наміру — тести несподівано отримують «чужу» фікстуру.
- Хелпери, які не є фікстурами, у conftest — їх доведеться імпортувати; для них краще окремий модуль `helpers.py`.

## Підсумок

- `conftest.py` — фікстури для всіх тестів своєї папки й підпапок, без імпорту.
- Пошук: файл тесту → найближчий conftest → батьківські conftest → вбудовані.
- Фікстуру можна перевизначити в conftest підпапки.
- Фікстура-фабрика повертає функцію, яка будує дані з параметрами.
- conftest не імпортують; `python -m pytest --fixtures` показує всі фікстури.
