# Автентифікація: Basic, токени, JWT, cookies

Більшість API захищені: дані замовлень, профілю, адмінки бачать лише ті, кому можна. Помилки тут — найнебезпечніші баги: витік чужих даних, дії від імені іншого користувача. Тому тестування доступу — обов'язкова частина API-тестування.

## Автентифікація vs авторизація

| | Питання | Код, якщо не так |
|---|---|---|
| **Authentication** (автентифікація) | **Хто ти?** Чи справжній токен / пароль? | **401** Unauthorized |
| **Authorization** (авторизація) | **Що тобі можна?** Чи маєш права на цей ресурс? | **403** Forbidden |

## Способи автентифікації

**Basic auth** — логін і пароль у заголовку, закодовані Base64:

```text
Authorization: Basic cWFAZ2FkZ2V0bHkudGVzdDpUZXN0MTIzNA==
```

> [!WARNING]
> Base64 — це **кодування**, а не шифрування: будь-хто розкодує його за секунду. Basic auth допустимий лише через HTTPS.

**API key** — постійний ключ у заголовку (`X-API-Key: …`) або query. Часто для інтеграцій між сервісами.

**Bearer token** — після логіну сервер видає токен, і клієнт додає його до кожного запиту:

```text
POST /api/auth/login  { "email": "qa@gadgetly.test", "password": "Test1234" }
→ 200 { "token": "eyJhbGciOi…", "tokenType": "Bearer" }

GET /api/me
Authorization: Bearer eyJhbGciOi…
```

**Сесійні cookies** — після логіну сервер ставить cookie (`Set-Cookie: session=…; HttpOnly; Secure`), і браузер сам надсилає його з кожним запитом (урок 7 модуля 07).

## JWT

**JWT** (JSON Web Token) — популярний формат токена з трьох частин через крапку:

```text
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9 . eyJzdWIiOjQyLCJyb2xlIjoiY3VzdG9tZXIi… . Z2FkZ2V0bHkt…
            header (alg)                      payload (data)                    signature
```

- **Header** і **payload** — це JSON, закодований base64url. Їх **може прочитати будь-хто**.
- **Signature** — підпис сервера. Якщо змінити хоч один символ payload (наприклад, `role` на `admin`), підпис перестане збігатися, і сервер має відповісти **401**.
- У payload зазвичай: `sub` (id користувача), `role`, `exp` (коли спливає), `iat` (коли видано).

> [!QA]
> Ніколи не клади в payload секрети: пароль, номер картки — їх прочитає будь-хто. Розкодувати токен можна в **JWT decoder** у [API console](/playground/api).

## Що тестувати

| Тест | Очікування |
|---|---|
| Запит **без** токена | 401 |
| **Невалідний** / змінений токен | 401 |
| **Прострочений** токен | 401 |
| `Bearer` пропущено або з помилкою | 401 |
| Правильний токен, **свій** ресурс | 200 |
| Правильний токен, **чужий** ресурс (`/orders/1001` іншого користувача) | 403 (або 404) — **ніколи 200** |
| Роль customer на адмін-ендпоінті | 403 |
| Logout → старий токен | 401 (якщо токени відкликаються) |
| Неправильний пароль багато разів | блокування / 429 |

> [!IMPORTANT]
> Доступ до чужого ресурсу, просто змінивши id в URL, — вразливість **IDOR** (Insecure Direct Object Reference). Один з найчастіших і найдорожчих багів у реальних API. Перевіряй завжди.

## Підсумок

- 401 — не автентифікований; 403 — немає прав.
- Basic (Base64 ≠ шифрування), API key, Bearer token, сесійні cookies.
- JWT = header.payload.signature; payload читає будь-хто, підробку виявляє підпис.
- Тестуй відсутній / невалідний / прострочений токен, чужі ресурси (IDOR) і ролі.
