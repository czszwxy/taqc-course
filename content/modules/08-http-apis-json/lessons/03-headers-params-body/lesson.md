# Заголовки, параметри і тіло

Дані можна передати в запиті чотирма способами. Тестувальник має знати, **куди** що класти, і перевіряти, як API реагує, коли дані потрапляють «не туди».

```text
PATCH /api/orders/1002?notify=false HTTP/1.1     ← path parameter: 1002 · query parameter: notify
Authorization: Bearer eyJhbGciOi…                ← headers
Content-Type: application/json

{ "quantity": 3 }                                ← body
```

## Path-параметри

Частина шляху, що **ідентифікує ресурс**: `/orders/1002`, `/products/3`.

Тести: неіснуючий id (`9999` → 404), не той тип (`abc` → 400), від'ємний чи нульовий id, дуже велике число.

## Query-параметри

Після `?`, пари `ключ=значення` через `&`. Використовують для **фільтрів, сортування, пагінації**:

```text
/api/products?category=Phones&inStock=true&page=2&limit=5
```

Тести: кожен фільтр окремо і разом, межі (`limit=0`, `limit=51`, `page=0`), невідомі значення (`category=Cars`), регістр (`category=phones`), відсутній параметр (значення за замовчуванням).

> [!TIP]
> Спецсимволи в query кодуються: пробіл → `%20` або `+`, `&` → `%26`. Запит `?q=Phone & Case` без кодування сервер прочитає як `q=Phone ` і зайвий параметр ` Case`. Перевіряй пошук зі спецсимволами.

## Заголовки (headers)

| Заголовок | Де | Для чого |
|---|---|---|
| `Content-Type` | запит / відповідь | формат тіла: `application/json` |
| `Accept` | запит | який формат клієнт хоче отримати |
| `Authorization` | запит | токен: `Bearer eyJ…` |
| `Location` | відповідь | адреса створеного ресурсу (після 201) |
| `WWW-Authenticate` | відповідь | яку автентифікацію очікує сервер (з 401) |
| `Allow` | відповідь | дозволені методи (з 405) |
| `X-Request-Id` | відповідь | id запиту для пошуку в логах сервера |
| `Cache-Control`, `Set-Cookie` | відповідь | кешування і cookies |

> [!QA]
> Назви заголовків **нечутливі до регістру** (`content-type` = `Content-Type`), а значення — зазвичай чутливі. Перевір, як API реагує на відсутній `Content-Type`, на `text/plain` замість JSON і на `Authorization` без слова `Bearer`.

## Тіло (body)

Найчастіше — **JSON** (детально в наступному уроці). Тіло мають POST, PUT, PATCH; GET і DELETE — зазвичай ні.

Тести тіла: обов'язкові поля відсутні; зайві поля (`"total": 1` — чи не дасть сервер підмінити суму?); не ті типи (`"2"` замість `2`); `null`; порожній об'єкт `{}`; невалідний JSON; дуже великий body.

## Підсумок

- Path — **який** ресурс; query — **як** фільтрувати/сортувати/гортати; headers — **метадані**; body — **дані**.
- Тестуй межі й невалідні значення в кожному місці.
- `Content-Type`, `Authorization`, `Location`, `X-Request-Id` — заголовки, які QA перевіряє найчастіше.
- Зайві поля в тілі можуть бути діркою безпеки.
