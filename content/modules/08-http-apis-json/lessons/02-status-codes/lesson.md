# Статус-коди

Статус-код — тризначне число в першому рядку відповіді. Це **перше**, що перевіряє кожен API-тест: якщо код неправильний, клієнт (сайт, мобільний застосунок) неправильно зрозуміє відповідь — покаже «успіх» замість помилки або навпаки.

## Класи

| Клас | Значення | Хто «винен» |
|---|---|---|
| **1xx** | інформаційні (рідко бачиш) | — |
| **2xx** | успіх | — |
| **3xx** | перенаправлення | — |
| **4xx** | помилка **клієнта**: неправильний запит | клієнт (але сервер має відповісти правильним кодом!) |
| **5xx** | помилка **сервера** | сервер — **завжди баг** або збій інфраструктури |

## Найважливіші коди

| Код | Назва | Коли |
|---|---|---|
| **200** | OK | успішний GET, PUT, PATCH |
| **201** | Created | ресурс створено (POST); часто з заголовком `Location` |
| **204** | No Content | успіх без тіла (часто DELETE) |
| **301 / 302** | Moved | ресурс переїхав, браузер іде за новою адресою |
| **304** | Not Modified | «у тебе в кеші актуальна версія» |
| **400** | Bad Request | невалідні дані: немає поля, не той тип, кількість 0 |
| **401** | Unauthorized | **не автентифікований**: немає або невалідний токен |
| **403** | Forbidden | автентифікований, але **немає прав** |
| **404** | Not Found | ресурсу або маршруту не існує |
| **405** | Method Not Allowed | метод не підтримується (DELETE на каталог) |
| **409** | Conflict | конфлікт стану: товару немає в наявності, дубль |
| **415** | Unsupported Media Type | не той `Content-Type` тіла |
| **422** | Unprocessable Content | дані валідні за форматом, але порушують бізнес-правило |
| **429** | Too Many Requests | перевищено ліміт запитів |
| **500** | Internal Server Error | необроблена помилка на сервері |
| **502 / 503 / 504** | Bad Gateway / Unavailable / Timeout | проблеми інфраструктури, сервер недоступний |

> [!WARNING]
> **401 vs 403** — улюблене питання на співбесідах. 401: «я не знаю, хто ти» (увійди). 403: «я знаю, хто ти, але тобі сюди не можна».

## Коли статус-код — це баг

- Будь-який **5xx** у відповідь на дані користувача: сервер не обробив помилку. Правильно — 4xx з повідомленням.
- **200 з помилкою в тілі** (`{ "error": "…" }` зі статусом 200) — клієнт вирішить, що все гаразд.
- **201 / 204 замість 4xx** — сервер «прийняв» невалідні дані.
- **404 замість 403** або навпаки — залежить від вимог; але **200** на чужий ресурс — серйозний баг безпеки.
- Однакові помилки повертають **різні** коди в різних ендпоінтах.

> [!QA]
> Тестуючи API, перевіряй **код + тіло**: «400 і повідомлення `quantity must be from 1 to 10`» — значно кращий результат, ніж просто «400». Повідомлення має пояснювати, **що** не так.

## Практика

У завданні 3 ти виконаєш набір запитів у [API console](/playground/api) і запишеш, які коди повертає Gadgetly API.

## Підсумок

- 2xx — успіх, 3xx — перенаправлення, 4xx — помилка запиту, 5xx — помилка сервера.
- 200 / 201 / 204; 400 / 401 / 403 / 404 / 405 / 409 / 415 / 422; 500.
- 401 — хто ти? 403 — тобі не можна.
- 5xx на дані користувача і 2xx на невалідні дані — баги.
