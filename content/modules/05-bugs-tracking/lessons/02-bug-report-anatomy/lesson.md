# Будова баг-репорту

Баг-репорт — головний «продукт» тестувальника, який бачить уся команда. Хороший репорт дозволяє розробнику відтворити й виправити баг **без жодного питання** до тебе. Поганий — повертається з коментарем «не відтворюється» і забирає час у всіх.

## Поля баг-репорту

| Поле | Що писати | Приклад |
|---|---|---|
| **Summary** (заголовок) | що не так + де + за якої умови | Cart: SALE10 shows the discount line but does not reduce the total |
| **Environment** | середовище, браузер і версія, ОС, пристрій, версія білда | staging, build 2.4.1, Chrome 131, Windows 11 |
| **Preconditions** | стан до першого кроку | user olena@example.com is logged in; cart is empty |
| **Steps to reproduce** | пронумеровані дії, одна на крок | 1. Add "Laptop Stand"… |
| **Test data** | конкретні значення | promo code SALE10 |
| **Actual result** | що сталося насправді | total stays 1200 грн |
| **Expected result** | що мало статися (з посиланням на вимогу) | total is 1080 грн (−10%, US-58) |
| **Severity / Priority** | вплив і терміновість | Major / High |
| **Attachments** | скриншот, відео, лог | screenshot.png, console.log |
| **Reproducibility** | як часто відтворюється | always / 3 of 5 attempts |

## Summary: формула

**[Де] + [що не так] + [за якої умови]**, без емоцій і без слова «bug»:

| ❌ Погано | ✅ Добре |
|---|---|
| Кошик не працює!!! | Cart: total is not updated after changing quantity |
| Bug with login | Login: valid user is rejected when email has capital letters |
| Помилка | Checkout: "Pay" button stays disabled after entering a valid card |

> [!TIP]
> Перевір summary так: чи зрозуміє тімлід, **що зламалось і наскільки це серйозно**, прочитавши лише заголовок у списку з 50 багів?

## Кроки відтворення

- Починаються з **передумови** (стану), а не з «відкрий комп'ютер».
- **Одна дія — один крок**, нумеровані.
- **Мінімальні**: прибери кроки, які не впливають на відтворення.
- **Конкретні дані**: не «додай товар», а «додай "Laptop Stand" (1200 грн)».

## Фактичний і очікуваний результат

- **Actual** — що ти **побачив**: точний текст помилки, значення, стан. Не «не працює».
- **Expected** — що **мало** статися, бажано з посиланням на вимогу чи user story.
- Вони мають **відрізнятися**. Якщо ні — це не баг.

> [!QA]
> Один баг — один репорт. Якщо знайшов дві проблеми на одній сторінці, заведи два баги: їх можуть виправляти різні люди в різний час.

## Підсумок

- Обов'язкові поля: summary, environment, steps, actual, expected, severity/priority.
- Summary: де + що + за якої умови.
- Кроки: від передумови, атомарні, мінімальні, з конкретними даними.
- Actual — що побачив; expected — що мало бути (з посиланням на вимогу).
