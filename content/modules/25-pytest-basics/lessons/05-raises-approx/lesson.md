# Перевірка винятків і дробових чисел

Половина важливих тестів — **негативні**: система має правильно відмовити на погані дані. А друга пастка — дробові числа, які не можна порівнювати через `==`. pytest має для обох випадків окремі інструменти.

## pytest.raises

```python
import pytest

def test_zero_quantity_is_rejected():
    with pytest.raises(ValueError):
        parse_quantity("0")
```

Тест проходить, якщо код усередині блоку `with` підняв `ValueError` (або його нащадка).

## Розбір: три результати блоку raises

| Що сталося в блоці | Результат тесту |
|---|---|
| піднято `ValueError` | ✅ тест пройшов — очікувана відмова |
| винятку не було | ❌ `DID NOT RAISE ValueError` — код прийняв погані дані |
| піднято інший тип, наприклад `KeyError` | ❌ виняток «пролітає» далі — тест падає з ним |

Тобто `raises` перевіряє і **сам факт** відмови, і **тип** винятку.

## match — перевірка повідомлення

```python
with pytest.raises(ValueError, match="Invalid quantity: '0'"):
    parse_quantity("0")
```

`match` — це **регулярний вираз**, який шукають у тексті винятку. Символи `.` `(` `)` `?` `*` `+` у ньому мають спеціальне значення. Якщо в повідомленні є такі символи, екрануй увесь текст: `match=re.escape("Invalid quantity: '1.5'")`.

## Деталі винятку: as exc_info

```python
with pytest.raises(ConfigError) as exc_info:
    load_settings({})

assert exc_info.value.setting == "base_url"
assert str(exc_info.value) == "Missing setting: base_url"
```

`exc_info.value` — сам об'єкт винятку: його атрибути й текст можна перевірити звичайними `assert` **після** блоку `with`.

> [!WARNING]
> У блоці `with pytest.raises(...)` залишай **один** виклик, який має впасти. Рядки після нього всередині блоку не виконаються, а якщо виняток підніме не той рядок, який ти мав на увазі, тест пройде з хибної причини.

## Дробові числа і approx

```python
0.1 + 0.2 == 0.3          # False — 0.30000000000000004
```

Дробові числа зберігаються з крихітною похибкою, тож `==` для них ненадійне. `pytest.approx` порівнює з допуском:

```python
def test_average_response_time():
    assert average([0.1, 0.2]) == pytest.approx(0.15)
```

За замовчуванням допуск відносний — мільйонна частка від очікуваного значення. Його можна змінити: `pytest.approx(10.0, abs=0.01)` — «±0.01», `pytest.approx(10.0, rel=0.05)` — «±5 %». `approx` працює і зі списками: `[0.1, 0.2] == pytest.approx([0.1, 0.2])`.

> [!QA]
> Гроші в серйозних системах зберігають цілими числами (копійки), і тоді `approx` не потрібен — порівнюй точно. `approx` — для того, що справді дробове: середні, відсотки, час відповіді, координати.

## Типові помилки

- `pytest.raises(Exception)` — пройде на **будь-якій** помилці, навіть на `TypeError` через опечатку в коді. Вказуй конкретний тип.
- `pytest.raises(ValueError)` без `with` — нічого не перевіряє.
- Кілька дій у блоці `with` — тест може пройти, бо впала «не та» дія.
- `match="Price (UAH) is invalid"` — дужки в регулярному виразі означають групу; використовуй `re.escape`.
- `assert round(result, 2) == 0.15` — округлення ховає справжню похибку; для дробових — `approx`.

## Підсумок

- `with pytest.raises(Тип):` — тест падає, якщо винятку немає або він іншого типу.
- `match` — регулярний вираз для тексту винятку; спецсимволи — через `re.escape`.
- `as exc_info` → `exc_info.value` для атрибутів і тексту, перевірки — після блоку.
- Дробові — через `pytest.approx` (`rel`, `abs`); цілі гроші — точне `==`.
