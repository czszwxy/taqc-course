# Перші тести з assert

`assert` — серце тесту. Від того, **що** саме ти перевіряєш і **на яких значеннях**, залежить, чи впаде тест на справжньому багу.

## assert і повідомлення pytest

```python
def test_vat_is_added():
    assert add_vat(1000) == 1250
```

Якщо функція повернула 1200, pytest покаже обидва значення:

```text
>       assert add_vat(1000) == 1250
E       assert 1200 == 1250
E        +  where 1200 = add_vat(1000)
```

Ліворуч — що **отримали**, праворуч — що **очікували**. Для списків і словників pytest показує різницю елемент за елементом. Тому повідомлення в `assert` зазвичай не потрібне; додають його, коли значення самі по собі нічого не пояснюють:

```python
assert response_time < 500, f"too slow for /api/orders: {response_time} ms"
```

## Що перевіряти

| Перевірка | Коли |
|---|---|
| `assert result == 850` | конкретне значення — найчастіше і найсильніше |
| `assert result is None` | функція має нічого не знайти |
| `assert result is True` | саме `True`, а не будь-яке truthy-значення |
| `assert "Invalid email" in message` | частина тексту |
| `assert isinstance(total, int)` | тип результату важливий |
| `assert items == ["a", "b"]` | увесь список одразу — порядок і склад |

## Одна поведінка — один тест

```python
def test_is_adult_at_18():
    assert is_adult(18) is True

def test_is_adult_false_at_17():
    assert is_adult(17) is False
```

Якщо в одному тесті десять перевірок, перша ж невдала зупинить його, і решта проблем залишиться невидимою. Окремі тести покажуть усі.

Назва — це опис поведінки: `test_<що>_<умова>_<результат>`. За `test_is_adult_false_at_17` у звіті одразу зрозуміло, що зламалося, а за `test_1` — ні.

## Розбір: які значення взяти

Функція `is_adult(age)` повертає `True` від 18 років. Техніки з модуля тест-дизайну працюють і для автотестів:

| Значення | Звідки | Чому саме воно |
|---|---|---|
| `17` | межа — 1 | останнє «ні» |
| `18` | межа | перше «так» — ловить `>` замість `>=` |
| `40` | клас «дорослі» | типове значення всередині класу |
| `0` | клас «діти», мінімум | нижній край |

Чотири тести замість сотні випадкових значень — і кожен перевіряє окремий ризик.

> [!QA]
> Найкорисніший тест той, що впаде на **реальному** багу. Перш ніж писати перевірку, спитай себе: «Яку помилку розробника ловить цей тест?» Якщо відповіді немає — тест, найімовірніше, зайвий.

## Типові помилки

- `assert result == 5 or 6` — **завжди** істинне: `or 6` — це просто 6, а воно truthy. Правильно `result in (5, 6)`.
- `assert (result == 5, "message")` — кортеж у дужках завжди truthy, тест ніколи не впаде (pytest навіть попередить). Повідомлення пишуть **без** дужок: `assert result == 5, "message"`.
- `assert result` замість `assert result == 850` — пройде для будь-якого непорожнього значення.
- Очікуване значення, обчислене тією самою формулою, що й у коді (`assert f(x) == x * 85 // 100`): якщо формула хибна, тест повторить помилку. Пиши конкретні числа.

## Підсумок

- `assert вираз`; pytest сам показує обидва значення при падінні.
- Перевіряй конкретні значення: `==`, `is None`, `is True`, `in`, `isinstance`.
- Одна поведінка — один тест; назва описує поведінку.
- Значення — з класів еквівалентності й меж.
- Пастки: `== a or b`, `assert (умова, "msg")`, слабкий `assert result`.
