# CRUD-тести з фікстурами і прибиранням

CRUD — це **C**reate, **R**ead, **U**pdate, **D**elete: створити, прочитати, змінити, видалити. Тести таких операцій змінюють дані на сервері, тому мають два обов'язки: працювати **на своїх** даних і **прибирати** їх за собою — навіть коли тест упав. У pytest для обох задач є фікстури.

## Сесія з токеном на весь запуск

```python
@pytest.fixture(scope="session")
def session(api):
    s = requests.Session()
    login = s.post(f"{api}/auth/login", json=USER, timeout=TIMEOUT)
    login.raise_for_status()
    s.headers.update({"Authorization": f"Bearer {login.json()['token']}"})
    yield s
    s.close()
```

Вхід відбувається один раз; усі тести отримують ту саму сесію з токеном у заголовках. Після `yield` — закриття з'єднань.

## Дані — фікстура з yield

Приклад для уявного API нотаток (у Gadgetly такого немає — тут важливий шаблон):

```python
@pytest.fixture
def note(session, api):
    response = session.post(f"{api}/notes", json={"text": "QA"}, timeout=TIMEOUT)
    response.raise_for_status()
    created = response.json()
    yield created
    session.delete(f"{api}/notes/{created['id']}", timeout=TIMEOUT)   # без assert: нотатку міг видалити сам тест
```

## Розбір: порядок виконання

| Крок | Що відбувається |
|---|---|
| 1 | pytest бачить, що тест просить `note`, а `note` — `session` |
| 2 | `session` уже є (scope session) — вхід не повторюється |
| 3 | `note` створює нотатку і віддає її тесту (`yield created`) |
| 4 | тест працює з нотаткою — можливо, падає на assert |
| 5 | **завжди** виконується код після `yield`: `DELETE` |
| 6 | наступний тест отримує нову нотатку — тести не залежать один від одного |

Прибирання не має **падати**: якщо тест сам видалив об'єкт, повторний `DELETE` поверне 404 — це нормально. Тому в teardown немає `assert`.

## Фабрика: кілька об'єктів на тест

```python
@pytest.fixture
def make_note(session, api):
    created = []

    def make(**fields):
        response = session.post(f"{api}/notes", json={"text": "QA", **fields}, timeout=TIMEOUT)
        response.raise_for_status()
        created.append(response.json()["id"])
        return response.json()

    yield make
    for note_id in created:
        session.delete(f"{api}/notes/{note_id}", timeout=TIMEOUT)
```

Тест викликає `make_note(text="A")`, `make_note(text="B")` скільки треба; фікстура пам'ятає всі id і прибирає їх наприкінці.

## Що перевіряти в CRUD

| Операція | Перевірки |
|---|---|
| Create (`POST`) | `201`, `Location`, тіло відповідає вимогам; потім `GET` повертає те саме |
| Read (`GET`) | `200` і той самий об'єкт; чужий — `403`; неіснуючий — `404` |
| Update (`PUT`) | повна заміна: усі поля — нові, похідні значення (суми) перераховані |
| Update (`PATCH`) | змінене лише передане поле, похідні значення перераховані |
| Delete (`DELETE`) | `204`, потім `GET` → `404`; повторний `DELETE` → `404` |

> [!WARNING]
> Ніколи не перевіряй **глобальну** кількість: «замовлень стало 3». Інші тести (і паралельні запуски) створюють і видаляють свої дані в ту саму мить. Перевіряй **свій** об'єкт за його `id`.

> [!QA]
> Тест, що не прибирає за собою, — це «бомба уповільненої дії»: сьогодні він зелений, а через тиждень тестова база забита тисячами сміттєвих записів, і падають зовсім інші тести. Прибирання — частина тесту, а не «приємний бонус».

## Типові помилки

- Створення даних у тілі тесту без прибирання — дані лишаються після кожного падіння.
- `assert` у teardown — прибирання падає на вже видаленому об'єкті і ховає справжню помилку тесту.
- Тест B використовує замовлення, створене тестом A.
- Перевірка «стало на одне більше» замість перевірки свого об'єкта за `id`.
- Session-фікстура з даними, які тести змінюють: зміни одного тесту бачить наступний.

## Підсумок

- Сесія з токеном — `scope="session"`; дані — фікстура `scope="function"` з `yield`.
- Код після `yield` виконується завжди, навіть після падіння тесту; він не має падати сам.
- Фабрика-фікстура створює скільки треба об'єктів і прибирає всі.
- CRUD-перевірки: 201 + Location, читання того самого, перерахунок похідних значень, 204 і 404 після видалення.
- Перевіряй свій об'єкт за `id`, а не глобальні кількості.
