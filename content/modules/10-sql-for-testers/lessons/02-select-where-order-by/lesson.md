# SELECT, WHERE, ORDER BY

90% запитів тестувальника — це `SELECT` з умовою: «покажи замовлення 1006», «знайди користувачів без міста», «які товари закінчилися». У цьому уроці — все, що для цього потрібно.

## Порядок частин запиту

```sql
SELECT name, price          -- 1. які колонки
FROM products               -- 2. з якої таблиці
WHERE category = 'Laptops'  -- 3. які рядки (фільтр)
ORDER BY price DESC         -- 4. у якому порядку
LIMIT 2;                    -- 5. скільки рядків
```

Частини пишуться **саме в такому порядку**. `--` починає коментар до кінця рядка.

## WHERE: оператори порівняння

| Оператор | Значення | Приклад |
|---|---|---|
| `=` | дорівнює | `status = 'paid'` |
| `<>` (або `!=`) | не дорівнює | `status <> 'cancelled'` |
| `>`, `<`, `>=`, `<=` | більше / менше | `price >= 1000` |

Текст і дати пишуться в **одинарних** лапках: `'Kyiv'`, `'2024-09-14'`. Числа пишуться без лапок.

> [!WARNING]
> У SQLite `=` для тексту **чутливий до регістру**: `city = 'kyiv'` не знайде `Kyiv`. У PostgreSQL так само, а в MySQL зазвичай ні. Пиши значення точно як у даних. Якщо регістр невідомий, використовуй `LOWER(city) = 'kyiv'`.

## AND, OR, NOT і дужки

```sql
SELECT name, price FROM products
WHERE in_stock = 1 AND price < 1000;

SELECT id, status FROM orders
WHERE status = 'paid' OR status = 'shipped';
```

`AND` виконується раніше за `OR`, як множення раніше за додавання. Тому змішуючи їх, став дужки:

```sql
-- товари в наявності, які є ноутбуками АБО телефонами
WHERE in_stock = 1 AND (category = 'Laptops' OR category = 'Phones')
```

Без дужок умова означала б «(в наявності І ноутбук) АБО будь-який телефон». Це типовий баг і в запитах, і в коді фільтрів.

## IN, BETWEEN, LIKE

```sql
WHERE status IN ('paid', 'shipped')          -- одне зі значень списку
WHERE status NOT IN ('delivered', 'cancelled')
WHERE price BETWEEN 2000 AND 10000           -- включно з обома межами!
WHERE created_at BETWEEN '2024-08-01' AND '2024-08-31'
WHERE name LIKE '%Phone%'                    -- містить "Phone"
WHERE email LIKE 'a%'                        -- починається з "a"
```

У `LIKE` знак `%` означає будь-яку кількість будь-яких символів, а `_` — рівно один символ. У SQLite `LIKE` для латиниці **не** чутливий до регістру.

> [!QA]
> `BETWEEN` включає обидві межі. Це ті самі boundary values, що й у модулі 03! Якщо вимога каже «від 2000 до 10000 включно», `BETWEEN 2000 AND 10000` підходить. Якщо «більше 2000», потрібно `price > 2000`.

Дати тут зберігаються текстом у форматі `РРРР-ММ-ДД`. Такий текст сортується й порівнюється так само, як дати. Тому `BETWEEN '2024-08-01' AND '2024-08-31'` працює.

## IS NULL

```sql
SELECT id, name FROM users WHERE city IS NULL;      -- місто не вказане
SELECT id, name FROM users WHERE city IS NOT NULL;
```

`city = NULL` завжди повертає 0 рядків: з `NULL` нічого не «дорівнює», навіть інший `NULL`.

## ORDER BY і LIMIT

```sql
SELECT name, price FROM products
ORDER BY price DESC, name ASC   -- спершу за ціною (спадання), при рівній ціні — за назвою
LIMIT 3;                        -- лише перші 3 рядки
```

`ASC` (за зростанням) діє за замовчуванням, `DESC` сортує за спаданням. Без `ORDER BY` порядок рядків **не гарантований**. Не покладайся на нього в тестах!

> [!TIP]
> «Топ-3 найдорожчі», «5 останніх замовлень» завжди пишуться через `ORDER BY … LIMIT N`. Без `ORDER BY` `LIMIT` бере випадкові N рядків.

## DISTINCT і псевдоніми

```sql
SELECT DISTINCT city FROM users;           -- кожне місто один раз
SELECT name AS product, price AS uah FROM products;   -- AS дає колонці іншу назву
```

## Підсумок

- Порядок частин: `SELECT … FROM … WHERE … ORDER BY … LIMIT`.
- Текст і дати пишуться в одинарних лапках. У SQLite `=` для тексту чутливий до регістру.
- Змішуючи `AND` з `OR`, став дужки.
- `IN` перевіряє список значень, `BETWEEN` — діапазон включно з межами, `LIKE` з `%` і `_` — шаблон.
- `NULL` шукають тільки через `IS NULL` / `IS NOT NULL`.
- `ORDER BY` задає порядок (`DESC` — за спаданням), `LIMIT` обрізає результат, `DISTINCT` прибирає повтори.
