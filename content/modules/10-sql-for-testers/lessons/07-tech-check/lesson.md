# Tech check: веб, HTTP, Git і SQL

Технічна база — улюблена частина tech check для джунів: питання короткі, а по відповіді одразу видно, чи людина реально працювала з DevTools, API і базою даних, чи лише читала про них. «Чим 401 відрізняється від 403?», «Що відбувається, коли вводиш адресу сайту?», «Чим LEFT JOIN відрізняється від INNER?» — класика співбесід.

Цей урок закриває технічний блок. Блок вважається пройденим, коли ти складеш tech check.

## Як проходить сесія

1. 12 випадкових питань з банку — рівномірно з кожної теми, тема за темою.
2. На кожне — близько 2 хвилин. Відповідай **уголос**.
3. Відкриваєш еталонну відповідь і відмічаєш ключові пункти, які ти **справді сказав**.
4. Прохідний бал — 80%. Повторна спроба — новий набір питань.

## Як відповідати на технічні питання

- **Коротке визначення + приклад з практики.** «401 — немає автентифікації: наприклад, запит без токена. 403 — автентифікація є, а прав немає: звичайний користувач відкриває адмінку».
- **Покажи, що користувався інструментом.** «Я відкриваю Network, фільтрую Fetch/XHR, дивлюся статус і тіло відповіді» звучить переконливіше за визначення з підручника.
- **Пов'яжи з тестуванням.** Навіщо QA знати JOIN? Щоб перевірити, що замовлення збереглося з правильним користувачем.
- **Код і запити проговорюй.** Якщо просять написати SQL — проговорюй кожну частину: «вибираю з таблиці orders, фільтрую за user_id, сортую за датою від нових».

> [!TIP]
> У питаннях про HTTP і SQL інтерв'юери люблять уточнення: «А що таке ідемпотентність?», «А як знайти користувачів без замовлень?». Знай не лише відповідь, а й наступний крок.

## Після сесії

- **Не склав** — таблиця «By topic» покаже, які модулі технічного блоку повторити.
- **Склав** — закріпи з Claude (**Practice with Claude**) або з ментором (**Questions for a mentor**), а ще краще — відкрий DevTools і поясни вголос, що бачиш у Network на будь-якому сайті.

> [!QA]
> Технічні питання на співбесіді часто перетікають у практику: «Ось сайт — покажи в DevTools, звідки беруться дані». Тренуй не лише відповіді, а й дії в інструментах.

## Що перевіряє цей tech check

| Тема | Про що питають |
|---|---|
| Як працює веб | клієнт-сервер, URL і DNS, DOM, DevTools (Console, Network), cookies і storage, селектори, адаптивність |
| HTTP і API | методи, статус-коди, 401 vs 403, запит і відповідь, REST і CRUD, JSON, токени й JWT, тест-дизайн API, Postman |
| Git і GitHub | цикл роботи, гілки, конфлікти, pull request і рев'ю, .gitignore |
| SQL | SELECT, JOIN, GROUP BY / HAVING, ключі, UPDATE / DELETE, SQL у роботі тестувальника |

## Підсумок

- Технічні питання короткі, тож особливо цінуються приклади з практики.
- Показуй, що користувався інструментами: DevTools, Postman, Git, SQL.
- Пов'язуй кожну тему з тестуванням.
- Готуйся до уточнень: знай не лише відповідь, а й наступне питання.
