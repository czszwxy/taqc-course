# Каскад, специфічність і успадкування

Ти пишеш `.title { color: red; }`, а заголовок лишається синім. Найчастіша причина — інше правило **сильніше**. CSS вирішує такі суперечки за чіткими правилами; хто їх знає, той не воює зі стилями через `!important`.

## Каскад: хто перемагає

Коли кілька правил задають одну властивість одному елементу, браузер порівнює їх по черзі:

1. **Походження й важливість.** Стилі браузера (за замовчуванням) < твої стилі. `!important` перевертає порядок — перемагає важливе.
2. **Специфічність** селектора — хто «точніше» вказав на елемент.
3. **Порядок у коді**: за рівної специфічності перемагає те, що **нижче** (пізніше).

Атрибут `style="…"` сильніший за будь-який селектор у файлі — ще одна причина його уникати.

## Як рахувати специфічність

Специфічність — три числа **(id, класи, теги)**, порівнюються зліва направо:

| Селектор | id | класи, атрибути, псевдокласи | теги, псевдоелементи | Разом |
|---|---|---|---|---|
| `p` | 0 | 0 | 1 | (0, 0, 1) |
| `article p` | 0 | 0 | 2 | (0, 0, 2) |
| `.headline` | 0 | 1 | 0 | (0, 1, 0) |
| `a[href^="https://"]` | 0 | 1 | 1 | (0, 1, 1) |
| `.news .headline:hover` | 0 | 3 | 0 | (0, 3, 0) |
| `#top-story` | 1 | 0 | 0 | (1, 0, 0) |

(0, 1, 0) перемагає (0, 0, 2): один клас «важить» більше за будь-яку кількість тегів. А один id — більше за будь-яку кількість класів.

Особливі псевдокласи:

- `:is(.a, #b)` і `:not(#b)` беруть специфічність **найсильнішого** аргументу;
- `:where(…)` завжди має специфічність **0** — зручно для базових стилів, які легко перебити.

## Чому id і !important — пастка

Новинний сайт: заголовок головної новини.

```css
#top-story .headline { color: #111827; }    /* (1, 1, 0) */
.headline--urgent    { color: #b91c1c; }    /* (0, 1, 0) — програє, хоча написано пізніше */
```

Щоб термінові новини стали червоними, доводиться писати ще сильніший селектор або `!important`. Потім хтось перебиває `!important` іншим `!important` — починається «війна специфічності». Як її уникнути:

- для стилів — **класи**, а не id;
- тримай специфічність **низькою й рівною** (один-два класи), тоді все вирішує порядок у файлі;
- `!important` — лише в крайньому разі (наприклад, службовий клас `.visually-hidden`).

## Успадкування

Деякі властивості передаються від батька до нащадків, якщо нащадку не задано своє значення:

| Успадковуються | Не успадковуються |
|---|---|
| `color`, `font-family`, `font-size`, `font-weight`, `line-height`, `text-align`, `letter-spacing`, `visibility`, `cursor`, `list-style` | `margin`, `padding`, `border`, `background`, `width`, `height`, `display`, `position` |

Тому `body { color: #1f2937; font-family: system-ui, sans-serif; }` фарбує весь текст сторінки, а `body { border: 1px solid; }` не дає рамку кожному абзацу.

Ключові слова для будь-якої властивості:

- `inherit` — взяти значення батька;
- `initial` — початкове значення зі стандарту;
- `unset` — `inherit` для успадковуваних властивостей, `initial` для інших.

> [!WARNING]
> Кнопки й поля форм **не** успадковують шрифт: браузер дає їм власний системний. Тому майже в кожному проєкті є правило `button, input, select, textarea { font: inherit; }`.

## Шари @layer

Сучасний CSS має **шари каскаду**: `@layer base, components;`. Правило з пізнішого шару перемагає правило з ранішого незалежно від специфічності. Це зручно для великих проєктів і бібліотек; поки достатньо знати, що такий інструмент існує.

## Як розібратися в DevTools

DevTools → Elements → Styles показує правила вибраного елемента від сильнішого до слабшого. Перебита декларація закреслена — поруч видно, яке правило перемогло. Нижче — блок «Inherited from body»: успадковані значення.

## Підсумок

- Перемагає: важливість → специфічність → пізніший порядок.
- Специфічність (id, класи, теги): клас сильніший за будь-яку кількість тегів, id — за будь-яку кількість класів.
- Класи замість id, низька й рівна специфічність, без `!important`.
- Шрифт, колір, інтерліньяж успадковуються; відступи, рамки, фон — ні; кнопкам потрібен `font: inherit`.
