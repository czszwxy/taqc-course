# Як працює CSS

HTML каже, **що** є на сторінці, а **CSS** (Cascading Style Sheets) — **як** це виглядає: кольори, шрифти, відступи, розташування блоків. Та сама розмітка з іншим CSS може виглядати як блог, інтернет-магазин чи застосунок — і саме тому структуру й вигляд тримають окремо.

## Правило CSS

Кулінарний блог: виділимо час приготування.

```css
/* коментар: браузер його пропускає */
.cook-time {
  color: #b45309;
  font-weight: 700;
}
```

- `.cook-time` — **селектор**: до яких елементів застосувати правило.
- `color: #b45309;` — **декларація**: **властивість**, двокрапка, **значення**, крапка з комою.
- Усе разом у фігурних дужках — **правило**.

## Три способи підключити CSS

```html
<!-- 1. Окремий файл: найкраще -->
<link rel="stylesheet" href="styles.css">

<!-- 2. <style> у <head>: стилі лише для цієї сторінки -->
<style>
  .cook-time { color: #b45309; }
</style>

<!-- 3. Атрибут style: уникай -->
<p style="color: #b45309">25 хвилин</p>
```

| Спосіб | Плюси | Мінуси |
|---|---|---|
| `<link>` на файл | один файл для всіх сторінок, браузер кешує його | ще один запит до сервера (один раз) |
| `<style>` | швидко для однієї сторінки | на інших сторінках доведеться копіювати |
| `style="…"` | — | не можна перевикористати, складно перебити іншим правилом, змішує вигляд зі структурою |

`<link>` пишуть у `<head>`: так сторінка одразу малюється зі стилями, без «миготіння» голого HTML.

## Селектори для стилів

У модулі «How the Web Works» селектори були інструментом пошуку. Тут ті самі селектори вирішують, **кого фарбувати**:

| Селектор | Кого обирає | Приклад |
|---|---|---|
| `p` | усі елементи типу | усі абзаци |
| `.recipe` | елементи з класом | `<article class="recipe">` |
| `#main` | елемент з id | для стилів краще класи — id занадто «сильний» (наступний урок) |
| `[aria-current="page"]` | за атрибутом | поточний пункт меню |
| `a[href^="https://"]` | атрибут **починається** з | посилання на інші сайти |
| `nav a` | нащадок: `a` будь-де всередині `nav` | посилання меню |
| `ul > li` | **дочірній**: лише прямі діти | пункти верхнього рівня |
| `h2 + p` | **сусідній**: `p` одразу після `h2` | перший абзац розділу |
| `h1, h2` | група: те саме правило для кількох | |
| `li:first-child`, `tr:nth-child(odd)` | за позицією | перший пункт, непарні рядки |
| `a:hover`, `input:focus-visible` | за станом | наведення, фокус з клавіатури |
| `p:not(.note)` | заперечення | усі абзаци, крім приміток |
| `.link::after` | **псевдоелемент**: «віртуальний» шматок до / після вмісту | значок ↗ після посилання |

```css
a[href^="https://"]::after {
  content: " ↗";
}
```

> [!NOTE]
> Класи чутливі до регістру: `.Recipe` не знайде `class="recipe"`. Пиши класи малими літерами через дефіс: `.cook-time`, `.recipe-card`.

> [!WARNING]
> Текст з `content` у `::before` / `::after` — це прикраса. Частина екранних читачів його озвучує, частина ні, і його не можна виділити й скопіювати. Важлива інформація має бути в HTML.

## Коли CSS «не працює»

Браузер **мовчки пропускає** декларацію, яку не зрозумів, і йде далі:

| Помилка | Що станеться |
|---|---|
| `colr: red;` | невідома властивість — декларацію пропущено |
| `width: 100 px;` | пробіл між числом і одиницею — значення неправильне, пропущено |
| `color: red font-size: 20px;` | забута `;` — обидві декларації злилися в одне неправильне значення |
| `.Recipe { … }` при `class="recipe"` | селектор нічого не знаходить |
| `recipe { … }` без крапки | шукає тег `<recipe>`, якого немає |

Як шукати: **DevTools → Elements → Styles**. Там видно всі правила, що діють на вибраний елемент; пропущена декларація закреслена з жовтим трикутником ⚠, а перебита іншим правилом — просто закреслена. Галочкою можна вимкнути декларацію, а клік по значенню дає змінити його «наживо». Вкладка **Computed** показує підсумкові значення.

## Як працювати з задачами

У CSS-задачах HTML уже готовий (його видно в умові, у блоці `index.html`), а ти пишеш `styles.css`. Preview показує сторінку з твоїми стилями, а Check вимірює підсумкові значення: колір, відступи, позиції блоків — так само, як вкладка Computed у DevTools.

## Підсумок

- Правило = селектор + декларації `властивість: значення;`.
- Стилі — в окремому файлі через `<link rel="stylesheet">` у `<head>`; атрибута `style` уникай.
- Для стилів — класи, атрибути, комбінатори й псевдокласи; id і теги — рідше.
- `::before` / `::after` з `content` — лише для прикрас.
- Браузер пропускає незрозумілі декларації мовчки — шукай їх у DevTools → Styles.
