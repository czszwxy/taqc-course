# Стани, переходи й рух

Інтерфейс «відповідає» людині: кнопка темнішає під мишкою, поле з помилкою червоніє, вибрана картка підсвічується. CSS уміє стилізувати стани **без JavaScript** — головне, щоб стан на екрані збігався з тим, що чує екранний читач, і щоб рух не шкодив.

## Псевдокласи станів

Фотогалерея: кнопки й перемикачі.

```css
.button:hover { background-color: #1e40af; }          /* під мишкою */
.button:active { transform: translateY(1px); }        /* поки натискають */
.button:disabled { background-color: #e5e7eb; color: #4b5563; cursor: not-allowed; }
input:checked + .switch-label { font-weight: 700; }   /* позначений перемикач */
```

| Псевдоклас | Коли діє |
|---|---|
| `:hover` | курсор над елементом — **на сенсорних екранах наведення немає** |
| `:focus` | елемент у фокусі — будь-яким способом, і клацанням мишки теж |
| `:focus-visible` | фокус, який варто показати: з клавіатури, у полях вводу |
| `:active` | поки кнопку натискають |
| `:disabled` / `:enabled` | поле чи кнопка вимкнені |
| `:checked` | позначений чекбокс чи радіокнопка |
| `:invalid` | значення не проходить перевірку — **одразу**, навіть у порожньому полі |
| `:user-invalid` | те саме, але лише **після** того, як людина змінила поле |
| `:has(…)` | у елемента є нащадок, що відповідає селектору |

> [!WARNING]
> Ніколи не пиши `:focus { outline: none; }` без заміни. Якщо рамка «некрасива» при кліку мишкою — стилізуй `:focus-visible`: її бачитимуть ті, хто працює з клавіатурою, і не бачитимуть ті, хто клікає.

```css
.button:focus-visible {
  outline: 3px solid #f59e0b;
  outline-offset: 2px;
}
```

`:hover` — лише бонус. Важлива інформація (підказка, кнопка «Видалити») не має з'являтися **тільки** при наведенні: на телефоні її не побачать.

## :has() — стиль батька за станом дитини

```html
<label class="album-option">
  <input type="radio" name="album" value="travel"> Подорожі
</label>
```

```css
.album-option:has(input:checked) {
  border-color: #1d4ed8;
  background-color: #eff6ff;
}
```

Раніше для цього потрібен був JavaScript. `:has()` працює в усіх сучасних браузерах з кінця 2023 року.

## Стилі через ARIA-атрибути

Стан, який читач уже чує, найкраще стилізувати **за тим самим атрибутом** — тоді вигляд ніколи не розійдеться з доступністю:

```css
.filters-toggle[aria-expanded="true"] { background-color: #1d4ed8; color: #fff; }
nav a[aria-current="page"] { font-weight: 700; }
input[aria-invalid="true"] { border-color: #b91c1c; }
```

Замість класу `.is-open`, який легко забути оновити разом з `aria-expanded`, — один атрибут на обидві потреби.

## Переходи

```css
.button {
  transition: background-color 150ms ease;
}
```

`transition` плавно змінює значення між станами: **що** анімувати, **скільки** триває, **як** (крива). 100–300 мс — непомітно швидко й приємно; довше — інтерфейс здається повільним.

Найдешевше для браузера анімувати `transform` (зсув, масштаб, поворот) і `opacity` — вони не змушують перераховувати розкладку. Анімація `width`, `height`, `top` змушує браузер перемальовувати сторінку на кожному кадрі.

Для складніших рухів є `@keyframes` + `animation`, але правило те саме: коротко, по суті, без нескінченного «блимання».

## prefers-reduced-motion

У людей з вестибулярними розладами рух на екрані може викликати запаморочення й нудоту. Вони вмикають у системі «Зменшити рух», і сторінка це бачить:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    transition: none !important;
    animation: none !important;
    scroll-behavior: auto !important;
  }
}
```

(Тут `!important` виправданий: це загальне «вимкнути все» поверх будь-яких компонентів.) Або точково: вимикати лише великі рухи, залишаючи зміну кольору.

## Підсумок

- `:hover` — бонус, не єдиний спосіб; `:focus-visible` — обов'язкова видима рамка фокусу.
- `:disabled`, `:checked`, `:user-invalid`, `:has()` стилізують стан без JavaScript.
- Стан, що є в ARIA, стилізуй за ARIA-атрибутом.
- Переходи короткі (100–300 мс), анімуй `transform` і `opacity`.
- Поважай `prefers-reduced-motion`.
