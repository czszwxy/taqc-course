# Декоратори

Рядки з `@` над функціями ти вже бачив: `@pytest.fixture`, `@dataclass`, а у FastAPI — `@app.get("/orders")`. Це **декоратори** — функції, які приймають функцію і повертають нову, «обгорнуту» версію. Вони додають поведінку (логування, кешування, перевірку прав, повтори, реєстрацію маршрутів) **без змін у самій функції**. У бекенд-фреймворках декоратори всюди, тож треба розуміти, що вони роблять усередині.

> [!NOTE]
> Декоратор спирається на дві речі з модуля «Functions, Modules & Errors»: функція — це значення, яке можна передати й повернути, а вкладена функція пам'ятає змінні зовнішньої (замикання).

## Функція, що повертає обгортку

```python
import time


def timer(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed_ms = (time.perf_counter() - start) * 1000
        print(f"{func.__name__} took {elapsed_ms:.1f} ms")
        return result

    return wrapper
```

- `timer` отримує функцію `func` і повертає **нову** функцію `wrapper`.
- `wrapper(*args, **kwargs)` приймає будь-які аргументи й передає їх оригіналу без змін.
- `return result` — обгортка мусить повернути результат оригіналу, інакше він загубиться.

## Синтаксис @

```python
@timer
def load_orders(user_id):
    ...
```

— це рівно те саме, що:

```python
def load_orders(user_id):
    ...


load_orders = timer(load_orders)
```

## Розбір: що відбувається і коли

| Момент | Що виконується |
|---|---|
| Python виконує `def load_orders` з `@timer` | створює функцію і **одразу** викликає `timer(load_orders)` |
| `timer` повертає `wrapper` | ім'я `load_orders` тепер вказує на `wrapper` |
| код викликає `load_orders(42)` | насправді викликається `wrapper(42)`: `args == (42,)`, `kwargs == {}` |
| усередині `wrapper` | засікає час, викликає справжню `func(42)`, друкує час |
| `wrapper` повертає `result` | виклик отримує те, що повернула б оригінальна функція |

Тіло `timer` виконується **один раз** — коли модуль імпортується. Тіло `wrapper` — **на кожен виклик**.

## functools.wraps: не губити ім'я і документацію

Після декорування `load_orders.__name__` дорівнює `"wrapper"`, а docstring зник. Це ламає логи, документацію API, налагодження і навіть фреймворки, які реєструють функції за іменем. Виправлення — ще один декоратор, `functools.wraps`:

```python
from functools import wraps


def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        ...

    return wrapper
```

`@wraps(func)` копіює в обгортку `__name__`, `__doc__`, `__module__` та інші атрибути і зберігає оригінал у `wrapper.__wrapped__`. Правило просте: **кожна обгортка — з `@wraps`**.

## Декоратор з аргументами

`@repeat(3)` — спершу виконується виклик `repeat(3)`, і вже він повертає справжній декоратор. Звідси три рівні вкладеності:

```python
def repeat(times):                      # 1. приймає налаштування
    def decorator(func):                # 2. приймає функцію
        @wraps(func)
        def wrapper(*args, **kwargs):   # 3. замінює кожен виклик
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result

        return wrapper

    return decorator


@repeat(3)
def ping():
    print("ping")
```

| Рівень | Коли виконується | Що пам'ятає |
|---|---|---|
| `repeat(3)` | один раз, під час визначення | `times` |
| `decorator(ping)` | одразу після нього | `times`, `func` |
| `wrapper()` | на кожен виклик `ping()` | `times`, `func`, аргументи виклику |

## Кілька декораторів

```python
@timer
@repeat(3)
def ping(): ...
```

Застосовуються **знизу вгору**: `ping = timer(repeat(3)(ping))`. А під час виклику першою працює **верхня** обгортка (`timer`); вона викликає нижню, а та — оригінал. Тому `timer` виміряє час усіх трьох повторів разом. Порядок важливий: перевірка прав над кешем і кеш над перевіркою прав — різна поведінка.

## Стан в обгортці

Обгортка — об'єкт, тож їй можна додати атрибут, який житиме між викликами:

```python
import warnings


def deprecated(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        if not wrapper.warned:
            warnings.warn(f"{func.__name__} is deprecated", DeprecationWarning)
            wrapper.warned = True
        return func(*args, **kwargs)

    wrapper.warned = False
    return wrapper
```

Кожна задекорована функція отримує **свою** обгортку — і свій прапорець `warned`.

## Декоратори, які ти зустрінеш

| Декоратор | Що робить | Де |
|---|---|---|
| `@property`, `@classmethod`, `@staticmethod` | особливі методи класу | урок «OOP in depth» |
| `@functools.cache`, `@lru_cache` | кешує результати | урок «collections & functools» |
| `@contextmanager` | менеджер контексту з генератора | наступний урок |
| `@dataclass` | декоратор **класу**: генерує `__init__`, `__eq__` | модуль OOP |
| `@app.get("/orders")` | реєструє функцію як обробник маршруту | FastAPI |
| `@pytest.fixture`, `@pytest.mark...` | реєструє фікстуру, ставить мітку | pytest |

Декоратор не обов'язково обгортає: `@app.get(...)` просто запам'ятовує функцію в таблиці маршрутів і повертає її ж.

## Типові помилки

- Забути `return result` в обгортці — задекорована функція завжди повертає `None`.
- Забути `return wrapper` — після декорування ім'я функції вказує на `None`.
- Обгортка без `@wraps` — `__name__ == "wrapper"`, docstring зник.
- `@repeat` без дужок для декоратора з аргументами — у `times` потрапляє сама функція.
- `@timer()` з дужками для декоратора без аргументів — `TypeError`: бракує аргументу `func`.
- Важка робота в тілі декоратора (а не в `wrapper`) — вона виконається при імпорті модуля.

## Підсумок

- Декоратор — функція, що приймає функцію і повертає заміну; `@d` над `def f` означає `f = d(f)`.
- Тіло декоратора — один раз при визначенні; тіло обгортки — на кожен виклик.
- Обгортка: `*args, **kwargs`, `return func(...)`, `@wraps(func)`.
- Декоратор з аргументами — три рівні: налаштування → функція → виклик.
- Кілька декораторів застосовуються знизу вгору, а при виклику верхня обгортка працює першою.
