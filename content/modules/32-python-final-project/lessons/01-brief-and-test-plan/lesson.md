## Бриф

> **Gadgetly Returns & refunds.** Customers can return items from a delivered order online. They find the order by its number and email, choose items and quantities, a reason, the item condition and how to get the money back. The refund is calculated by the server and shown before the request is sent. After the request the customer gets a return number and can track or cancel the return.

Сторінка: **`/playground/returns`** (Bug Playground → Returns & refunds). Ціни й суми рахує **returns API** — у ньому теж є дефекти.

## Правила (вимоги)

| Правило | Деталі |
|---|---|
| «Сьогодні» | фіксована дата демо — **20 березня 2026**: вікна повернення не «пливуть» від дня запуску тестів |
| Пошук замовлення | номер + email (регістр не важливий); не доставлене замовлення повернути не можна |
| Вікно повернення | **14 днів** після доставки, останній день включно; для причини *Defective* — **30 днів** |
| Кількість | від 1 до купленої кількості; подарункові картки не повертаються |
| Комісія (restocking fee) | **15 %** вартості товарів (вниз до гривні) — лише *Changed my mind* + **Opened** |
| Доставка повернення | **90 UAH** — лише для *Changed my mind*; брак, не той товар, пошкодження — безкоштовно |
| Магазинний кредит | **+10 %** від суми повернення **після** утримань (вниз до гривні) |
| Коментар | до 300 символів; для *Defective* і *Damaged in delivery* — обов'язковий, 10–300 |
| Відстеження | номер повернення + email замовлення; інший email → «Return not found» |

**Сума повернення** = вартість товарів − комісія − доставка повернення (+ бонус, якщо магазинний кредит).

## Розбір: рахуємо суму повернення

Замовлення **#5001** (`anna.koval@example.test`, доставлене 18.03.2026): Wireless Headphones H1 — 2,999 UAH.

| Причина | Стан | Куди | Комісія | Доставка | Бонус | Повернення |
|---|---|---|---|---|---|---|
| Changed my mind | Unopened | картка | 0 | 90 | 0 | **2,909** |
| Changed my mind | Opened | картка | 449 (15 % від 2,999 = 449.85 → 449) | 90 | 0 | **2,460** |
| Changed my mind | Opened | кредит | 449 | 90 | 246 (10 % від 2,460) | **2,706** |
| Defective | Opened | картка | 0 | 0 | 0 | **2,999** |

## Як досліджувати систему

- **UI** — пройди сценарії руками за вимогами з жовтої панелі.
- **Network** у DevTools — кожна зміна на сторінці відправляє `POST /api/returns/quote`; подивись тіло запиту й відповідь.
- **Python** — у лабораторії (`npm run lab:python-setup` уже зроблено) можна відкрити інтерпретатор `lab\.venv\Scripts\python` і робити запити:

```python
import requests

API = "http://localhost:5173/api/returns"
body = {"orderId": 5001, "email": "anna.koval@example.test", "items": [{"lineId": 1, "quantity": 1}],
        "reason": "changed-mind", "condition": "opened", "refundMethod": "original"}
print(requests.post(f"{API}/quote", json=body, timeout=5).json())
```

> [!WARNING]
> Частину дефектів видно **лише через API** — сторінка сама не дає відправити такий запит. Перевіряй сервер окремо: те, що UI щось забороняє, не означає, що це заборонено.

## Тест-план для фреймворку

Тест-план відповідає на питання «що, як, де, чим і коли досить»: обсяг і межі, підхід (що на рівні API, що в UI, що вручну), дані й середовище (фіксована дата, тестові замовлення, прибирання створених повернень), ризики, критерії входу й виходу, результати й графік. Для цієї системи головні ризики — **гроші** (сума повернення) і **межі** (вікна, кількості), тож їх варто покривати насамперед на рівні API: швидко, точно і з усіма комбінаціями.

## Підсумок

- Система: сторінка `/playground/returns` + returns API; «сьогодні» — 20.03.2026.
- Правила: вікно 14 / 30 днів включно, комісія 15 % лише за відкритий товар з причиною *Changed my mind*, доставка 90 UAH лише для неї ж, бонус 10 % після утримань, подарункові картки не повертаються.
- Шість тестових замовлень покривають межі вікна, не доставлене замовлення і неповертаний товар.
- Досліджуй і UI, і API: частина дефектів — лише на сервері.
- Тест-план: ризики — гроші й межі; API-рівень — основа перевірок.
