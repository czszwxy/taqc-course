# STLC: життєвий цикл тестування

Якщо SDLC описує життя продукту, то **STLC (Software Testing Life Cycle)** описує, як організоване саме тестування: від планування до підсумкового звіту. У силабусі ISTQB це називається **test process** — набір активностей тестування.

## Активності процесу тестування (ISTQB)

| Активність | Головне питання | Що робимо | Результат (testware) |
|---|---|---|---|
| **Test planning** | Що, як, коли і ким тестуємо? | визначаємо обсяг, підхід, ресурси, графік, ризики, критерії входу/виходу | тест-план |
| **Test monitoring & control** | Чи йдемо за планом? | порівнюємо прогрес з планом, коригуємо дії | звіти про прогрес |
| **Test analysis** | **Що** тестувати? | аналізуємо вимоги, визначаємо умови тестування (test conditions), шукаємо дефекти у вимогах | список умов тестування, питання до вимог |
| **Test design** | **Як** тестувати? | застосовуємо техніки тест-дизайну, пишемо тест-кейси, визначаємо тестові дані | тест-кейси, чеклісти |
| **Test implementation** | Чи все готове до запуску? | готуємо середовище, тестові дані, збираємо набори тестів, пишемо автотести | тестові набори, дані, готове середовище |
| **Test execution** | Що показують тести? | виконуємо тести, порівнюємо фактичне з очікуваним, реєструємо дефекти | результати, баг-репорти |
| **Test completion** | Що ми дізналися? | підсумовуємо, архівуємо testware, аналізуємо уроки | підсумковий звіт про тестування |

```text
Planning → Analysis → Design → Implementation → Execution → Completion
    ↑__________ Monitoring & control (протягом усього процесу) __________↑
```

> [!NOTE]
> Активності не обов'язково йдуть строго одна за одною. В Agile-команді вони повторюються для кожної історії й накладаються: поки одна задача в execution, для наступної вже йде analysis.

### Інша поширена схема

У багатьох курсах і статтях STLC описують шістьма фазами. Це та сама ідея іншими словами:

| Поширена схема | Відповідає за ISTQB |
|---|---|
| Requirement analysis | test analysis |
| Test planning | test planning |
| Test case development | test design (+ частина implementation) |
| Test environment setup | test implementation |
| Test execution | test execution |
| Test cycle closure | test completion |

## Entry і exit criteria

- **Entry criteria** (критерії входу) — умови, без яких починати активність немає сенсу. Приклад для execution: *білд розгорнуто на тестовому середовищі, smoke-тести пройшли, тест-кейси готові*.
- **Exit criteria** (критерії виходу) — коли можна вважати активність завершеною. Приклад: *виконано 100% запланованих тестів, немає відкритих дефектів severity Critical/Blocker, усі High виправлені або погоджені з PO*.

> [!QA]
> Exit criteria захищають команду від суперечки «а чи можна вже релізити?». Замість відчуттів є домовленість: виконано X, відкритих критичних багів Y, ризики Z.

## Testware

**Testware** — усе, що створюється під час тестування: тест-план, умови тестування, тест-кейси, тестові дані, скрипти автотестів, баг-репорти, звіти. Тестова документація — частина продукту команди: її підтримують, версіонують і переглядають.

## Traceability (трасованість)

Зв'язок між **вимогами ↔ тестами ↔ дефектами**. Дозволяє відповісти на питання:

- які вимоги ще не покриті тестами;
- які тести треба перезапустити, якщо змінилася вимога;
- до якої вимоги відноситься дефект.

## Як це виглядає в реальній Scrum-команді (одна user story)

1. **Analysis** — на рефайнменті читаєш історію, ставиш питання, уточнюєш acceptance criteria.
2. **Design** — пишеш чекліст або тест-кейси, продумуєш тестові дані.
3. **Implementation** — готуєш дані й акаунти, оновлюєш автотести.
4. **Execution** — тестуєш фічу, щойно вона готова; заводиш баги; перевіряєш виправлення.
5. **Completion** — історія відповідає Definition of Done; автотести додано в регресію.

Planning і monitoring відбуваються на рівні спринту чи релізу: Sprint Planning, дейлі, статус багів на дошці.

## Підсумок

- STLC (test process) — планування, моніторинг і контроль, аналіз, дизайн, реалізація, виконання, завершення.
- Analysis відповідає «що тестувати», design — «як», implementation — «чи все готово», execution — «що показали тести».
- Entry/exit criteria визначають, коли починати і коли можна завершувати.
- Testware — усі артефакти тестування; traceability пов'язує вимоги, тести й дефекти.
