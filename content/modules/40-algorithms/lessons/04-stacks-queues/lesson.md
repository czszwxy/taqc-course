# Стеки та черги

Дві найпростіші структури даних, які трапляються всюди. **Стек** — «стопка тарілок»: кладеш зверху і береш зверху (LIFO — last in, first out). **Черга** — «черга в касу»: стаєш у кінець, обслуговують з початку (FIFO — first in, first out).

## Стек на списку

```python
stack = []
stack.append("open orders page")    # покласти — O(1)
stack.append("open order #1002")
stack[-1]                           # подивитися верхній — 'open order #1002'
stack.pop()                         # зняти верхній — O(1)
if stack:                           # перед pop перевіряй, чи не порожній
    stack.pop()
```

`pop()` з порожнього списку — `IndexError: pop from empty list`.

## Черга на deque

```python
from collections import deque

queue = deque()
queue.append("send email #1")       # у кінець — O(1)
queue.append("send email #2")
queue.popleft()                     # з початку — O(1): 'send email #1'
```

Список як черга (`pop(0)`) працює, але зсуває всі елементи — `O(n)` на кожну операцію (урок про Big-O).

## Де вони в бекенді

| Структура | Приклади |
|---|---|
| Стек | стек викликів функцій (і traceback — це він); undo / redo; перевірка вкладеності дужок, тегів, JSON; кнопка «назад» у браузері; обхід дерева в глибину без рекурсії |
| Черга | черги фонових задач (Celery, RQ); обробка запитів по черзі; обхід графа в ширину (BFS); буфер повідомлень |

## Розбір: перевірка дужок стеком

Рядок `f(a[1], {b: 2})`: кожна відкривна дужка — на стек, кожна закривна має відповідати **верхній**.

| Символ | Дія | Стек після |
|---|---|---|
| `f` | не дужка — пропустити | `[]` |
| `(` | покласти | `['(']` |
| `a` | пропустити | `['(']` |
| `[` | покласти | `['(', '[']` |
| `1` | пропустити | `['(', '[']` |
| `]` | верхній `[` — пара, зняти | `['(']` |
| `,` та пробіл | пропустити | `['(']` |
| `{` | покласти | `['(', '{']` |
| `b: 2` | пропустити | `['(', '{']` |
| `}` | верхній `{` — пара, зняти | `['(']` |
| `)` | верхній `(` — пара, зняти | `[]` |
| кінець | стек порожній → **збалансовано** | |

Три способи провалитися: закривна дужка при порожньому стеку (`)(`), закривна не тієї форми (`(]`), і непорожній стек у кінці (`((`). Саме стек, а не лічильник, потрібен через різні види дужок: `[(])` має правильну кількість, але неправильну вкладеність.

## Undo як стек станів

Редактор зберігає кожен попередній стан на стеку `undo`. «Скасувати» — зняти верхній стан і повернутися до нього, а поточний покласти на стек `redo`. Будь-яка **нова** зміна очищує `redo` — гілка «майбутнього» більше не існує. Так працюють і текстові редактори, і «скасувати останню дію» в адмінках.

## Черга «по колу»

Планувальник дає кожній задачі квант часу; незавершена задача стає в кінець черги. Ніхто не чекає вічно, і короткі задачі закінчуються раніше. З `deque` кожен крок — `popleft()` і, можливо, `append()`, обидва `O(1)`.

## Типові помилки

- `pop()` з порожнього стека — `IndexError`; перевіряй `if stack:`.
- Перевірка дужок лічильником — не ловить `[(])`.
- Забути перевірити, що стек порожній **у кінці** — `((` вважається правильним.
- Черга на списку з `pop(0)` на великих обсягах.
- Не очищати `redo` після нової зміни — «повернути» можна стан, якого вже не мало б бути.

## Підсумок

- Стек — LIFO: `append` / `pop` / `[-1]` на списку, усе `O(1)`.
- Черга — FIFO: `append` / `popleft` на `deque`, обидва `O(1)`.
- Стек — для вкладеності, undo / redo, обходу в глибину; черга — для задач по черзі й обходу в ширину.
- У задачах зі стеком перевіряй порожній стек і на кожному кроці, і в кінці.
