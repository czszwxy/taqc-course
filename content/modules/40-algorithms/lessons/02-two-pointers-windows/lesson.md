# Два вказівники та ковзне вікно

Багато задач про списки й рядки «в лоб» розв'язуються циклом у циклі: перебрати всі пари, усі відрізки. Дві прості техніки роблять те саме за **один прохід** — `O(n)` замість `O(n²)`. Обидві постійно трапляються на співбесідах, а в бекенді — в аналітиці (піки навантаження за годину, ковзні середні) і в обробці потоків даних.

## Два вказівники

Ідея: два індекси, які рухаються по списку назустріч один одному (або в один бік), і кожен крок відкидає частину варіантів.

```python
def is_palindrome(text):
    left, right = 0, len(text) - 1
    while left < right:
        if text[left] != text[right]:
            return False
        left += 1
        right -= 1
    return True
```

Найсильніше техніка працює на **відсортованих** даних: якщо сума двох крайніх елементів замала, лівий вказівник іде праворуч (сума зросте); якщо завелика — правий іде ліворуч (сума зменшиться).

## Розбір: пара на суму 1300 у відсортованому списку

`prices = [200, 450, 600, 850, 1100]`, шукаємо дві ціни з сумою `1300`:

| Крок | left → ціна | right → ціна | Сума | Дія |
|---|---|---|---|---|
| 1 | 0 → 200 | 4 → 1100 | 1300 | знайдено |

Інший бюджет, `1050`:

| Крок | left → ціна | right → ціна | Сума | Дія |
|---|---|---|---|---|
| 1 | 0 → 200 | 4 → 1100 | 1300 | завелика → `right -= 1` |
| 2 | 0 → 200 | 3 → 850 | 1050 | знайдено: 200 + 850 |

Чому нічого не загубили: коли сума завелика, найбільша ціна не підходить **ні до якої** з решти (вони лише більші за поточну ліву), тож її можна відкинути. Кожен крок відкидає один елемент — максимум `n` кроків.

## Ковзне вікно фіксованого розміру

Задача: замовлення по годинах, знайти 3 години поспіль з найбільшою кількістю замовлень. «В лоб» — сума кожного вікна заново (`k` кроків на вікно). Розумніше — **зсувати** вікно: додати новий елемент справа, відняти той, що вийшов зліва.

```python
def max_window_sum(values, k):
    window = sum(values[:k])
    best = window
    for end in range(k, len(values)):
        window += values[end] - values[end - k]
        best = max(best, window)
    return best
```

| Вікно | Як отримали суму | Сума для `[4, 2, 7, 1, 8]`, k = 3 |
|---|---|---|
| `[4, 2, 7]` | `sum` перших трьох | 13 |
| `[2, 7, 1]` | `13 + 1 − 4` | 10 |
| `[7, 1, 8]` | `10 + 8 − 2` | 16 |

Кожен елемент додається і віднімається один раз — `O(n)` замість `O(n · k)`.

## Ковзне вікно змінного розміру

Коли розмір вікна не відомий наперед («найдовший відрізок, де…»), праву межу рухають завжди, а ліву — лише коли умова порушилась. Класика: найдовший фрагмент рядка без повторюваних символів. Права межа додає символ; якщо він уже є у вікні — ліва межа перестрибує за його попередню позицію. Важливий нюанс: ліва межа ніколи **не рухається назад** — повтор, що лишився лівіше вікна, вже не має значення.

## Коли яка техніка

| Ознака задачі | Техніка |
|---|---|
| відсортовані дані, пара / трійка з умовою на суму | два вказівники з двох кінців |
| перевірка «з обох кінців» (паліндром) | два вказівники назустріч |
| «k елементів поспіль», ковзне середнє | вікно фіксованого розміру |
| «найдовший / найкоротший відрізок, де…» | вікно змінного розміру |

## Типові помилки

- Два вказівники на **невідсортованих** даних — алгоритм пропускає відповіді.
- `left <= right` замість `left < right` — елемент «утворює пару сам із собою».
- Перераховувати суму вікна через `sum(values[i:i + k])` — знову `O(n · k)`.
- Помилки на межах: вікно довше за список, `k = 0`, порожній вхід.
- У вікні змінного розміру ліва межа стрибає назад — неправильна довжина.

## Підсумок

- Два вказівники на відсортованих даних відкидають один елемент за крок — `O(n)`.
- Ковзне вікно оновлює результат за `O(1)` на крок: додати новий, відняти старий.
- Вікно змінного розміру: права межа йде завжди, ліва — коли умова порушилась, і ніколи назад.
- Перевіряй межі: порожній вхід, один елемент, `k` більше за довжину.
