# Big-O: наскільки швидкий твій код?

На тестових даних з десяти замовлень працює будь-який код. У продакшні замовлень мільйон, і функція, що «трохи повільна», стає хвилинним запитом, тайм-аутом і падінням сервісу. **Складність алгоритму** відповідає на питання: як зростає час (або пам'ять), коли зростає кількість даних `n`. Записують її через **Big-O**. Це обов'язкова тема на співбесідах, але важливіше інше: вона вчить помічати повільний код ще до того, як він потрапить у продакшн.

## Рахуємо кроки, а не секунди

Секунди залежать від комп'ютера. Тому рахують **кількість базових кроків** залежно від `n` і залишають лише те, що росте найшвидше:

| Кроків | Big-O | Чому так |
|---|---|---|
| `3n + 5` | `O(n)` | константи й доданки, що ростуть повільніше, відкидають |
| `n² / 2 + n` | `O(n²)` | головне — квадрат |
| `100` (не залежить від `n`) | `O(1)` | «константний час» |

## Класи складності на числах

| Big-O | Назва | n = 1 000 | n = 1 000 000 | Приклад |
|---|---|---|---|---|
| `O(1)` | константна | 1 | 1 | `user_by_id[42]` |
| `O(log n)` | логарифмічна | ~10 | ~20 | бінарний пошук |
| `O(n)` | лінійна | 1 000 | 1 000 000 | один прохід по списку |
| `O(n log n)` | «лінійно-логарифмічна» | ~10 000 | ~20 000 000 | `sorted(...)` |
| `O(n²)` | квадратична | 1 000 000 | 1 000 000 000 000 | цикл у циклі |

Різниця між `O(n)` і `O(n²)` на мільйоні записів — секунда проти тижнів.

## Вкладені цикли

```python
for order in orders:              # n разів
    for item in order["items"]:   # m разів для кожного замовлення
        ...                       # усього n · m кроків
```

Якщо обидва цикли йдуть по тих самих `n` елементах — це `O(n²)`. Та сама пастка ховається в «невинному» коді: `if email in emails_list` усередині циклу — це теж цикл у циклі, бо `in` для списку перебирає його.

## Скільки коштують операції Python

| Операція | Складність |
|---|---|
| `items[i]`, `len(items)`, `items.append(x)`, `items.pop()` | `O(1)` |
| `x in items` (список), `items.index(x)`, `items.count(x)` | `O(n)` |
| `items.insert(0, x)`, `items.pop(0)` | `O(n)` — зсуваються всі елементи |
| `x in some_set`, `some_dict[key]`, `some_dict.get(key)` | `O(1)` у середньому |
| `items[a:b]` — зріз | `O(b - a)` — копіювання |
| `sorted(items)`, `items.sort()` | `O(n log n)` |
| `text += piece` у циклі | до `O(n²)` сумарно — краще `"".join(pieces)` |

## Розбір: «чи є повтор?» двома способами

```python
def has_repeat_slow(emails):
    for i in range(len(emails)):
        for j in range(i + 1, len(emails)):
            if emails[i] == emails[j]:
                return True
    return False


def has_repeat_fast(emails):
    seen = set()
    for email in emails:
        if email in seen:
            return True
        seen.add(email)
    return False
```

| n | Порівнянь у `has_repeat_slow` (без повторів) | Перевірок у `has_repeat_fast` |
|---|---|---|
| 10 | 45 | 10 |
| 1 000 | 499 500 | 1 000 |
| 100 000 | ~5 000 000 000 | 100 000 |

Обидві функції правильні. Але друга лінійна, бо перевірка `in` для множини — `O(1)`. Платимо за це пам'яттю: множина `seen` займає до `n` елементів. Це типовий обмін «пам'ять за швидкість».

## Пам'ять

Пам'ять оцінюють так само: скільки **додаткових** даних створює алгоритм. `has_repeat_slow` — `O(1)` пам'яті, `has_repeat_fast` — `O(n)`. Зазвичай пам'ять дешевша за час, але не завжди: «завантажити мільйон рядків у список, щоб порахувати кількість» — погана ідея, коли можна рахувати по одному.

## Як тести в цьому модулі перевіряють швидкість

Секунди на телефоні й на ноутбуці різні, тому тести **рахують операції**: передають у функцію список, що рахує прочитані елементи, або об'єкти, що рахують порівняння. Правильна відповідь з квадратичною кількістю операцій не пройде — як на співбесіді, де питають «а яка складність?».

## Типові помилки

- `in` для списку всередині циклу — прихований `O(n²)`.
- `list.pop(0)` у циклі — краще `collections.deque.popleft()`.
- Складати рядок через `+=` у великому циклі — краще список і `"".join(...)`.
- Сортувати весь список, щоб знайти мінімум, — `min(...)` дає `O(n)` замість `O(n log n)`.
- Плутати «працює швидко на моїх 10 записах» зі «швидкий алгоритм».

## Підсумок

- Big-O описує, як росте кількість кроків зі зростанням `n`; константи відкидають.
- `O(1) < O(log n) < O(n) < O(n log n) < O(n²)` — різниця величезна на великих даних.
- Цикл у циклі по тих самих даних — `O(n²)`; `in` для списку — теж цикл.
- `set` і `dict` дають пошук за `O(1)` в середньому ціною пам'яті.
- Тести модуля рахують операції: важлива не лише відповідь, а й шлях до неї.
