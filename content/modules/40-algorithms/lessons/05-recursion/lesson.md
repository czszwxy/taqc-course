# Рекурсія

Деякі дані мають форму «таке саме всередині такого самого»: коментар з відповідями, кожна з яких — коментар з відповідями; папка з папками; JSON з вкладеними об'єктами; категорії товарів з підкатегоріями. Для такої форми найприродніше рішення — **рекурсія**: функція, що викликає сама себе для вкладеної частини.

## Два обов'язкові елементи

| Елемент | Що це | Без нього |
|---|---|---|
| **Базовий випадок** | ситуація, де відповідь відома одразу, без нового виклику | нескінченні виклики → `RecursionError` |
| **Рекурсивний крок** | виклик для **меншої** частини задачі + поєднання результатів | функція нічого не розв'язує |

```python
def max_depth(comment):
    """How deep is a comment thread? A comment without replies has depth 1."""
    replies = comment["replies"]
    if not replies:                                   # базовий випадок
        return 1
    return 1 + max(max_depth(reply) for reply in replies)   # рекурсивний крок
```

## Розбір: стек викликів

```python
thread = {"text": "Great!", "replies": [
    {"text": "Agree", "replies": [{"text": "+1", "replies": []}]},
    {"text": "Why?", "replies": []},
]}
max_depth(thread)
```

| Крок | Виклик | Що відбувається | Стек (зверху — поточний) |
|---|---|---|---|
| 1 | `max_depth(Great!)` | є відповіді → викликає для `Agree` і чекає | Great! |
| 2 | `max_depth(Agree)` | є відповідь → викликає для `+1` і чекає | Agree → Great! |
| 3 | `max_depth(+1)` | відповідей немає → **повертає 1** | +1 → Agree → Great! |
| 4 | `max_depth(Agree)` | отримала 1 → повертає `1 + 1 = 2` | Agree → Great! |
| 5 | `max_depth(Why?)` | відповідей немає → повертає 1 | Why? → Great! |
| 6 | `max_depth(Great!)` | `max(2, 1) = 2` → повертає `1 + 2 = 3` | Great! |

Кожен виклик чекає на результати вкладених і лише потім завершується — це і є **стек викликів**. Traceback помилки показує саме його.

## Ліміт глибини

Кожен виклик займає місце в стеку. Python обмежує глибину (`sys.getrecursionlimit()`, зазвичай 1000) і кидає `RecursionError: maximum recursion depth exceeded` — частіше через забутий базовий випадок, ніж через справді глибокі дані. Якщо дані можуть мати тисячі рівнів вкладеності (наприклад, ланцюжок, а не дерево), рекурсію замінюють циклом з **власним стеком** (список, урок «Stacks and queues»).

## Рекурсія для вкладених даних

Типовий шаблон для JSON-подібних даних — перевірити тип і зайти всередину:

```python
def walk(data):
    if isinstance(data, dict):
        for value in data.values():
            walk(value)
    elif isinstance(data, list):
        for item in data:
            walk(item)
    else:
        ...   # «лист»: число, рядок, None — базовий випадок
```

Результати повертають наверх: або як значення (`return 1 + ...`, `sum(...)`), або збираючи в список (`result.extend(walk(item))`).

## Рекурсія чи цикл

| Ситуація | Що обрати |
|---|---|
| дерева, вкладені структури невідомої глибини | рекурсія — код повторює форму даних |
| простий перебір списку, лічильник | цикл |
| дуже глибокі ланцюжки (тисячі рівнів) | цикл з власним стеком |
| ті самі підзадачі рахуються багато разів | рекурсія + кеш (урок про динамічне програмування) |

## Типові помилки

- Немає базового випадку або він не досягається (рекурсивний виклик не зменшує задачу).
- Забутий `return` перед рекурсивним викликом — результат губиться, функція повертає `None`.
- Рядок — теж послідовність: перевірка «чи можна обійти» (`iter(...)`) зайде в рядок і розібʼє його на символи; перевіряй конкретні типи (`list`, `dict`).
- Змінюваний аргумент за замовчуванням для накопичення (`def f(data, result=[])`) — список спільний між викликами.

## Підсумок

- Рекурсія = базовий випадок + рекурсивний крок для меншої частини.
- Кожен виклик чекає вкладені — так будується стек викликів.
- Ліміт глибини ~1000; для дуже глибоких даних — цикл з власним стеком.
- Для вкладених даних перевіряй тип (`dict`, `list`) і заходь усередину; результати повертай наверх.
