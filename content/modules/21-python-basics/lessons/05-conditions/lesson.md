# Умови

Умови — це правила продукту в коді: «якщо сума від 10 000 — доставка безкоштовна», «якщо статус 401 — показати форму входу». Тестувальник, який читає умови, одразу бачить, де межі і які гілки треба перевірити.

## if / elif / else

```python
def response_time_label(ms):
    if ms < 300:
        return "fast"
    elif ms < 1000:
        return "acceptable"
    else:
        return "slow"
```

- після умови — двокрапка `:`, тіло — з відступом;
- `elif` («else if») перевіряється, лише якщо попередні умови були хибні;
- `else` спрацьовує, коли не підійшла жодна умова;
- Python перевіряє умови **згори донизу** і виконує **першу** істинну гілку.

> [!WARNING]
> Порядок має значення. Якщо першою поставити `if ms < 1000:`, то 100 мс теж стане «acceptable» — гілка «fast» ніколи не виконається. Від вузьких умов — до широких.

## Truthy і falsy

У `if` можна писати не лише `True`/`False`, а будь-яке значення. **Хибними** (falsy) вважаються: `False`, `None`, `0`, `0.0`, `""` (порожній рядок), порожні колекції `[]`, `{}`. Усе інше — **істинне** (truthy).

```python
name = ""
if not name:
    print("Name is required")     # спрацює: порожній рядок — falsy

if name.strip():                  # рядок лише з пробілів після strip() стає порожнім
    print("Name is filled")
```

> [!QA]
> «Поле лише з пробілів» — класичний баг валідації: `"   "` — truthy, тому `if name:` пропускає його. Правильна перевірка — `if not name.strip():`.

## Порівняння з None

```python
if result is None:
    print("no result")
```

Для `None` прийнято писати `is None` / `is not None`, а не `== None`.

## Оператор in

```python
method = "courier"
if method in ("pickup", "post", "courier"):
    print("known delivery method")
```

`in` перевіряє, чи є значення в наборі — читається краще, ніж три `or`.

## Складені умови

```python
if age >= 18 and country == "UA":
    ...
if role == "admin" or role == "owner":
    ...
if not (is_blocked or is_deleted):
    ...
```

Коли умова довга — винеси частини у змінні з промовистими назвами: `is_adult = age >= 18`. Так її легше читати і перевіряти.

## Ранній return

Замість глибокої вкладеності функція може повернути результат одразу, щойно все ясно:

```python
def discount_percent(subtotal, is_member):
    if subtotal <= 0:
        return 0
    if is_member:
        return 10
    if subtotal >= 5000:
        return 5
    return 0
```

Після `return` функція завершується, тож наступні `if` не потребують `elif`.

## Розбір: таблиця тестів для умови

Тестувальник проходить по кожній гілці і по кожній межі. Для `discount_percent`:

| `subtotal` | `is_member` | Яка гілка спрацює | Очікування |
|---|---|---|---|
| `0` | `True` | `subtotal <= 0` | `0` — навіть для члена клубу |
| `100` | `True` | `is_member` | `10` |
| `5000` | `False` | `subtotal >= 5000` — межа | `5` |
| `4999` | `False` | жодна з умов | `0` — на 1 менше за межу |

Чотири рядки — чотири тести, і кожен перевіряє окремий шлях у коді. Зверни увагу на пару `5000` / `4999`: якщо розробник написав `>` замість `>=`, впаде саме тест з `5000`.

## Тернарний вираз

Для простого вибору з двох значень є коротка форма:

```python
label = "free" if fee == 0 else f"{fee} UAH"
```

Не вкладай їх одне в одне — для складної логіки краще звичайний `if`.

## Типові помилки

- `if status == "passed" or "skipped":` — **завжди** `True`! Друга частина — просто рядок `"skipped"`, а він truthy. Правильно: `status == "passed" or status == "skipped"` або `status in ("passed", "skipped")`.
- `if code = 200:` — `SyntaxError`: в умові потрібне `==`.
- Одна з гілок без `return` — функція поверне `None` саме для цього випадку.
- Перевірка `>` замість `>=` на межі — найчастіший баг, який ловлять граничні значення.

## Підсумок

- `if` / `elif` / `else`: перевірка згори донизу, виконується перша істинна гілка.
- Порядок умов — від вузьких до широких; межі — через `<=` / `>=`.
- Falsy: `False`, `None`, `0`, `""`, порожні колекції; рядок з пробілами — truthy.
- `is None`, `in (...)`, ранній `return`; кожна гілка і кожна межа — тест-кейс.
- `x == "a" or "b"` — пастка: порівнюй кожне значення окремо або через `in`.
