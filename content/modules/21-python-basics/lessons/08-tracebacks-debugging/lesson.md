# Як читати traceback і налагоджувати код

Помилки — нормальна частина роботи. Різниця між новачком і досвідченим інженером не в кількості помилок, а в тому, як швидко він їх **читає** і знаходить причину. Для QA Automation це подвійно важливо: падіння автотесту — це traceback, який треба зрозуміти за хвилину.

## Анатомія traceback

```text
Traceback (most recent call last):
  File "test_cart.py", line 12, in test_total
    assert cart_total(items) == 5570
  File "cart.py", line 5, in cart_total
    total += item["price"] * item["qty"]
KeyError: 'qty'
```

Читай **знизу вгору**:

1. **Останній рядок** — тип помилки і повідомлення: `KeyError: 'qty'` — у словнику немає ключа `qty`.
2. **Рядок над ним** — де саме сталося: файл `cart.py`, рядок 5, і сам код.
3. **Вище** — хто викликав цю функцію (тест `test_total`). Це шлях від тесту до місця збою.

## Найчастіші помилки

| Помилка | Що означає | Типова причина |
|---|---|---|
| `SyntaxError` | код не відповідає синтаксису | забута `:`, дужка, лапка |
| `IndentationError` | зламані відступи | тіло функції без відступу |
| `NameError` | ім'я не визначене | одруківка у назві змінної, змінна до присвоєння |
| `TypeError` | операція з невідповідним типом | `"Total: " + 5570`, зайвий/відсутній аргумент |
| `ValueError` | тип правильний, значення ні | `int("abc")` |
| `IndexError` | індекс поза списком | `items[5]` у списку з 3 елементів |
| `KeyError` | ключа немає у словнику | `user["phone"]`, коли телефону немає |
| `ZeroDivisionError` | ділення на нуль | середнє для порожнього списку |
| `AttributeError` | у значення немає такого атрибута/методу | `None.strip()`, одруківка в назві методу |

> [!TIP]
> Скопіюй останній рядок помилки в пошук — для стандартних помилок Python ти майже завжди знайдеш пояснення на перших посиланнях.

## Як налагоджувати

1. **Відтвори** помилку стабільно — тест або Run.
2. **Прочитай** traceback знизу вгору: тип, файл, рядок.
3. **Подивись на значення**: додай `print(repr(variable))` перед рядком з помилкою. `repr` покаже лапки і приховані символи.
4. **Звузь проблему**: прибери все зайве, доки не залишиться мінімальний приклад.
5. **Виправ одну річ** і перевір знову — не змінюй п'ять місць одночасно.

> [!NOTE]
> На своєму комп'ютері зручно використовувати **дебагер** VS Code: точка зупинки (breakpoint) на рядку, запуск у режимі Debug — і можна дивитися значення всіх змінних та виконувати код крок за кроком.

## Логічні помилки

Найпідступніші помилки — без traceback: код працює, але результат неправильний (`>` замість `>=`, `=+` замість `+=`, одруківка в рядку `"skiped"`). Їх ловлять **тести** — тому тестувальник і пише їх для кожної межі й гілки.

> [!QA]
> Коли автотест падає, спершу визнач: це **баг у продукті** чи **помилка в самому тесті** (зламаний локатор, неправильні дані, одруківка)? Traceback підказує: якщо падіння в коді тесту чи хелпера — дивись туди першим.

## Підсумок

- Traceback читаємо знизу вгору: тип і повідомлення → файл і рядок → хто викликав.
- Запам'ятай 9 типових помилок і їхні причини.
- Налагодження: відтворити → прочитати → подивитися значення (`print(repr(x))`) → звузити → виправити одну річ.
- Логічні помилки не дають traceback — їх ловлять тести на межах і гілках.
