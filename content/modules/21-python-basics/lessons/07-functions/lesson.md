# Функції

Функція — це іменований шматок коду, який приймає дані (параметри) і повертає результат. В автотестах функції всюди: хелпер логіну, побудова URL, підготовка тестових даних. Тести pytest — це теж функції.

## Оголошення і виклик

```python
def full_name(first, last):
    """Return the full name for reports."""
    return first + " " + last

print(full_name("Olena", "Tester"))     # Olena Tester
```

- `first`, `last` — **параметри** (імена в оголошенні);
- `"Olena"`, `"Tester"` — **аргументи** (значення при виклику);
- рядок у потрійних лапках одразу після `def` — **docstring**, опис функції.

Оголошення `def` лише **створює** функцію — її код виконається, коли функцію викличуть.

## Що відбувається під час виклику

Розберемо крок за кроком рядок `total = add_vat(1000)`:

```python
def add_vat(price):
    vat = price * 20 // 100
    return price + vat

total = add_vat(1000)
print(total)
```

1. Python бачить виклик `add_vat(1000)` і переходить у тіло функції.
2. Параметр отримує значення аргументу: `price = 1000`.
3. Виконується тіло: `vat = 200`.
4. `return price + vat` обчислює `1200`, **завершує** функцію і повертає значення туди, звідки її викликали.
5. Повернене значення присвоюється: `total = 1200`. Друкується `1200`.

## return

`return` повертає значення і **завершує** функцію. Без `return` функція повертає `None`.

```python
def double(x):
    print(x * 2)        # лише показує

result = double(5)      # друкує 10
print(result)           # None
```

> [!IMPORTANT]
> Тест перевіряє `return`, а не `print`. Функція, що друкує, але нічого не повертає, — найчастіша причина «тест падає, хоча на екрані все правильно».

## Локальні змінні

Змінні, створені всередині функції (і її параметри), — **локальні**: вони існують лише під час виклику і не видні ззовні.

```python
def add_vat(price):
    vat = price * 20 // 100
    return price + vat

add_vat(1000)
print(vat)       # NameError: name 'vat' is not defined
```

Щоб отримати значення з функції, його треба **повернути** через `return` і зберегти в змінну там, де функцію викликали.

## Значення за замовчуванням

```python
def build_url(base, path, page=1):
    return f"{base}/{path}?page={page}"

build_url("https://shop.test", "products")           # page=1
build_url("https://shop.test", "products", 3)        # page=3
```

Параметри зі значенням за замовчуванням ідуть **після** обов'язкових.

## Іменовані аргументи

```python
build_url("https://shop.test", "products", page=2)
build_url(path="orders", base="https://shop.test")     # порядок не важливий
```

Іменовані аргументи роблять виклики зрозумілими: `create_user(name="Olena", admin=False)` читається краще, ніж `create_user("Olena", False)`.

## Кілька значень

Функція може повернути кілька значень — насправді це **tuple** (кортеж):

```python
def passed_failed(results):
    passed = results.count("passed")
    return passed, len(results) - passed

ok, bad = passed_failed(["passed", "failed", "passed"])   # 2, 1
```

## Функції викликають функції

Велику задачу розбивають на маленькі функції, кожна з яких робить **одну** річ:

```python
def is_valid_email(email):
    return "@" in email and "." in email

def signup_error(email, password):
    if not is_valid_email(email):
        return "Invalid email"
    if len(password) < 8:
        return "Password is too short"
    return ""
```

`signup_error` використовує `is_valid_email` — і кожну з них можна перевірити окремо. Якщо правило для email зміниться, правка буде в одному місці.

## Швидка перевірка: assert

`assert` перевіряє, що вираз істинний, і падає з `AssertionError`, якщо ні. Так виглядають і приховані тести в задачах, і тести pytest:

```python
assert add_vat(1000) == 1200
assert signup_error("qa@example.test", "12345678") == ""
assert signup_error("qa", "12345678") == "Invalid email"
```

Можеш дописати кілька таких рядків під своєю функцією і натиснути **Run** — тиша означає, що все гаразд.

## Чисті функції

**Чиста функція** залежить лише від своїх параметрів і нічого не змінює навколо (не друкує, не пише у файли, не змінює глобальні змінні). Такі функції найлегше тестувати: однакові аргументи — однаковий результат.

> [!QA]
> Коли пишеш хелпери для автотестів, роби їх чистими там, де можна: `build_url`, `format_price`, `expected_total` — і їх можна перевірити окремими маленькими тестами.

## Типові помилки

- **Забутий `return`** — функція повертає `None`.
- **`return` усередині циклу завчасно** — функція виходить на першій ітерації (дивись урок про цикли).
- **Виклик без дужок:** `print(full_name)` надрукує `<function full_name at 0x...>`, а не результат. Потрібно `full_name("Olena", "Tester")`.
- **Аргументи не в тому порядку:** `build_url("products", "https://shop.test")` — помилки немає, але URL неправильний. Іменовані аргументи захищають від цього.
- **Виклик до оголошення:** якщо рядок з викликом стоїть вище за `def`, буде `NameError`.

## Підсумок

- `def name(params):` + тіло з відступом + `return`; docstring описує функцію.
- Виклик: аргументи → параметри → тіло → `return` повертає значення туди, де функцію викликали.
- Змінні всередині функції локальні; щоб «винести» значення — `return`.
- Значення за замовчуванням — після обов'язкових параметрів; іменовані аргументи — для читабельності.
- Велику задачу розбивай на маленькі функції; перевіряй їх через `assert`.
