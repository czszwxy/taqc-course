# Форми

Реєстрація, вхід, пошук, оформлення замовлення — усе це форми. Від того, як вони розмічені, залежить, чи дійде людина до кнопки «Оформити». Хороша форма підказує браузеру, яку клавіатуру показати на телефоні, що підставити з автозаповнення і як перевірити введене, — і все це **без жодного рядка JavaScript**.

## Форма і її відправка

Форма запису на лекцію в бібліотеці:

```html
<form action="/lectures/signup" method="post">
  <p>
    <label for="reader-name">Ім'я</label>
    <input id="reader-name" name="name" type="text" autocomplete="name" required>
  </p>
  <p>
    <label for="reader-email">Email</label>
    <input id="reader-email" name="email" type="email" autocomplete="email" required>
  </p>
  <button type="submit">Записатися</button>
</form>
```

- `action` — **куди** відправити дані, `method` — **як**.
- `method="get"` — дані йдуть в адресу: `/search?q=борщ`. Для пошуку й фільтрів: таку адресу можна зберегти й надіслати.
- `method="post"` — дані йдуть у тілі запиту. Для всього, що створює чи змінює дані, і для паролів (вони не мають потрапити в адресу та історію браузера).
- `name` — **ключ**, під яким значення поля піде на сервер: `name=Олена&email=…`. Поле без `name` не відправляється взагалі.

## label — підпис, який працює

```html
<label for="reader-email">Email</label>           <!-- явний: for = id поля -->
<input id="reader-email" name="email" type="email">

<label>                                           <!-- неявний: поле всередині label -->
  <input type="checkbox" name="news"> Хочу отримувати анонси
</label>
```

Що дає `<label>`:

- екранний читач у полі каже «Email, поле редагування», а не просто «поле редагування»;
- клік по підпису ставить курсор у поле, а для чекбокса — перемикає його: ціль для пальця стає більшою.

> [!WARNING]
> `placeholder` — **не підпис**. Він зникає, щойно людина почне писати (і вона забуває, що це було за поле), зазвичай блідий і погано читається, а частина екранних читачів його не озвучує. Placeholder — лише приклад формату: `placeholder="name@example.com"`.

## Типи полів

`type` змінює і перевірку, і **клавіатуру на телефоні**:

| type | Для чого | Що дає |
|---|---|---|
| `text` | звичайний текст | — |
| `email` | email | клавіатура з `@`, перевірка формату |
| `tel` | телефон | цифрова клавіатура (формат не перевіряється — номери в різних країнах різні) |
| `password` | пароль | символи приховано |
| `number` | **кількість**, вік | стрілки ±, лише числа |
| `date` | дата | вбудований календар |
| `checkbox` | так / ні, кілька варіантів | — |
| `radio` | один варіант із кількох | — |
| `search`, `url` | пошук, адреса сайту | своя клавіатура |

> [!TIP]
> `type="number"` — не для номерів, а для **кількостей**. Номер картки, поштовий індекс, код із SMS — це `type="text"` з `inputmode="numeric"`: цифрова клавіатура без стрілок ±, а індекс `01001` не втратить нуль на початку.

## autocomplete — автозаповнення

`autocomplete` підказує браузеру й менеджеру паролів, **що** це за поле:

| Значення | Поле |
|---|---|
| `name`, `email`, `tel` | ім'я, email, телефон |
| `street-address`, `address-level2`, `postal-code` | адреса, місто, індекс |
| `username`, `current-password` | логін і пароль на сторінці **входу** |
| `new-password` | новий пароль: реєстрація, зміна пароля — менеджер запропонує згенерувати надійний |
| `one-time-code` | код із SMS: телефон підставить його сам |
| `cc-number`, `cc-exp`, `cc-csc` | номер картки, термін дії, CVC |

Для людей з порушеннями моторики чи пам'яті автозаповнення — не зручність, а можливість узагалі заповнити форму (вимога WCAG 1.3.5).

## Перевірка, яку робить браузер

```html
<input name="code" type="text" inputmode="numeric" required
       minlength="6" maxlength="6" pattern="[0-9]{6}" title="6 цифр з SMS">
```

| Атрибут | Перевіряє |
|---|---|
| `required` | поле не порожнє (для чекбокса — позначений) |
| `minlength` / `maxlength` | довжину тексту (`maxlength` просто не дасть ввести більше) |
| `min` / `max` / `step` | межі числа чи дати |
| `pattern` | відповідність регулярному виразу; пояснення формату — у видимому тексті поруч |
| `type="email"` / `"url"` | формат |

Під час відправки браузер зупиняє форму на першому неправильному полі й показує повідомлення. `<form novalidate>` вимикає ці перевірки — так роблять, коли перевірку показує JavaScript.

> [!IMPORTANT]
> Перевірка в браузері — лише **зручність**. Атрибут можна прибрати в DevTools, а запит — надіслати взагалі без форми. Сервер **завжди** перевіряє дані сам.

## Групи, списки, великі поля

```html
<fieldset>
  <legend>Формат лекції</legend>
  <label><input type="radio" name="format" value="hall" checked> У залі</label>
  <label><input type="radio" name="format" value="online"> Онлайн</label>
</fieldset>

<label for="topic">Тема</label>
<select id="topic" name="topic" required>
  <option value="">Оберіть тему</option>
  <option value="history">Історія Києва</option>
  <option value="poetry">Сучасна поезія</option>
</select>

<label for="question">Питання лектору</label>
<textarea id="question" name="question" rows="4" maxlength="500"></textarea>
```

- **Радіокнопки** однієї групи мають **однаковий `name`** — тоді вибрати можна лише одну. Групу обгортають у `<fieldset>`, а її питання — у `<legend>`: читач скаже «Формат лекції, група; У залі, перемикач, вибрано».
- `<select>` з першим `<option value="">` і `required` змушує зробити вибір: порожнє значення не пройде перевірку.
- `<textarea>` — багаторядковий текст; `rows` — висота, `maxlength` — обмеження.

## Кнопки

| Запис | Що робить |
|---|---|
| `<button>` **усередині форми** | `submit` — **відправляє** форму (так за замовчуванням!) |
| `<button type="submit">` | відправляє форму — пиши явно |
| `<button type="button">` | нічого не відправляє: «Показати пароль», «Назад», «Додати ще адресу» |
| `<button type="reset">` | очищує форму — майже завжди шкодить |

Enter у текстовому полі теж відправляє форму. А `<div class="button">` — не кнопка: на нього не перейти клавішею Tab і не натиснути Enter.

## disabled чи readonly

- `disabled` — поле вимкнене: не отримує фокус і **не відправляється**.
- `readonly` — не можна змінити, але фокус є, і значення **відправляється** (номер замовлення, сума).

## Підсумок

- Кожне поле має `<label>` (`for` = `id` або поле всередині); placeholder — лише приклад формату.
- `name` — ключ даних на сервері; без нього поле не відправиться.
- `type`, `inputmode` і `autocomplete` дають правильну клавіатуру й автозаповнення.
- `required`, `minlength`, `min`, `pattern` — перевірка в браузері, але сервер перевіряє завжди.
- Радіо однієї групи — один `name` у `<fieldset>` з `<legend>`; кнопка, що не відправляє, — `type="button"`.
