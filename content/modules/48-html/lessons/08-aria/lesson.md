# ARIA: коли HTML не вистачає

**ARIA** (Accessible Rich Internet Applications) — набір атрибутів `role` і `aria-*`, які додають у дерево доступності те, чого не вміє сказати HTML: «це меню розгорнуто», «це поле з помилкою», «це поточна сторінка». Головне, що треба запам'ятати: ARIA **змінює лише те, що чує екранний читач**. Вона не додає поведінки: `role="button"` не зробить `<div>` фокусованим і не навчить його реагувати на Enter.

## П'ять правил ARIA

W3C сформулював правила використання ARIA. Перше — найважливіше:

1. **Якщо є HTML-елемент чи атрибут з потрібним значенням — бери його, а не ARIA.** `<button>`, а не `<div role="button">`; `<nav>`, а не `<div role="navigation">`; `<input required>`, а не `aria-required`.
2. Не змінюй ролі вбудованих елементів без потреби (`<h2 role="tab">` — погано).
3. Усі інтерактивні ARIA-елементи мають працювати з клавіатури.
4. Не став `aria-hidden="true"` чи `role="presentation"` на елементи, що отримують фокус.
5. Усі інтерактивні елементи мають мати доступне ім'я.

> [!WARNING]
> «Жодної ARIA краще, ніж погана ARIA» — так пише сам W3C. Неправильна ARIA бреше користувачу: читач скаже «кнопка», а натиснути її неможливо.

## Назва й опис

Фотогалерея: кнопки «попереднє / наступне фото» — лише стрілки-іконки.

```html
<button type="button" aria-label="Попереднє фото">
  <svg aria-hidden="true" …>…</svg>
</button>

<section aria-labelledby="album-title">
  <h2 id="album-title">Карпати, вересень</h2>
  …
</section>

<label for="caption">Підпис до фото</label>
<input id="caption" aria-describedby="caption-hint">
<p id="caption-hint">До 120 символів. Підпис бачать усі, хто має посилання.</p>
```

| Атрибут | Що робить | Коли |
|---|---|---|
| `aria-label="…"` | задає ім'я текстом (замінює вміст) | кнопка-іконка без видимого тексту |
| `aria-labelledby="id"` | бере ім'я з іншого **видимого** елемента | розділ чи діалог названий своїм заголовком |
| `aria-describedby="id"` | додає **опис**: його читають після імені й ролі | підказка до поля, текст помилки |
| `aria-hidden="true"` | ховає від читача, але не з екрана | декоративні іконки, дублювання тексту |

Пріоритет імені: `aria-labelledby` → `aria-label` → HTML (`<label>`, `alt`, текст кнопки) → `title`. Тому `aria-label` на кнопці з текстом **перекриває** цей текст — і людина, яка керує комп'ютером голосом («натисни Завантажити»), не зможе натиснути кнопку, бо її ім'я тепер інше.

> [!NOTE]
> `aria-label` на звичайних `<div>` і `<span>` без ролі не працює: стандарт ARIA 1.2 забороняє давати ім'я елементам без значення, і читачі його ігнорують.

## Стани

### Розгорнуто чи згорнуто: aria-expanded

```html
<button type="button" aria-expanded="false" aria-controls="filters">Фільтри</button>
<div id="filters" hidden>…</div>
```

Скрипт, відкриваючи панель, прибирає `hidden` і ставить `aria-expanded="true"`. Читач скаже «Фільтри, кнопка, згорнуто». `aria-expanded` — на **кнопці**, а не на панелі.

> [!TIP]
> Для простого «показати / сховати» є вбудований елемент без жодної ARIA і JavaScript: `<details><summary>Фільтри</summary>…</details>`.

### Поточна сторінка: aria-current

```html
<nav aria-label="Альбоми">
  <a href="/albums/2025">2025</a>
  <a href="/albums/2026" aria-current="page">2026</a>
</nav>
```

Клас `active` змінює лише колір; `aria-current="page"` каже читачу «поточна сторінка». Те саме — для останньої ланки хлібних крихт.

### Помилки форми: aria-invalid

```html
<label for="album-name">Назва альбому</label>
<input id="album-name" aria-invalid="true" aria-describedby="album-name-error">
<p id="album-name-error">Назва не може бути порожньою</p>
```

Читач скаже: «Назва альбому, поле редагування, недійсне значення, Назва не може бути порожньою». Без `aria-describedby` червоний текст під полем для нього просто ще один абзац десь на сторінці.

## Живі області: повідомлення без переходу фокусу

Коли щось змінюється на сторінці без перезавантаження («Фото завантажено», «Помилка мережі»), читач про це не знає — фокус же нікуди не переходив. Для цього є **живі області**:

| Запис | Як оголошує | Коли |
|---|---|---|
| `role="status"` (= `aria-live="polite"`) | дочекається паузи | «Збережено», «Знайдено 12 фото» |
| `role="alert"` (= `aria-live="assertive"`) | перебиває одразу | помилки, що потребують уваги |

```html
<div role="status"></div>   <!-- порожній контейнер є на сторінці з самого початку -->
```

Контейнер має бути в DOM **заздалегідь**, а скрипт лише міняє його текст. Якщо додати область разом з текстом, частина читачів її пропустить.

## Ролі-області й порожні ролі

- `role="search"`, `role="navigation"` — лише якщо немає відповідного елемента (є `<search>`, `<nav>`).
- `role="presentation"` / `role="none"` — прибирає значення елемента (наприклад, у старої таблиці для розкладки).
- `role="img"` + `aria-label` — для SVG-малюнка, який несе зміст: `<svg role="img" aria-label="Графік завантажень за тиждень">`.

## Типові помилки

| Помилка | Чому погано | Як правильно |
|---|---|---|
| `<div role="button">` без `tabindex` і обробки Enter / пробілу | читач каже «кнопка», а натиснути не можна | `<button>` |
| `<nav role="navigation">`, `<button role="button">` | зайве: роль уже є | просто `<nav>`, `<button>` |
| `aria-hidden="true"` на кнопці | фокус є, а читач мовчить — «порожнє місце» | прибери `aria-hidden` з фокусованого елемента |
| `aria-label` поверх видимого тексту з іншими словами | голосове керування не знайде кнопку | ім'я має містити видимий текст |
| `aria-expanded` на панелі | читач не почує стан на кнопці | `aria-expanded` — на кнопці |

## Підсумок

- ARIA змінює лише дерево доступності, поведінку додаєш сам(а) — тому спершу HTML.
- Ім'я: `aria-label` / `aria-labelledby`; опис: `aria-describedby`; сховати декор: `aria-hidden="true"`.
- Стани: `aria-expanded` на кнопці-розкривачці, `aria-current="page"` у навігації, `aria-invalid` + `aria-describedby` для помилок.
- Повідомлення без переходу фокусу — `role="status"` чи `role="alert"`, контейнер існує заздалегідь.
- Зайва ARIA (`<nav role="navigation">`) — шум, неправильна — брехня.
