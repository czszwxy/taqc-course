# Перша HTML-сторінка

Кожна сторінка в інтернеті — від пошуковика до інтернет-магазину — це текстовий файл з **HTML**. Браузер читає його й малює те, що ти бачиш на екрані. У цьому модулі ти навчишся писати HTML так, як це роблять фронтенд-розробники: правильна структура, зрозумілий зміст і **доступність** — щоб сторінкою могли користуватися і ті, хто працює лише з клавіатурою або слухає сайт через екранний читач.

## Три мови фронтенду

| Мова | Відповідає за | Приклад |
|---|---|---|
| **HTML** | структуру й зміст: *що* є на сторінці | «це заголовок», «це кнопка», «це список книжок» |
| **CSS** | вигляд | кольори, шрифти, розташування блоків (модуль «CSS & Layout») |
| **JavaScript / TypeScript** | поведінку | що станеться після кліку (модуль «DOM & Browser APIs») |

> [!NOTE]
> HTML — не мова програмування: у ній немає змінних, умов і циклів. Це **мова розмітки**: ти «розмічаєш» текст і пояснюєш браузеру, що означає кожна його частина.

## Елемент, тег, атрибут

```html
<a href="/catalog" class="menu-link">Каталог книжок</a>
```

- `<a href="/catalog" class="menu-link">` — **відкривальний тег**, `</a>` — **закривальний** (зі слешем).
- «Каталог книжок» — **вміст** елемента.
- `href="/catalog"` — **атрибут**: ім'я, знак `=` і значення в лапках. Атрибути пишуть лише у відкривальному тегу.
- Усе разом — **елемент** `a` (посилання).

**Порожні (void) елементи** не мають вмісту й закривального тегу: `<img>`, `<input>`, `<br>`, `<hr>`, `<meta>`, `<link>`. Запис `<br />` теж дозволений — слеш нічого не змінює.

**Логічні атрибути** (`required`, `disabled`, `checked`) працюють самою присутністю: `<button disabled>` — вимкнена кнопка. Підступ: `<button disabled="false">` — **теж вимкнена**, бо атрибут є. Щоб увімкнути кнопку, атрибут треба прибрати.

Елементи вкладаються один в одного, і закривати їх треба у **зворотному** порядку:

```html
<p>Новинка: <strong>«Тіні забутих предків»</strong></p>   <!-- ✓ strong закрито всередині p -->
<p>Новинка: <strong>«Тіні забутих предків»</p></strong>   <!-- ✗ перехрещені теги -->
```

## Скелет сторінки

Сторінка електронного каталогу бібліотеки:

```html
<!doctype html>
<html lang="uk">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Каталог — Бібліотека «Сторінка»</title>
    <meta name="description" content="Електронний каталог міської бібліотеки: пошук і бронювання книжок.">
  </head>
  <body>
    <h1>Каталог книжок</h1>
    <p>Знайди книжку й забронюй її онлайн.</p>
  </body>
</html>
```

`<head>` — інформація **про** сторінку (її не видно на самій сторінці), `<body>` — те, що бачить користувач. Розберімо рядки по черзі:

| Рядок | Що робить | Що буде без нього |
|---|---|---|
| `<!doctype html>` | вмикає стандартний режим | «режим сумісності» (quirks mode): браузер імітує помилки старих браузерів, розміри й відступи поводяться дивно |
| `<html lang="uk">` | мова сторінки | екранний читач читає українське англійською вимовою, браузер пропонує «перекласти з англійської» |
| `<meta charset="utf-8">` | кодування символів | «кракозябри» замість кирилиці; має стояти першим у `<head>` |
| `viewport` | на телефоні ширина сторінки = ширина екрана | телефон малює сторінку завширшки ~980 px і зменшує її — текст дрібний |
| `<title>` | назва вкладки, закладки, рядок у результатах пошуку; її першою оголошує екранний читач | у вкладці видно адресу замість назви |
| `description` | короткий опис для пошукових систем | пошуковик сам вибере випадковий шматок тексту |

> [!TIP]
> Давай кожній сторінці свій `<title>`: спершу конкретне, потім назва сайту — «Кошик — Gadgetly», «Оформлення замовлення — Gadgetly». Коли відкрито десять вкладок, саме початок назви допомагає знайти потрібну.

> [!WARNING]
> Не додавай у viewport `user-scalable=no` чи `maximum-scale=1`: так людям зі слабким зором заборонено збільшувати сторінку пальцями.

## Пробіли й переноси рядків

Браузер стискає будь-яку кількість пробілів, табуляцій і переносів рядка в **один пробіл**:

```html
<p>Бібліотека    працює
   щодня</p>
```

На екрані: «Бібліотека працює щодня» — в один рядок. Структуру задають **теги**: новий абзац — це новий `<p>`, а не Enter у файлі. Відступи в коді потрібні людям, щоб бачити вкладеність, браузеру вони байдужі.

## Коментарі

```html
<!-- Блок новинок оновлюємо щопонеділка -->
```

Браузер коментар не показує, але **будь-хто** бачить його через «Переглянути код сторінки» (Ctrl+U). Ніколи не залишай у коментарях паролів, внутрішніх адрес чи «TODO: обійти перевірку оплати».

## Браузер прощає помилки — по-своєму

HTML-парсер ніколи не зупиняється з помилкою: на кожну помилку в стандарті є правило, як її «полагодити». Тому помилка рідко видна одразу — вона проявляється дивною поведінкою:

```html
<p>Нові надходження: <a href="/new">дивитися всі</p>
<p>Години роботи: 9:00–18:00</p>
```

| Що ти написав(ла) | Що побудував браузер (DOM) |
|---|---|
| посилання без `</a>` | браузер «переносить» незакрите посилання далі — другий абзац теж стає посиланням |
| `alt=Обкладинка книжки` без лапок | `alt="Обкладинка"`, а `книжки` стає окремим порожнім атрибутом |
| `<p>Термін: <div>3 дні</div></p>` | `<p>` закривається перед `<div>`, а в кінці з'являється зайвий порожній `<p></p>` — абзац може містити лише текст і «рядкові» елементи |
| `<li>` без `<ul>` / `<ol>` | пункти без списку: екранний читач не скаже «список, 3 пункти» |
| два елементи з `id="hours"` | посилання `#hours` веде до першого, а `id` має бути **унікальним** на сторінці |

Як знаходити такі помилки:

1. **DevTools → Elements** показує DOM — те, що браузер *побудував*, а не твій файл. Якщо там не те, що ти очікуєш, — шукай помилку поруч.
2. **W3C Validator** (validator.w3.org/nu): вставляєш код і отримуєш список помилок з номерами рядків.
3. **Редактор** (VS Code) підсвічує пару до тегу під курсором — так видно незакриті теги.

> [!NOTE]
> Деякі закривальні теги стандарт дозволяє пропускати (`</li>`, `</p>`), і браузер закриє їх сам. Але поки вчишся — закривай усе: так легше бачити структуру й не помилитися.

## Як працювати з практичними задачами

У задачах типу **Web page** зліва (на телефоні — зверху) умова, справа — редактор файлу `index.html`. Вкладка **Preview** показує сторінку так, як її намалює браузер; кнопки 📱 375 / ▭ 768 / 🖥️ Full міняють ширину. **Check** запускає приховані перевірки — кожна неуспішна пише, чого бракує. Для власних проєктів знадобиться редактор VS Code: створюєш файл `index.html` і відкриваєш його в браузері подвійним кліком.

## Підсумок

- HTML описує структуру і зміст, CSS — вигляд, JavaScript — поведінку.
- Елемент = відкривальний тег + вміст + закривальний тег; атрибути — у відкривальному тегу, значення — в лапках.
- Порожні елементи (`img`, `input`, `meta`, `br`) не закриваються; логічний атрибут діє самою присутністю.
- Скелет: `<!doctype html>`, `<html lang>`, `<meta charset="utf-8">`, viewport, унікальний `<title>`.
- Браузер мовчки «лагодить» помилки — перевіряй DOM у DevTools і код у валідаторі.
