# Структура сторінки та області

Відкрий будь-який сайт: шапка з логотипом і меню, основний вміст, бічна колонка, футер. Очима ці частини видно одразу. Але якщо все зверстано з `<div class="header">`, `<div class="content">`, для екранного читача сторінка — один довгий потік тексту. Семантичні елементи дають цим частинам **ролі**, і користувач може перестрибнути одразу до основного вмісту чи меню.

## «Суп з div» і семантика

Сторінка міського новинного сайту:

```html
<!-- ✗ «суп з div»: для браузера й читача все однакове -->
<div class="header">…</div>
<div class="menu">…</div>
<div class="content">…</div>
<div class="footer">…</div>

<!-- ✓ семантика: кожна частина має роль -->
<header>
  <a href="/"><img src="logo.svg" alt="Новини міста — на головну" width="160" height="40"></a>
  <nav aria-label="Головне меню">
    <ul>
      <li><a href="/city">Місто</a></li>
      <li><a href="/culture">Культура</a></li>
      <li><a href="/sport">Спорт</a></li>
    </ul>
  </nav>
</header>
<main id="main">
  <h1>Новини дня</h1>
  <article>
    <h2><a href="/city/bridge">Новий міст через Десну відкрили для руху</a></h2>
    <p>…</p>
  </article>
</main>
<aside>
  <h2>Найпопулярніше</h2>
  …
</aside>
<footer>
  <p>© 2026 Новини міста</p>
</footer>
```

## Області (landmarks)

| Елемент | Роль для читача | Що всередині |
|---|---|---|
| `<header>` | banner — шапка сайту | логотип, головне меню, пошук |
| `<nav>` | navigation | **основні** блоки навігації: меню, хлібні крихти, пагінація |
| `<main>` | main — основний вміст | те, заради чого відкрили саме цю сторінку; **один** на сторінці |
| `<aside>` | complementary | пов'язане, але не головне: «Найпопулярніше», реклама |
| `<footer>` | contentinfo — футер сайту | копірайт, контакти, правила |
| `<search>` | search | форма пошуку по сайту |
| `<section>` з заголовком і назвою | region | великий розділ, який варто мати в списку областей |

Користувач NVDA натискає **D** і стрибає між областями, а VoiceOver показує їх у «ротері». Тому областей не має бути забагато: не кожна група посилань — `<nav>` (три посилання у футері можна залишити просто списком).

> [!NOTE]
> `<header>` і `<footer>` стають шапкою й футером **сайту**, лише коли лежать не всередині `<article>`, `<section>`, `<aside>`, `<nav>` чи `<main>`. Усередині статті `<header>` — це просто «шапка статті» (заголовок, автор, дата), без ролі banner.

> [!TIP]
> `<search>` — новий елемент (2023), працює в усіх сучасних браузерах. Він дає області роль search без жодного атрибута: `<search><form action="/search">…</form></search>`.

## article чи section?

- `<article>` — **самостійний** шматок, який має сенс окремо від сторінки: новина, допис у блозі, картка товару, відгук, коментар. Перевірка: «Чи можна поділитися ним окремо?»
- `<section>` — **розділ** чогось більшого з власним заголовком: «Характеристики», «Відгуки» на сторінці товару, розділ статті.
- `<div>` — коли немає жодного значення: обгортка, щоб розташувати блоки поруч у CSS. Це нормально: `<div>` не помилка, помилка — `<div>` **замість** семантичного елемента.

Розділ без заголовка — підозріло: швидше за все, це або не розділ, або заголовок забули.

## Посилання «Перейти до основного вмісту»

Людина, що працює з клавіатурою, на кожній сторінці проходить Tab'ом крізь логотип і десять пунктів меню, перш ніж дійде до вмісту. Рішення — **skip link**, перше посилання сторінки:

```html
<body>
  <a href="#main" class="skip-link">Перейти до основного вмісту</a>
  <header>…</header>
  <main id="main">…</main>
</body>
```

Зазвичай його ховають CSS-ом, доки на нього не перейде фокус (як — у модулі про CSS). Головне — воно **перше** в розмітці і веде на `id` елемента `<main>`.

## Дати й контакти

- `<time datetime="2026-11-03">3 листопада</time>` — дата, яку зрозуміють пошуковики й календарі; `datetime` у форматі `РРРР-ММ-ДД` (можна з часом: `2026-11-03T18:30`).
- `<address>` — контакти **власника** сторінки чи статті (email редакції, телефон). Не для будь-якої поштової адреси в тексті.

## Типові помилки

- Кілька `<main>` або жодного.
- `<nav>` навколо кожного маленького набору посилань — область «меню» губиться серед інших.
- `<section>` як заміна `<div>` для стилів — розділ без заголовка.
- Skip link не першим або з `href` на неіснуючий `id`.
- Семантичні елементи є, але всередині меню — посилання без списку: читач не скаже «список, 3 пункти».

## Підсумок

- Області сторінки: `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`, `<search>` — читач показує їх списком.
- `<main>` один; на нього веде перше посилання «Перейти до основного вмісту».
- `<article>` — самостійний вміст, `<section>` — розділ з заголовком, `<div>` — коли значення немає.
- `<header>` / `<footer>` усередині `<article>` — шапка й футер статті, не сайту.
- `<time datetime>` для дат, `<address>` для контактів власника сторінки.
