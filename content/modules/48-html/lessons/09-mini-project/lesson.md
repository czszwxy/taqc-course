# Міні-проєкт: сторінка товару

Час зібрати все разом. У цьому уроці ти розмітиш з нуля повну сторінку товару Gadgetly — таку, яку не соромно показати на співбесіді: правильний документ, зрозуміла структура, доступні зображення, посилання й форма. А потім перевіриш її так, як це роблять у командах.

## Порядок роботи

Досвідчені розробники не пишуть сторінку зверху вниз «як вийде». Вони йдуть від загального до деталей:

1. **Зміст.** Збери весь текст і зрозумій, що на сторінці головне (тут — товар і кнопка «Додати в кошик»).
2. **Скелет документа**: doctype, `lang`, `charset`, viewport, `<title>`, опис.
3. **Області**: skip link, `<header>` з меню, `<main>`, `<aside>`, `<footer>`.
4. **Заголовки**: один `<h1>` і розділи `<h2>` / `<h3>` — так, щоб зі списку заголовків було зрозуміло всю сторінку.
5. **Вміст**: текст, списки, таблиця, зображення з `alt`, форма з `<label>`.
6. **Перевірка**: клавіатура, валідатор, автоматичні інструменти, екранний читач.

## Як виглядає готова структура

Схема сторінки (вміст скорочено):

```text
body
├─ a «Перейти до основного вмісту» → #main
├─ header
│  ├─ a (логотип з alt) → /
│  └─ nav «Головне меню» → ul > li > a (поточний — aria-current="page")
├─ main#main
│  ├─ nav «Хлібні крихти» → ol > li (остання — aria-current="page")
│  ├─ article (товар)
│  │  ├─ h1
│  │  ├─ figure → img (alt, width, height) + figcaption
│  │  ├─ p ціна: strong + del
│  │  ├─ form «Додати в кошик» → label + input number + button
│  │  ├─ section → h2 «Характеристики» + table (caption, th scope="row")
│  │  └─ section#reviews → h2 «Відгуки» + article × N (h3 автор)
│  └─ aside → h2 «Схожі товари» + ul > li > a
└─ footer → address (mailto:, tel:) + ©
```

Зверни увагу: відгуки — `<article>` усередині `<article>` товару. Це нормально: кожен відгук самостійний, а належить цьому товару.

## Як перевіряти готову сторінку

**Клавіатура.** Клікни в сторінку (у задачі — у Preview) і пройди її Tab'ом від початку до кінця:

- першим отримує фокус skip link;
- порядок фокусу збігається з порядком читання;
- фокус видно на кожному елементі;
- поле «Кількість» змінюється стрілками, кнопка натискається Enter і пробілом.

**Зміст і області.** Випиши заголовки з рівнями — чи зрозуміла з них сторінка без тексту? Перелічи області — чи немає зайвих чи безіменних дублікатів?

**Інструменти.** Збережи код у файл `index.html` на комп'ютері й відкрий у Chrome:

- W3C Validator (validator.w3.org/nu → Validate by File Upload) — помилки розмітки;
- DevTools → **Lighthouse** → категорія Accessibility — автоматичний аудит;
- DevTools → Elements → **Accessibility** — роль і ім'я конкретного елемента;
- WAVE чи розширення axe DevTools — ще один погляд.

Пам'ятай: інструменти знаходять лише частину проблем. Те, що `alt` «нормальний» і порядок Tab логічний, перевіряєш ти.

> [!TIP]
> Цю сторінку можна покласти в портфоліо: репозиторій на GitHub з `index.html` і коротким README «що я перевірив(ла) і як». У модулі про CSS ти зробиш її ще й гарною.

## Підсумок

- Від загального до деталей: зміст → скелет → області → заголовки → вміст → перевірка.
- Готова сторінка читається з самого списку заголовків і областей.
- Перевірка — клавіатура, валідатор, Lighthouse / axe і власні очі: автоматика бачить не все.
