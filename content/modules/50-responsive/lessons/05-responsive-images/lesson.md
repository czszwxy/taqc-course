# Адаптивні зображення

Фото 1600 px завширшки на телефоні з екраном 390 px — це зайві мегабайти через мобільний інтернет. А на ноутбуці з екраном високої щільності фото 800 px виглядає розмитим. Мета: кожному пристрою — **найменший файл, якого досить**.

## srcset з w: браузер обирає сам

Фотогалерея подорожей:

```html
<img
  src="lake-800.jpg"
  srcset="lake-400.jpg 400w, lake-800.jpg 800w, lake-1600.jpg 1600w"
  sizes="(min-width: 60em) 33vw, 100vw"
  alt="Озеро Синевир у тумані на світанку"
  width="1600" height="1067">
```

- `srcset` — список файлів і їхня **справжня ширина**: `400w` означає 400 пікселів.
- `sizes` — яку ширину фото займе **на сторінці**: «від 60em — третину вікна, інакше — на всю ширину». Перемагає перша умова, що збіглася; останнє значення — без умови.
- `src` — запасний варіант для дуже старих браузерів.

Браузер рахує: ширина місця на сторінці (**слоту**) × щільність пікселів екрана (**DPR**). Телефон 390 px з DPR 3: 390 × 3 = 1170 → потрібен файл від 1170w → `lake-1600.jpg`. Ноутбук 1440 px з DPR 1: третина вікна — 480 px → `lake-800.jpg`.

> [!NOTE]
> Специфікація дозволяє браузеру обирати й інакше: взяти файл, що вже є в кеші, або менший на повільній мережі. Твоя задача — дати варіанти і правдиві `sizes`, а рішення — за браузером.

> [!WARNING]
> Без `sizes` браузер вважає, що фото займає **всю ширину вікна** (`100vw`), і для маленької картинки в сітці завантажує найбільший файл.

## srcset з x: фіксований розмір

Логотип чи аватар завжди 120 × 40 px — ширина слоту відома, різниться лише щільність екрана:

```html
<img src="club.png" srcset="club.png 1x, club@2x.png 2x" alt="Фотоклуб «Кадр»" width="120" height="40">
```

Логотипи й іконки ще краще робити в **SVG**: вектор чіткий на будь-якому екрані й при будь-якому збільшенні.

## <picture>: інший кадр або інший формат

`<picture>` потрібен, коли файл має бути **іншим**, а не просто більшим чи меншим.

**Art direction.** На телефоні широкий банер стає смужкою, де нічого не видно. Краще інший кадр — квадратний, з крупним планом:

```html
<picture>
  <source media="(min-width: 48em)" srcset="festival-wide.jpg" width="1600" height="500">
  <img src="festival-square.jpg" alt="Сцена фестивалю вночі" width="800" height="800">
</picture>
```

**Формати.** AVIF і WebP значно легші за JPEG при тій самій якості. Браузер бере перший `<source>`, тип якого вміє показувати:

```html
<picture>
  <source type="image/avif" srcset="lake-800.avif 800w, lake-1600.avif 1600w" sizes="100vw">
  <source type="image/webp" srcset="lake-800.webp 800w, lake-1600.webp 1600w" sizes="100vw">
  <img src="lake-800.jpg" srcset="lake-800.jpg 800w, lake-1600.jpg 1600w" sizes="100vw"
       alt="Озеро Синевир у тумані на світанку" width="1600" height="1067">
</picture>
```

Правила `<picture>`:

- `<img>` **обов'язковий** і стоїть останнім: показується саме він, тому `alt`, `width`, `height`, `loading` пишуть на ньому.
- `<source>` перевіряються **по черзі**, перемагає перший, що підходить. Тому AVIF — вище за WebP.
- `sizes` у кожного `<source>` свій: з `<img>` він не успадковується.
- `<source>` може мати власні `width` і `height`, якщо пропорції кадру інші.

> [!TIP]
> Коли `<img>` загорнутий у `<picture>`, елементом сітки чи flex-рядка стає `<picture>`. А він за замовчуванням не стискається вужче за справжню ширину фото: `max-width: 100%` на `<img>` не допомагає, і фото 1600 px вилазить за екран. Рятує `min-width: 0` для `<picture>` (або колонка `minmax(0, 1fr)`).

## Завантаження: lazy і пріоритет

```html
<img src="hero.jpg" … fetchpriority="high">       <!-- головне фото першого екрана -->
<img src="comment-photo.jpg" … loading="lazy">     <!-- нижче, поза першим екраном -->
```

- `loading="lazy"` — браузер завантажує фото, лише коли до нього доскролили. Для всього, що нижче першого екрана.
- **Не** став `lazy` на головне фото першого екрана: воно найважливіше для швидкості (метрика **LCP** — коли з'явився найбільший елемент), а lazy його затримує.
- `fetchpriority="high"` — підказка «це фото завантажити раніше за інші».
- `width` і `height` — завжди: браузер резервує місце ще до завантаження, і текст не «стрибає» (метрика **CLS** — наскільки зсувається сторінка).

## CSS: однакові рамки для різних фото

Фото різних пропорцій у сітці? `aspect-ratio` + `object-fit` (урок 3):

```css
.gallery img {
  width: 100%;
  height: auto;
  aspect-ratio: 1;
  object-fit: cover;
}
```

> [!QA]
> Як перевірити, який файл завантажився: DevTools → Network → фільтр **Img** на різних ширинах і DPR (у Device toolbar можна задати DPR 1, 2 чи 3). Або в консолі `$0.currentSrc` для зображення, вибраного в Elements. Перевіряй і повільну мережу: чи не «стрибає» текст, поки вантажаться фото.

## Підсумок

- `srcset` з `w` + правдиві `sizes` — браузер сам обирає найменший достатній файл.
- `srcset` з `1x` / `2x` — для фото фіксованого розміру; логотипи й іконки — SVG.
- `<picture>` + `media` — інший кадр; `<picture>` + `type` — новий формат із запасним.
- `<img>` у `<picture>` обов'язковий, останній, з `alt`, `width`, `height`.
- `loading="lazy"` — нижче першого екрана; головне фото — без lazy, з `fetchpriority="high"`.
