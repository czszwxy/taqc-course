# Tech check: Web Basics

Перше, що питають у junior frontend-розробника, — не React, а основа: як браузер отримує й малює сторінку, чому `<button>` краще за `<div>`, як рахується специфічність, що таке mobile first. За відповідями одразу видно, чи людина верстала сама, чи лише дивилася відео.

Цей урок закриває блок **Web Basics** (як працює веб, HTML і доступність, CSS, адаптивний дизайн). Блок вважається пройденим, коли ти складеш tech check.

## Як проходить сесія

1. 12 випадкових питань з банку — порівну з кожної теми, тема за темою.
2. На кожне — близько 2 хвилин. Відповідай **уголос**.
3. Відкриваєш еталонну відповідь і відмічаєш ключові пункти, які ти **справді сказав(ла)**.
4. Прохідний бал — 80 %. Повторна спроба — новий набір питань.

## Як відповідати frontend-розробнику

- **Визначення + приклад з коду.** «Специфічність — вага селектора: id сильніший за клас, клас — за тег. Наприклад, `#header a` переможе `.nav a`, тому я не стилізую через id».
- **Покажи, що верстав(ла) сам(а).** «Я перевіряю сторінку на 320 px і на межах breakpoints», «Спершу пишу телефонну розкладку» звучить переконливіше за визначення з підручника.
- **Згадуй доступність.** Майже кожне питання про HTML і CSS має доступний бік: фокус, контраст, підписи, збільшення. Інтерв'юери це цінують.
- **Кажи, коли «залежить».** «Flexbox — для одного виміру, Grid — для двох, а часто вони разом: Grid для сторінки, Flexbox у шапці».

> [!TIP]
> Майже кожне питання має уточнення: «А як це перевірити?», «А що, якщо …?». Знай не лише відповідь, а й наступний крок: DevTools, ширину, яку перевіриш, правило, яке напишеш.
