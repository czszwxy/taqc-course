# Сенсорні екрани й мобільний UX

Палець — не курсор: він товстий, неточний і не вміє «наводити». А ще в телефона є віртуальна клавіатура, виріз камери й панелі браузера, які з'являються й ховаються. Адаптивна сторінка враховує не лише ширину, а й **спосіб взаємодії**.

## Розмір цілі

| Вимога | Розмір |
|---|---|
| WCAG 2.5.8 Target Size (Minimum), рівень AA | щонайменше **24 × 24 CSS px** — або менша ціль з таким вільним місцем навколо, щоб коло діаметром 24 px не зачіпало сусідів |
| WCAG 2.5.5 Target Size (Enhanced), рівень AAA | 44 × 44 CSS px |
| Apple Human Interface Guidelines | 44 × 44 pt |
| Material Design | 48 × 48 dp |

Для кнопок мобільного інтерфейсу цілься в **44 px**. Ціль можна збільшити, не змінюючи вигляду значка, — через `min-width` / `min-height` або padding. Плеєр подкастів:

```css
.player-controls { display: flex; gap: 0.5rem; }    /* відстань між цілями */

.player-controls button {
  min-width: 2.75rem;      /* 44 px */
  min-height: 2.75rem;
  display: inline-flex;
  align-items: center;
  justify-content: center;
}
```

Посилання всередині абзацу — виняток із WCAG 2.5.8: їхній розмір задає рядок тексту. А посилання в меню й футері — окремі цілі, їм теж потрібна висота.

## Наведення є лише в мишки

На сенсорному екрані `:hover` поводиться дивно: «прилипає» після дотику або не спрацьовує взагалі. Тому:

1. Важливе ніколи не ховається за `:hover`: підказки, кнопка «Видалити», підменю.
2. Ефекти наведення — лише для пристроїв, які вміють наводити:

```css
@media (hover: hover) {
  .episode:hover { background-color: #f3f4f6; }
}
```

`(hover: hover)` — основний пристрій уміє наводити, `(pointer: coarse)` — основний пристрій неточний (палець), і цілі можна зробити ще більшими.

## Поля вводу на телефоні

**Шрифт поля — від 16 px.** Safari на iPhone збільшує сторінку, коли торкаєшся поля з дрібнішим шрифтом, і людині доводиться зменшувати її назад.

**Правильна клавіатура.** `type` і `inputmode` вирішують, яку клавіатуру показати:

| Атрибут | Клавіатура | Для чого |
|---|---|---|
| `type="email"` | з `@` і `.` | email |
| `type="tel"` | цифри, `+`, `*`, `#` | телефон |
| `type="url"` | з `/` і `.com` | адреса сайту |
| `type="search"` | Enter = «Пошук» | пошук |
| `inputmode="numeric"` | лише цифри | коди, номери карток, індекси |
| `inputmode="decimal"` | цифри й кома | суми з копійками |

Код з SMS: `inputmode="numeric" autocomplete="one-time-code"` — телефон сам запропонує код з повідомлення.

> [!WARNING]
> `type="number"` — для **кількостей**, з якими рахують. Номерам (картка, індекс) він шкодить: відкидає нулі на початку, додає стрілки, а значення може змінитися від прокрутки коліщатком.

## Висота екрана: vh, svh, dvh

На телефоні панелі браузера ховаються під час прокрутки, і висота вікна змінюється. `100vh` рахується від **найбільшої** висоти, тож кнопка внизу «першого екрана» ховається під панеллю.

| Одиниця | Висота вікна |
|---|---|
| `svh` | найменша: панелі видно |
| `lvh` | найбільша: панелі сховані |
| `dvh` | поточна, змінюється під час прокрутки |

```css
.onboarding { min-height: 100svh; }   /* перший екран, який точно видно повністю */
```

Ці одиниці працюють в усіх сучасних браузерах з 2022 року.

## Виріз камери й безпечні зони

На iPhone з вирізом в альбомній орієнтації вміст може сховатися за камерою, а внизу — за смужкою жесту «додому». З `viewport-fit=cover` сторінка займає весь екран, а безпечні відступи задаєш сам(а):

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

```css
.player-bar {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  padding-bottom: max(0.75rem, env(safe-area-inset-bottom));
}
```

`env(safe-area-inset-bottom)` — висота «небезпечної» зони знизу (0 на звичайних екранах), а `max()` дає щонайменше звичайний відступ.

## Фіксовані панелі не мають закривати вміст

Липка шапка чи панель знизу закриває частину сторінки. Перевір дві речі:

- коли доскролиш до кінця, останній блок видно повністю: під фіксовану панель знизу потрібен відступ на її висоту;
- елемент у фокусі не ховається під шапкою (WCAG 2.4.11 Focus Not Obscured): `html { scroll-padding-top: 5rem; }` — і браузер прокручує з урахуванням шапки.

> [!QA]
> Чек-лист для телефона: натисни кожну кнопку пальцем (не мишкою в емуляції!), відкрий кожне поле й подивися на клавіатуру, поверни телефон горизонтально, доскроль до кінця під фіксованою панеллю, перевір, що нічого важливого не з'являється лише при наведенні.

## Підсумок

- Цілі — 44 px (мінімум WCAG AA — 24 × 24), з відстанню між ними.
- `:hover` — лише бонус і лише в `@media (hover: hover)`.
- Поля — шрифт від 16 px; `type` і `inputmode` дають правильну клавіатуру.
- `svh` / `dvh` замість `vh` для «першого екрана» на телефоні.
- `env(safe-area-inset-*)` + `viewport-fit=cover` — вміст не ховається за вирізом.
- Фіксовані панелі не закривають ні останній блок, ні фокус.
