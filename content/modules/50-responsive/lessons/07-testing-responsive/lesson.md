# Тестування й налагодження адаптивної верстки

Модуль «Як працює веб» навчив дивитися на сторінку очима тестувальника: breakpoints, режим пристрою, реальні пристрої. Тепер ти розробник(ця): треба не лише помітити, що щось вилазить, а й **знайти, що саме**, виправити і переконатися, що на інших ширинах нічого не зламалося.

## Знайти, що вилазить

Сторінка гортається вбік, а винуватця не видно? Сніпет для Console у DevTools:

```js
const width = document.documentElement.clientWidth;
document.querySelectorAll('body *').forEach((node) => {
  if (node.getBoundingClientRect().right > width) console.log(node);
});
```

У списку будуть і винуватець, і всі його батьки, яких він розпирає. Шукай **найглибший** елемент — той, усередині якого немає інших зі списку. Друга техніка — тимчасово обвести все:

```css
* { outline: 1px solid red; }
```

`outline`, на відміну від `border`, не займає місця: розкладка не зміниться, а межі всіх блоків стануть видимі.

Типові винуватці — з уроку 1: фіксовані ширини, фото без `max-width`, довгі слова, `100vw`, flex-рядки без перенесення. І ще один підступний: **grid- чи flex-елемент не стискається вужче за свій вміст** (`min-width: auto`). Довгий email у колонці `1fr` розпирає всю сітку. Допомагає `min-width: 0` або `overflow-wrap: anywhere`. Саме `anywhere`, а не `break-word`: лише воно зменшує мінімальну ширину колонки.

> [!WARNING]
> Знайшов(ла) винуватця — виправ **його**, а не батька. `overflow: hidden` на батькові не прибирає проблему, а обрізає вміст: людина не побачить кінець email чи кнопку.

## DevTools для адаптивної верстки

| Інструмент | Де | Для чого |
|---|---|---|
| Device toolbar | Ctrl + Shift + M | будь-яка ширина, DPR, поворот, сенсорний ввід |
| Смужки медіазапитів | ⋮ у Device toolbar → Show media queries | breakpoints сторінки кольоровими смужками; клік — і ширина стає на межу |
| Rendering → Emulate CSS media feature | ⋮ → More tools → Rendering | `prefers-color-scheme`, `prefers-reduced-motion` без зміни налаштувань системи |
| Rendering → Emulate CSS media type | там само | `print` — як сторінка друкується |
| Бейджі `grid` / `flex` | Elements, поруч з елементом | накладка з лініями сітки, номерами ліній і проміжками |
| Computed | Elements → Computed | яке значення перемогло і з якого правила |
| Network → Img | Network | які файли зображень завантажились на цій ширині й DPR |
| Lighthouse (Mobile) | Lighthouse | швидкість і доступність на телефоні: LCP, CLS, розмір цілей |

## Що перевіряти

1. **Межі breakpoints**: 639 / 640 / 641 px для `40em` — та сама BVA.
2. **Проміжки між breakpoints**: тягни вікно плавно — найбільше поломок саме там, де ніхто не дивився (900 px, 1100 px).
3. **320 px** — WCAG Reflow.
4. **Збільшення**: 200 % і 400 % (Ctrl + «+») і великий шрифт у налаштуваннях браузера.
5. **Text Spacing**: збільшені інтервали — текст не обрізається й не накладається.
6. **Довгий вміст**: довгі назви товарів, email, номери; переклади часто довші за оригінал.
7. **Без картинок і на повільній мережі**: чи не «стрибає» сторінка.
8. **Орієнтація**: телефон горизонтально — мало висоти, липкі панелі займають пів екрана.
9. **Тема, рух і друк**: темна тема, «Зменшити рух», друк.
10. **Справжній телефон**: Safari на iPhone, недорогий Android, палець замість мишки.

## Чого не покаже емуляція

Device toolbar змінює ширину й DPR, але це той самий Chrome на твоєму комп'ютері. Він не покаже, як Safari ховає адресний рядок і що від цього стається зі `100vh`, як iPhone збільшує поле з дрібним шрифтом, як віртуальна клавіатура закриває поле і чи зручно натиснути кнопку великим пальцем. Тому перед релізом — хоча б один iPhone і один Android.

> [!TIP]
> Телефон, підключений кабелем, можна відкрити в DevTools комп'ютера. Chrome на Android — через `chrome://inspect` на комп'ютері (на телефоні треба ввімкнути налагодження USB). Safari на iPhone — через меню Develop у Safari на Mac. Сторінка відкрита на телефоні, а інспектор — на великому екрані.

## Автоматизація

Перевіряти десять ширин руками після кожної зміни довго. В автотестах ширину задають так само: у Playwright — `page.setViewportSize({ width: 375, height: 667 })` і перевірки на кількох ширинах, а порівняння скриншотів ловить «поїхало на 2 px». Check у задачах цього модуля робить те саме: змінює ширину сторінки й міряє блоки.

> [!QA]
> Баг адаптивної верстки описуй з шириною і причиною, якщо знайшов(ла): «Chrome, 375 × 667, DPR 2: панель "Оформити" закриває останній товар; на 1024 px — усе гаразд. У .cart немає відступу під фіксовану панель». Розробнику, який бачить ширину й правило, не треба вгадувати.

## Підсумок

- Сніпет з `getBoundingClientRect().right` і `outline` знаходять винуватця; виправляй найглибший елемент.
- Grid- і flex-елементи не стискаються вужче за вміст: `min-width: 0` або `overflow-wrap: anywhere`.
- DevTools: Device toolbar і смужки медіазапитів, Rendering для теми, руху й друку, бейджі grid / flex, Network для зображень.
- Перевіряй межі й проміжки breakpoints, 320 px, збільшення, Text Spacing, довгий вміст, орієнтацію.
- Емуляція не замінює справжній iPhone і Android.
