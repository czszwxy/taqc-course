# Git: репозиторій, коміти, історія

Код автотестів — це код. Його пише команда, він змінюється щодня, а іноді треба повернутися до вчорашньої версії, бо «вчора тести проходили». **Git** — система контролю версій (version control system). Вона пам'ятає кожну збережену версію проєкту: хто, коли і що змінив.

## Основні поняття

- **Репозиторій** (repository, repo) — проєкт під наглядом Git. Уся історія лежить у прихованій папці `.git`.
- **Коміт** (commit) — збережений знімок (snapshot) проєкту з повідомленням, автором і датою. Кожен коміт має унікальний хеш, наприклад `9d5c712`.
- **Історія** — ланцюжок комітів, кожен посилається на попередній.

## Три стани файлу

```text
 working directory  ──git add──►  staging area  ──git commit──►  repository (.git)
 (твої зміни)                     (готові до коміту)              (збережена історія)
```

| Стан | Що означає | Як `git status` це показує |
|---|---|---|
| **untracked** | новий файл, Git його ще не відстежує | `Untracked files:` (червоний) |
| **modified** | відстежуваний файл змінено, зміна ще не в staging | `Changes not staged for commit:` (червоний) |
| **staged** | зміна додана через `git add` і піде в наступний коміт | `Changes to be committed:` (зелений) |
| **committed** | зміну збережено в історії, робоча папка «чиста» | `nothing to commit, working tree clean` |

Навіщо проміжний етап staging? Він дає вибрати, **що саме** піде в коміт. Наприклад, закомітити виправлений тест, а експериментальний файл поки лишити.

## Базові команди

```bash
git init                       # зробити з поточної папки репозиторій (один раз)
git status                     # що змінено, що в staging — запускай постійно!
git add tests/login.spec.ts    # додати файл у staging
git add .                      # додати всі зміни в поточній папці
git commit -m "Add login negative tests"   # зберегти коміт з повідомленням
git log --oneline              # історія: хеш + повідомлення
git diff                       # що змінено, але ще не в staging
git diff --staged              # що піде в коміт
```

Перед першим комітом Git просить представитися (це автор комітів):

```bash
git config --global user.name "Olena Kovalenko"
git config --global user.email "olena@example.com"
```

> [!TIP]
> `git status` — найкорисніша команда Git. Запускай її перед `add`, після `add` і перед `commit`. Вона ще й підказує наступні команди.

## Добре повідомлення коміту

Історію читають люди: «коли зламався тест кошика?». Повідомлення `fix` або `wip` нічого їм не скаже.

| Погано | Добре |
|---|---|
| `fix` | `Fix flaky cart test by waiting for the API response` |
| `changes` | `Add negative login tests for empty and wrong password` |
| `asdf` | `Remove hard-coded password from checkout test` |
| `final version 2` | `Update README with steps to run tests locally` |

Правила: дієслово в наказовому способі (Add, Fix, Remove, Update), **що** і за потреби **навіщо**, до ~70 символів у першому рядку. Один коміт — одна логічна зміна.

## Скасувати й повернути

```bash
git restore tests/login.spec.ts          # відкинути незбережені зміни у файлі (обережно: назавжди)
git restore --staged tests/login.spec.ts # прибрати з staging, зміни лишаються у файлі
git show 9d5c712                          # подивитися, що змінив коміт
git revert 9d5c712                        # новий коміт, що скасовує зміни старого (безпечно)
```

> [!WARNING]
> `git reset --hard` і `git push --force` переписують історію або безповоротно видаляють зміни. Без чіткого розуміння і згоди команди їх не використовують. Для скасування вже опублікованого коміту є `git revert`.

> [!QA]
> Git допомагає і в розслідуванні багів: «тест падає з учора» → `git log` показує, що змінилося з учора. `git diff` між двома комітами показує точні рядки. Для пошуку коміту, який зламав поведінку, є навіть окрема команда `git bisect`.

## Підсумок

- Git зберігає історію проєкту комітами (знімок + повідомлення + автор + хеш).
- Шлях файлу: working directory → `git add` → staging → `git commit` → історія.
- Стани: untracked, modified, staged, committed. `git status` показує, де що.
- `git log --oneline` і `git diff` показують історію і зміни.
- Повідомлення коміту: «Дієслово + що (+ навіщо)», одна логічна зміна на коміт.
- `git restore` відкидає локальні зміни, `git revert` безпечно скасовує опублікований коміт.
