# Міні-проєкт: повна тестова документація для To-do

Це фінальний проєкт модуля. Уяви: стартап Taskly випускає **To-do v1.0**, і ти — **єдиний тестувальник**. Ніхто не скаже, що саме перевіряти. Тобі треба самостійно пройти весь цикл, який ти відпрацювала в попередніх уроках, і в кінці відповісти команді: **можна випускати чи ні**.

Сторінка: [To-do list](/playground/todo).

## Що треба здати

| # | Артефакт | Урок, де ти це вже робила |
|---|---|---|
| 1 | **Чекліст** функції (12+ пунктів) | 03 — Login page |
| 2 | **Тест-кейс** на граничне значення | 04 — Registration form |
| 3 | **Баг-репорти** (щонайменше 4) | 03–07 |
| 4 | **Test summary report** з рекомендацією | 08 — Regression run |

## План роботи

1. **Прочитай вимоги** (жовтий блок) і випиши правила: довжина тексту, Enter / Esc, лічильник, фільтри, Clear completed, збереження.
2. **Тур по функції** (5–10 хвилин): просто покористуйся застосунком як звичайна людина.
3. **Чекліст**: позитивні, негативні, граничні значення, стани, дані після перезавантаження.
4. **Тест-кейс** для межі 100 символів.
5. **Exploratory-сесія** за чеклістом → баг-репорти.
6. **Звіт**: що перевірено, що знайдено, ризики, рекомендація.

## Евристики для To-do

- **CRUD:** Create (додати), Read (показати), Update (редагувати, відмітити), Delete (видалити, Clear completed) — перевір кожну операцію.
- **Межі:** 0, 1, 100, 101 символ; пробіли на початку/в кінці.
- **Стани задачі:** active ↔ completed; як кожна дія впливає на лічильник і фільтри.
- **Скасування:** Esc і Cancel мають **нічого не змінювати**.
- **Тексти:** однина / множина («1 item left»), повідомлення про помилки.
- **Збереження:** онови сторінку (F5) після кожної зміни — чи все залишилось як було?

> [!TIP]
> Лічильник «N items left» — чудовий «індикатор»: після **кожної** дії (додати, відмітити, видалити, очистити) перевіряй, чи правильне число. Помилки в обліку часто видно саме там.

> [!QA]
> Цей проєкт можна покласти в **портфоліо**: чекліст, тест-кейс, баг-репорти і звіт — саме те, що просять показати джуніора на співбесіді. Натисни **Copy for review** у кожному завданні й попроси Claude дати детальний фідбек.

## Підсумок

- Повний цикл: вимоги → тур → чекліст → тест-кейс → сесія → баги → звіт.
- Евристики: CRUD, межі, стани, скасування, тексти, збереження після перезавантаження.
- Після кожної дії перевіряй лічильник і фільтри.
- Звіт завершується однозначною рекомендацією з причиною.
