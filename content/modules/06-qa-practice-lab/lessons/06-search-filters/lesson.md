# Пошук і фільтри: exploratory-сесія

Пошук із фільтрами — функція з величезною кількістю комбінацій: текст × категорія × ціна × наявність × сортування. Написати тест-кейс на кожну неможливо. Тут найкраще працює **exploratory testing**: ти одночасно вивчаєш продукт, придумуєш тести і виконуєш їх, спираючись на мету й евристики.

Практика — на сторінці [Search & filters](/playground/search).

## Session-based exploratory testing

Exploratory testing — це не «потикати навмання». У нього є структура:

1. **Charter** — мета сесії одним реченням: *Explore* \<що\> *with* \<чим/як\> *to discover* \<яку інформацію\>.
2. **Time-box** — 30–60 хвилин без відволікань.
3. **Нотатки** під час сесії: що перевірила, які дані, що помітила, які питання виникли.
4. **Debrief** — короткий підсумок: знайдені баги, ризики, що не встигла, ідеї для наступної сесії.

```text
Charter: Explore the price filter and sorting
         with boundary prices, empty fields and min > max
         to discover calculation and ordering errors.
```

> [!TIP]
> Одна сесія — одна мета. Якщо помітила щось цікаве поза charter'ом, запиши ідею для **наступної** сесії, а не стрибай туди одразу.

## Евристики для пошуку і фільтрів

| Евристика | Що пробувати |
|---|---|
| **Регістр і пробіли** | `mouse`, `MOUSE`, `  Mouse ` — результат має бути однаковий |
| **Частковий збіг** | початок, середина, кінець назви: `Wire`, `less`, `M2` |
| **Порожньо / нічого не знайдено** | порожній запит, запит без результатів — є зрозуміле повідомлення? |
| **Межі діапазону** | Max = точна ціна товару; Min = Max; Min > Max; порожні поля |
| **Комбінації** | текст + категорія + ціна + In stock одночасно (AND) |
| **Сортування** | перевір **весь** список, а не лише перший товар; обидва напрямки |
| **Узгодженість** | лічильник «N products found» = кількість карток |
| **Скидання** | Clear filters повертає **все** в початковий стан |
| **Стан товару** | out-of-stock: мітка, кнопка Add to cart |

> [!QA]
> Класична помилка в програмуванні — порівнювати числа як **текст**: тоді `900` опиняється «більшим» за `1200`, бо символ «9» більший за «1». Тому перевіряй порядок за всім списком, особливо коли числа мають різну кількість цифр.

## Як вести нотатки

Короткі рядки з фактами, щоб потім легко оформити баги. Наприклад, нотатки з сесії на **іншому** сайті:

```text
10:05  Search "phone" → 4 results incl. "Phone Case" (accessory) → by name, OK
10:09  Min = Max = 2999 → exactly 1 product → OK
10:12  Search "%" → 500 error page ?!  → BUG? retry → reproducible
10:15  Question: should Clear filters reset sort too? Requirement says "everything" → yes
```

## Від нотаток до баг-репортів

Кожен рядок з «BUG?» перевір ще раз (відтворюється стабільно?), звуз умову (тільки з цим фільтром? тільки на цій межі?) і оформи окремий репорт.

## Підсумок

- Exploratory testing = навчання + дизайн + виконання одночасно, але з charter'ом і time-box'ом.
- Charter: *Explore … with … to discover …*.
- Для пошуку: регістр, пробіли, межі цін, комбінації, сортування всього списку, лічильник, скидання.
- Нотатки під час сесії → перевірка → окремі баг-репорти.
