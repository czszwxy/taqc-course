# Модулі, імпорти і стандартна бібліотека

Тестовий проєкт швидко виростає з одного файлу: хелпери для грошей і дат, білдери даних, клієнт API. **Модуль** — це просто `.py`-файл, а `import` дозволяє використати його код в іншому файлі.

## import

Нехай поруч з тестами лежить `money.py`:

```python
# money.py
CURRENCY = "UAH"

def format_uah(amount):
    return f"{amount:,}".replace(",", " ") + " " + CURRENCY
```

Три способи імпорту:

```python
import money
money.format_uah(1200)              # '1 200 UAH' — через ім'я модуля

from money import format_uah, CURRENCY
format_uah(1200)                    # напряму

import money as m                   # коротке ім'я (так роблять: import datetime as dt)
```

`from money import *` імпортує все підряд — так не роби: незрозуміло, звідки береться ім'я.

## Розбір: що відбувається під час import

| Крок | Що робить Python |
|---|---|
| 1 | Шукає `money.py`: спершу в папці запущеного скрипта, потім у стандартній бібліотеці й встановлених пакетах (`sys.path`) |
| 2 | **Виконує** весь файл згори донизу — створює функції й змінні модуля |
| 3 | Запам'ятовує модуль (`sys.modules`): повторний `import money` в іншому файлі не виконує його вдруге |
| 4 | Додає ім'я `money` (або імпортовані імена) у поточний файл |

Звідси два наслідки: код на верхньому рівні модуля (наприклад, `print`) виконується при імпорті, і файл тесту `random.py` або `json.py` у твоєму проєкті «перекриє» стандартний модуль — `import random` раптом завантажить твій файл.

## if __name__ == "__main__"

Код, який має працювати лише при прямому запуску файлу, ховають під умову:

```python
def format_uah(amount): ...

if __name__ == "__main__":
    print(format_uah(1200))     # лише при `python money.py`, не при import
```

## Пакети

Папка з модулями — **пакет**: `from helpers.money import format_uah`. Традиційно в такій папці лежить `__init__.py` (може бути порожнім). Структуру тестового проєкту з пакетами ти зробиш у модулі OOP, Files & Project Setup.

## Стандартна бібліотека

Python постачається «з батарейками» — багато модулів доступні без встановлення:

| Модуль | Для чого в тестах |
|---|---|
| `datetime` | дати доставки, терміни дії, «вчора / через тиждень» |
| `random` | випадкові тестові дані (з `seed` — відтворювані) |
| `string` | набори символів: `ascii_lowercase`, `digits` |
| `json` | розбір і створення JSON (модуль Python Collections) |
| `collections` | `Counter` для підрахунку, `defaultdict` |
| `math` | `ceil`, `isclose` для чисел з комою |
| `re` | регулярні вирази: перевірка формату |
| `time` | `time.sleep`, вимір тривалості |

### datetime

```python
from datetime import date, timedelta

today = date(2026, 11, 13)
today.isoformat()                    # '2026-11-13'
date.fromisoformat("2026-12-31")     # рядок → дата
today + timedelta(days=30)           # date(2026, 12, 13)
today - timedelta(weeks=1)           # date(2026, 11, 6)
today.weekday()                      # 4 — п'ятниця (понеділок = 0)
```

Арифметика дат сама враховує різну довжину місяців, високосні роки й перехід року.

> [!QA]
> Дати — улюблене місце багів: кінець місяця, 29 лютого, перехід року, часові пояси. Обчислюй очікувані дати через `datetime`, а не вручну рядками — тоді тест сам правильно перейде з 31 грудня на 1 січня. І завжди додавай ці межові дати в тестові дані.

### random і seed

```python
import random

rng = random.Random(42)        # власний генератор із seed
rng.randint(1, 100)            # те саме число при кожному запуску з seed 42
rng.choice(["mouse", "cable"])
```

Випадкові дані знаходять несподівані баги, але тест, що впав на «випадковому» значенні, треба вміти **повторити**. Тому seed фіксують і пишуть у лог. Власний `random.Random(seed)` краще за `random.seed(...)`: він не змінює спільний генератор, яким користуються інші тести.

## Типові помилки

- Файл проєкту з назвою стандартного модуля (`random.py`, `json.py`, `test.py`) — дивні `AttributeError` при імпорті.
- `import money`, а потім `format_uah(...)` без префікса — `NameError`; або `money.format_uah(...)`, або `from money import format_uah`.
- `from x import *` — імена перекривають одне одне, і незрозуміло, звідки що взялося.
- Код на верхньому рівні модуля (запити, `print`) виконується **при кожному імпорті** — ховай його під `if __name__ == "__main__":`.

## Підсумок

- Модуль = `.py`-файл; `import x`, `from x import y`, `import x as z`; без `import *`.
- Імпорт виконує файл один раз і кешує модуль; не називай свої файли як стандартні модулі.
- Код під `if __name__ == "__main__":` не виконується при імпорті.
- `datetime` + `timedelta` — арифметика дат з правильними межами місяців і років.
- `random.Random(seed)` — відтворювані випадкові дані без впливу на інші тести.
