# Ітератори і генератори

Цикл `for` працює зі списками, рядками, словниками, файлами, `range`, `zip`… Усе це **iterable** — об'єкти, які вміють віддавати елементи по одному. У цьому уроці — як це влаштовано і як писати власні «джерела даних» через `yield`. Це безпосередньо знадобиться у pytest: fixtures з `yield`.

## iter() і next()

```python
statuses = ["created", "paid"]
it = iter(statuses)      # ітератор — «курсор» по колекції
next(it)                 # 'created'
next(it)                 # 'paid'
next(it)                 # StopIteration — елементи скінчились
```

`for` робить саме це: бере `iter(...)`, викликає `next(...)`, доки не прийде `StopIteration`.

## Ітератор вичерпується

```python
codes = map(int, ["200", "404"])
list(codes)              # [200, 404]
list(codes)              # [] — другий прохід порожній!
```

`map`, `filter`, `zip`, генератори — **одноразові**. Список можна пройти скільки завгодно разів, ітератор — один.

> [!WARNING]
> Класичний «зелений» баг у тестах: результат `filter(...)` спершу вивели в лог, а потім перевірили `assert all(...)` по ньому ж — другий прохід порожній, а `all` на порожньому — `True`. Якщо потрібно пройти дані двічі — перетвори на `list(...)`.

## Генератори: yield

Функція з `yield` — **функція-генератор**. Виклик не виконує тіло, а повертає генератор; тіло виконується по шматочку на кожен `next()`, зупиняючись на `yield`:

```python
def countdown(n):
    while n > 0:
        yield n           # віддати значення і «заснути» тут
        n -= 1

gen = countdown(3)        # тіло ще не почало виконуватись
next(gen)                 # 3
list(gen)                 # [2, 1] — продовжує з місця зупинки
```

## Лінощі — це перевага

Генератор обчислює значення **на вимогу**. Це дозволяє:

- читати лог на 2 ГБ рядок за рядком, не завантажуючи весь у пам'ять;
- описати **нескінченне** джерело даних і брати з нього скільки потрібно.

```python
from itertools import islice

def order_ids(start):
    while True:
        yield start
        start += 1

list(islice(order_ids(2001), 3))     # [2001, 2002, 2003]
```

`list(order_ids(2001))` ніколи б не завершився — з нескінченного генератора беруть через `next()` або `islice`.

## Генераторні вирази

Comprehension у круглих дужках — генератор:

```python
total = sum(item["price"] * item["qty"] for item in items)   # без проміжного списку
```

Ти вже використовував їх з `sum`, `any`, `all`.

## itertools — коротко

| Функція | Що робить |
|---|---|
| `count(start)` | 2001, 2002, 2003… нескінченно |
| `islice(it, n)` | перші `n` елементів |
| `cycle(items)` | по колу: chrome, firefox, chrome… |
| `chain(a, b)` | спершу `a`, потім `b` |

## yield у pytest fixtures

У pytest генератори — основа **fixtures** (модуль про pytest розбере їх детально):

```python
@pytest.fixture
def user(api):
    user = api.create_user()       # setup — до тесту
    yield user                     # тест отримує user
    api.delete_user(user["id"])    # teardown — після тесту, навіть якщо він упав
```

> [!QA]
> Код до `yield` — підготовка, код після — прибирання. Завдяки генератору setup і teardown одного ресурсу лежать поруч, і тестові дані не «засмічують» середовище.

## Підсумок

- Iterable віддає ітератор (`iter`), ітератор — елементи (`next`), кінець — `StopIteration`.
- Ітератори (`map`, `filter`, `zip`, генератори) одноразові; для повторного проходу — `list(...)`.
- `yield` робить функцію генератором: значення обчислюються на вимогу.
- З нескінченних генераторів беруть `next()` або `islice`.
- Fixture з `yield`: до — setup, після — teardown.
