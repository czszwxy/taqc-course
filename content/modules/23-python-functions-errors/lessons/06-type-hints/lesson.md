# Type hints

Ти вже бачив у задачах сигнатури на зразок `def slowest(results: list[tuple[str, str, float]]) -> str:`. Це **анотації типів** (type hints): вони описують, що функція приймає і що повертає.

> [!IMPORTANT]
> Python **не перевіряє** анотації під час виконання. `def f(x: int)` спокійно прийме рядок. Перевіряють їх інструменти **до** запуску: редактор (Pylance у VS Code), `mypy`, `pyright`. Якщо знаєш TypeScript — ідея та сама, але без компілятора, який блокує запуск.

## Синтаксис

```python
def discount(price: int, percent: float) -> int:     # параметри і результат
    return round(price * (1 - percent))

retries: int = 3                                      # змінна
```

## Типи, які трапляються найчастіше

| Анотація | Значення |
|---|---|
| `int`, `float`, `str`, `bool` | прості значення; `float` приймає і `int` |
| `list[str]` | список рядків |
| `dict[str, int]` | словник: ключі-рядки, значення-числа |
| `set[int]` | множина чисел |
| `tuple[str, float]` | кортеж рівно з двох елементів: рядок і число |
| `tuple[int, ...]` | кортеж будь-якої довжини з чисел |
| `list[dict[str, int]]` | список словників — типова відповідь API |
| `str \| None` | рядок або `None` (старий запис — `Optional[str]`) |
| `-> None` | функція нічого не повертає |

Вкладеність читається зсередини назовні: `list[dict[str, int]]` — «список, елементи якого — словники з ключами-рядками і значеннями-числами».

## Розбір: читаємо сигнатуру вголос

```python
def find_user(users: list[dict], email: str, active_only: bool = True) -> dict | None:
```

| Частина | Як прочитати |
|---|---|
| `users: list[dict]` | список словників-користувачів |
| `email: str` | рядок |
| `active_only: bool = True` | прапорець, за замовчуванням `True` |
| `-> dict \| None` | повертає словник користувача **або** `None`, якщо не знайдено |

З такою сигнатурою не треба відкривати код функції, щоб правильно її викликати, — і редактор попередить, якщо після виклику забути перевірити результат на `None`.

## Значення, якого може не бути

`def send(report: str, cc: str = None)` — помилка для type checker: `None` — не рядок. Якщо параметр може бути `None`, це треба сказати явно: `cc: str | None = None`.

## Функції як параметри

```python
from collections.abc import Callable

def count_matching(values: list[int], condition: Callable[[int], bool]) -> int:
    ...
```

`Callable[[int], bool]` — «функція, що приймає число і повертає bool».

## Any

`Any` (з `typing`) означає «що завгодно» і **вимикає** перевірки для цього значення. Інколи він потрібен, але кожен `Any` — місце, де type checker тобі вже не допоможе.

## Що це дає на практиці

1. **Автодоповнення.** Редактор знає тип і підказує методи. У тестах Playwright для Python пишуть `def test_login(page: Page):` — і після `page.` бачать `goto`, `get_by_role`, `fill`…
2. **Помилки до запуску.** `discount("450", 0.1)` підкреслиться червоним ще в редакторі.
3. **Документація.** Сигнатура одразу каже, що передати і що отримати.

> [!QA]
> Type checker у CI — найдешевші «тести»: за секунди знаходить виклики з неправильними аргументами в усьому фреймворку, ще до запуску браузера. А тип відповіді API (наприклад, через `TypedDict`) робить очевидним, які поля тест очікує.

## Перевірити анотації з коду

Анотації зберігаються у функції, і їх можна прочитати — так це роблять бібліотеки (і перевірки в цьому курсі):

```python
from typing import get_type_hints
get_type_hints(discount)    # {'price': int, 'percent': float, 'return': int}
```

## Типові помилки

- `x: str = None` — для type checker це суперечність; правильно `x: str | None = None`.
- `def f(limit: 5)` — в анотації пишуть **тип**, а не значення: `limit: int = 5`.
- Анотація є, але не відповідає коду (`-> int`, а функція повертає рядок) — Python мовчить, але type checker і колеги будуть введені в оману.
- `list` без типу елементів працює, але каже менше, ніж `list[str]`.

## Підсумок

- Анотації: `param: Тип`, `-> Тип`, `змінна: Тип = значення`.
- Колекції з типами елементів: `list[str]`, `dict[str, int]`, `tuple[str, float]`, `set[int]`.
- Може бути `None` — `X | None`; нічого не повертає — `-> None`; функція — `Callable[[аргументи], результат]`.
- Python не перевіряє типи під час виконання — це роблять редактор, mypy і pyright.
- `Any` вимикає перевірки — використовуй рідко.
