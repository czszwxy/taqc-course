# Область видимості і замикання

**Область видимості** (scope) — де в коді «видно» змінну. Розуміння цього рятує від двох типових проблем у тестах: «змінна раптом не та» і «тести впливають один на одного через глобальний стан».

## Локальні і глобальні змінні

```python
BASE_URL = "https://api.example.test"      # глобальна (рівень модуля)

def orders_url():
    path = "/orders"                       # локальна — існує лише під час виклику
    return BASE_URL + path                 # глобальну можна ЧИТАТИ

orders_url()
print(path)                                # NameError: name 'path' is not defined
```

## Правило LEGB

Шукаючи ім'я, Python перевіряє області по черзі: **L**ocal (функція) → **E**nclosing (зовнішня функція) → **G**lobal (модуль) → **B**uilt-in (`len`, `print`…). Перше знайдене — і використовується.

> [!WARNING]
> Не називай змінні як вбудовані функції: після `list = [1, 2]` або `max = 10` виклик `list(...)` / `max(...)` у цьому модулі зламається — Python знайде твою змінну раніше за built-in.

## Присвоєння робить змінну локальною

```python
counter = 0

def increment():
    counter += 1      # UnboundLocalError!
```

Через присвоєння Python вважає `counter` **локальною** для всієї функції, а локальна ще не має значення. Можна написати `global counter`, але в тестовому коді глобальний стан, який змінюють функції, — шлях до тестів, що залежать від порядку запуску. Краще повертати значення або використати замикання.

## Функція всередині функції

```python
def make_limit_check(limit):
    def check(value):
        return value <= limit       # limit — з зовнішньої функції (Enclosing)
    return check                    # повертаємо саму функцію, без ()

fast_enough = make_limit_check(500)
fast_enough(320)                    # True
fast_enough(800)                    # False
```

`make_limit_check` — **фабрика функцій**: створює нові функції з налаштуванням.

## Замикання (closure)

Функція `check` «пам'ятає» `limit` навіть після того, як `make_limit_check` завершилась. Таку функцію разом із запам'ятованими змінними називають **замиканням**. Кожен виклик фабрики створює окреме замикання:

```python
api_check = make_limit_check(500)
page_check = make_limit_check(3000)    # свій limit, незалежний від api_check
```

## nonlocal — змінити змінну зовнішньої функції

Читати змінну з Enclosing можна просто так, а **змінити** — лише після `nonlocal`:

```python
def make_counter():
    count = 0
    def next_number():
        nonlocal count
        count += 1
        return count
    return next_number

next_id = make_counter()
next_id(), next_id(), next_id()        # (1, 2, 3)
```

> [!QA]
> Замикання з лічильником — простий генератор **унікальних тестових даних**: `user1@test.dev`, `user2@test.dev`… Тести, що реєструють користувачів, не конфліктують між собою, а кожна фабрика має свій лічильник — без глобальних змінних.

## Підсумок

- Локальні змінні живуть лише під час виклику; глобальні можна читати звідусіль.
- LEGB: Local → Enclosing → Global → Built-in. Не перекривай `list`, `max`, `id`.
- Присвоєння всередині функції робить змінну локальною; `global` — краще уникати.
- Функція може повертати функцію — фабрика функцій.
- Замикання пам'ятає змінні зовнішньої функції; `nonlocal` — щоб їх змінювати.
