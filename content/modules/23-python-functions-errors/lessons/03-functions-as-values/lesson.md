# Функції як значення

У Python функція — такий самий об'єкт, як число чи рядок: її можна покласти в змінну, у словник, передати в іншу функцію або повернути (ти вже робив це у фабриках). На цьому побудовані `sorted(key=...)`, хелпери очікування в Playwright і повтори нестабільних кроків.

```python
def is_ok(status):
    return status == 200

check = is_ok          # без дужок — сама функція
check(200)             # True
```

## Передати функцію в функцію

Функцію, яку передають як аргумент, часто називають **callback**:

```python
def count_matching(values, condition):
    count = 0
    for v in values:
        if condition(v):
            count += 1
    return count

count_matching([200, 404, 500], is_ok)                  # 1
count_matching([200, 404, 500], lambda s: s >= 400)     # 2
```

`lambda` (з модуля Python Collections) — зручний спосіб передати коротку умову на місці.

## Розбір: хто кого викликає

Простежимо `count_matching([200, 404], is_ok)`:

| Крок | Що відбувається |
|---|---|
| 1 | `count_matching` отримує список і **саму функцію** `is_ok` у параметр `condition` |
| 2 | Перша ітерація: `condition(200)` — насправді викликається `is_ok(200)` → `True`, `count = 1` |
| 3 | Друга ітерація: `condition(404)` → `is_ok(404)` → `False` |
| 4 | Повертається `1` |

`count_matching` не знає, **яку** умову перевіряє, — вона лише викликає те, що їй передали. Саме тому одну функцію можна використати з будь-якою умовою.

## Набір перевірок

Функції можна тримати в колекціях. Наприклад, правила для пароля:

```python
PASSWORD_RULES = [
    lambda p: len(p) >= 8,
    lambda p: any(ch.isdigit() for ch in p),
    lambda p: p.lower() != p,          # є велика літера
]

all(rule("Secret123") for rule in PASSWORD_RULES)     # True
all(rule("secret") for rule in PASSWORD_RULES)        # False
```

Додати нове правило — додати рядок у список, а код перевірки не змінюється. Якщо правилам дати назви (ключі словника), можна ще й повідомити, **яке** саме правило не пройшло.

## Retry і polling

Два хелпери, які є майже в кожному фреймворку:

- **retry** — викликати дію повторно, доки вона не вдасться, але не більше N разів;
- **polling** — опитувати стан («статус замовлення став `paid`?»), доки він не стане очікуваним.

Обидва приймають **функцію** — дію або перевірку — і самі вирішують, скільки разів її викликати. Playwright робить polling сам (`expect(...)` повторює перевірку до таймауту), а в API-тестах такі хелпери часто пишуть вручну.

> [!QA]
> `retry` лікує симптом, а не причину. Повторювати можна **очікування** (сервер ще обробляє замовлення), але не можна «повторювати, доки тест не пройде»: так ховаються справжні баги. Кожен retry у тесті має мати пояснення, чому стан з'являється не одразу.

## map і filter

`map(функція, колекція)` застосовує функцію до кожного елемента, `filter(функція, колекція)` залишає ті, для яких функція повертає істину. Обидві повертають **ледачий** об'єкт — щоб побачити результат, загорни в `list()`:

```python
codes = ["200", "404", "500"]
list(map(int, codes))                          # [200, 404, 500]
list(filter(lambda c: c >= 400, map(int, codes)))   # [404, 500]
list(map(str.upper, ["get", "post"]))          # ['GET', 'POST']
```

Те саме через comprehension: `[int(c) for c in codes]`. Обирай те, що читається краще: `map(int, items)` — коротко, бо функція вже готова; з `lambda` comprehension зазвичай зрозуміліший.

## any і all — коротко

Ти знаєш їх з модуля Python Collections: `any(...)` — хоч один, `all(...)` — усі, і `all` на порожній колекції — `True`. З функціями-перевірками вони поєднуються природно — як у прикладі з правилами пароля.

## Типові помилки

- `count_matching(codes, is_ok())` — дужки викликають функцію **зараз** (і падають без аргументу), а треба передати саму функцію: `is_ok`.
- `print(map(int, codes))` друкує `<map object ...>` — потрібен `list(...)`.
- Ледачий `map` / `filter` вичерпується: другий `list(...)` від того самого об'єкта дасть `[]`.
- `lambda` для складної логіки — нечитабельна; для кількох рядків пиши звичайну функцію через `def`.

## Підсумок

- Функція — значення: її можна присвоїти, передати, повернути, покласти в список чи словник.
- Callback — функція-аргумент; та, що приймає callback, сама вирішує, коли й скільки разів його викликати.
- Набір перевірок у колекції: нове правило = новий рядок.
- `retry` / `polling` — для очікування стану, а не для приховування багів.
- `map` / `filter` повертають ледачі одноразові об'єкти — `list(...)`.
