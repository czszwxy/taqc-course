# Семафори, блокування і черги

`gather` на тисячу адрес запустить тисячу запитів одночасно. Партнер у відповідь поверне `429 Too Many Requests` або просто ляже. Тож конкурентністю треба **керувати**: обмежувати, черговати, синхронізувати.

Приклад — краулер, що обходить сторінки партнерських сайтів і розсилає листи.

## Semaphore: не більше N одночасно

```python
async def crawl(urls, limit=10):
    gate = asyncio.Semaphore(limit)

    async def crawl_one(url):
        async with gate:                      # чекає, поки звільниться одне з 10 «місць»
            return await fetch_page(url)

    return await asyncio.gather(*(crawl_one(url) for url in urls))
```

Усі задачі створені одразу, але **всередині** `async with gate` одночасно лише `limit` штук. Решта чекає на вході й заходить, щойно хтось вийде.

## Lock: коли між читанням і записом є await

В одному потоці гонки менш часті, ніж з потоками, але **на кожному `await` інша корутина може змінити дані**:

```python
token = None
token_lock = asyncio.Lock()

async def get_token():
    global token
    async with token_lock:                    # лише одна корутина оновлює токен
        if token is None or token.expired:
            token = await auth.refresh()      # ← тут без Lock інші теж почали б оновлення
    return token
```

Без `Lock` десять запитів, що одночасно помітили прострочений токен, зробили б десять оновлень. Правило: якщо між «перевірив» і «записав» є `await`, потрібен `Lock`.

## Queue: виробник і воркери

```python
async def send_newsletter(emails, workers=3):
    queue = asyncio.Queue()
    for email in emails:
        queue.put_nowait(email)

    async def worker():
        while True:
            email = await queue.get()
            try:
                await send_email(email)
            finally:
                queue.task_done()             # позначити елемент обробленим — навіть після помилки

    tasks = [asyncio.create_task(worker()) for _ in range(workers)]
    await queue.join()                        # чекати, поки кожен елемент отримає task_done
    for task in tasks:
        task.cancel()                         # воркери нескінченні — зупинити
    await asyncio.gather(*tasks, return_exceptions=True)   # дочекатися, поки справді зупиняться
```

- `put` / `get` — додати / взяти (порожня черга — `get` чекає).
- `task_done()` на **кожен** `get`, `join()` чекає на всі.
- Воркерів зупиняють `cancel()` (і чекають на них) або «сигнальним» елементом, наприклад `None`.
- Черга з `maxsize` пригальмовує виробника, якщо воркери не встигають (backpressure).

## Event: «можна починати»

```python
cache_ready = asyncio.Event()

async def worker():
    await cache_ready.wait()                  # усі воркери чекають
    ...

await warm_up_cache()
cache_ready.set()                             # і одночасно стартують
```

## Що обрати

| Потрібно | Інструмент |
|---|---|
| не більше N одночасних операцій | `Semaphore(N)` |
| лише одна корутина в критичній секції | `Lock` |
| передавати роботу між виробниками й воркерами | `Queue` |
| повідомити всіх, що подія сталася | `Event` |

## Типові помилки

| Помилка | Наслідок |
|---|---|
| `gather` на тисячі адрес без обмеження | `429`, бан від партнера, вичерпані з'єднання |
| `Semaphore` створено **всередині** функції для одного запиту | у кожного свій семафор — обмеження немає |
| Забутий `task_done()` | `join()` чекає вічно |
| Воркери не зупинені після `join()` | «висять» фонові задачі |
| Перевірка й запис через `await` без `Lock` | подвійні оновлення, втрачені зміни |

> [!QA]
> Обмеження перевіряють тим самим лічильником одночасних викликів: з `limit=3` пік у фейку має бути **рівно** 3 (не 1 — інакше код послідовний, і не 10 — інакше обмеження не працює). Для черг — що кожен елемент оброблено рівно один раз і що після завершення не лишилося фонових задач.

## Підсумок

- `Semaphore(N)` + `async with` — не більше N одночасних операцій; один семафор на всі задачі.
- `Lock` — коли між перевіркою й записом спільних даних є `await`.
- `Queue` + воркери: `get` → робота → `task_done()`; `join()`; потім зупинити воркерів і дочекатися їх.
- `Event` — один сигнал для всіх, хто чекає.
