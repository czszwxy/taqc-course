# Тайм-аути, скасування і повтори

Мережа іноді не відповідає. Без тайм-ауту корутина чекатиме вічно, а з нею — запит користувача, з'єднання й пам'ять. Тому кожне очікування на зовнішній сервіс має межу, а код має вміти коректно **зупинитися**: звільнити бронь, закрити з'єднання.

Приклад — сервіс бронювання квитків, що питає погоду в партнера:

## Тайм-аут

```python
async def forecast_or_none(city: str) -> str | None:
    try:
        async with asyncio.timeout(2):          # Python 3.11+
            return await partner.forecast(city)
    except TimeoutError:
        return None                             # показати сторінку без прогнозу
```

- `asyncio.timeout(секунди)` — контекстний менеджер: якщо блок не встиг, внутрішню операцію **скасовують**, а назовні вилітає вбудований `TimeoutError`.
- Старіший варіант — `await asyncio.wait_for(partner.forecast(city), timeout=2)`, поведінка та сама.
- Лови саме `TimeoutError`. `except Exception: return None` «проковтне» і справжні баги — `KeyError`, помилку авторизації.

## Скасування

```python
task = asyncio.create_task(sync_bookings())
...
task.cancel()                     # попросити зупинитися
```

`cancel()` не вбиває задачу миттєво: на **найближчому** `await` всередині неї вилітає `asyncio.CancelledError`. Задача може прибрати за собою — і має пропустити виняток далі:

```python
async def hold_seat(booking):
    seat = await booking.reserve()
    try:
        return await booking.pay()
    except BaseException:                 # і помилка оплати, і скасування
        await booking.release(seat)       # звільнити місце
        raise                             # ❗ передати виняток далі
```

> [!IMPORTANT]
> `CancelledError` — нащадок `BaseException`, **не** `Exception`. `except Exception:` його не ловить — і прибирання не виконається. А «проковтнути» скасування (`except CancelledError: pass`) теж не можна: тайм-аути, `TaskGroup` і зупинка сервера покладаються на те, що скасована задача справді завершиться.

Прибирання найчастіше пишуть через `try/finally` або `async with` — вони спрацюють за будь-якого виходу: успіх, помилка, скасування.

## Повтори з затримкою

Частина помилок тимчасові: партнер перевантажений (`503`), мережа «моргнула». Їх варто повторити — але не одразу й не нескінченно:

```python
async def with_retries(call, attempts=3, delays=(0.5, 1.0), sleep=asyncio.sleep):
    for attempt in range(attempts):
        try:
            return await call()
        except TemporaryOutage:
            if attempt == attempts - 1:
                raise                                   # спроби скінчились — помилка летить далі
            await sleep(delays[min(attempt, len(delays) - 1)])
```

- Повторюй лише **тимчасові** помилки; «невірний пароль» повторювати безглуздо.
- Затримки ростуть (backoff), щоб не добивати перевантажений сервіс; у продакшні додають випадковий розкид (jitter).
- Обмежуй кількість спроб.
- `sleep` передано **параметром**: у тесті підставляють фейк, що лише записує затримки, — тест не чекає реальні секунди.

## Типові помилки

| Помилка | Наслідок |
|---|---|
| Немає тайм-ауту на зовнішній виклик | один «завислий» партнер тримає всі запити |
| `except Exception` для прибирання | при скасуванні бронь не звільняється |
| `except CancelledError: pass` | задачу неможливо зупинити, `TaskGroup` і тайм-аути працюють неправильно |
| Повтор будь-якої помилки | повторюєш баги й «невірний пароль», множиш навантаження |
| `await asyncio.sleep(...)` у тестах повторів | тести тривають секунди; підстав фейковий `sleep` |

> [!QA]
> Тайм-аути й скасування тестують на швидких фейках: сервіс, що «спить» 0.5 с, і тайм-аут 0.05 с. Перевіряй не лише відповідь (`None`), а й **наслідки**: повільний виклик справді скасовано, бронь звільнено, задача завершилася як скасована (`task.cancelled()`).

## Підсумок

- `async with asyncio.timeout(с)` / `wait_for` — межа очікування; назовні `TimeoutError`, усередині — скасування.
- Скасування — це `CancelledError` на найближчому `await`; прибирай у `finally` / `except BaseException` і передавай далі.
- `except Exception` не ловить `CancelledError`.
- Повтори — лише для тимчасових помилок, з обмеженням і зростаючою затримкою; `sleep` як параметр робить тести миттєвими.
