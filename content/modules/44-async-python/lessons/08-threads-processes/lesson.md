# Потоки, процеси чи asyncio?

asyncio — не єдиний спосіб робити кілька справ разом. Python має ще **потоки** і **процеси**, і кожен інструмент найкращий для свого типу роботи. Приклад — сервіс фотогалереї: завантажує фото з партнерів, створює мініатюри, шле листи.

## Два типи роботи

| Тип | Що відбувається | Приклади |
|---|---|---|
| **I/O-bound** | програма чекає на мережу, диск, базу | запити до API, листи, читання файлів |
| **CPU-bound** | процесор зайнятий обчисленнями | зміна розміру фото, хешування, складні розрахунки |

## GIL

У звичайному CPython діє **GIL** (Global Interpreter Lock): у кожен момент Python-код виконує лише один потік процесу. Тому:

- для **I/O** потоки працюють добре: поки потік чекає на мережу, GIL вільний, і виконуються інші;
- для **обчислень** потоки не пришвидшують — вони по черзі ділять одне ядро. Потрібні **процеси**: у кожного свій інтерпретатор і свій GIL.

> [!NOTE]
> Python 3.13 має експериментальну збірку без GIL (free-threaded, `python3.13t`). Вона ще не стандарт, і більшість бібліотек розраховані на звичайний CPython, тож правила вище поки що чинні.

## Потоки: блокувальні бібліотеки

```python
from concurrent.futures import ThreadPoolExecutor

with ThreadPoolExecutor(max_workers=8) as pool:
    pages = list(pool.map(download_page, urls))     # download_page користується requests
```

У асинхронному коді блокувальний виклик відправляють у потік через `asyncio.to_thread`:

```python
async def thumbnail_urls(photo_ids):
    gate = asyncio.Semaphore(4)                          # не більше 4 потоків одночасно

    async def one(photo_id):
        async with gate:
            return await asyncio.to_thread(legacy_storage.signed_url, photo_id)

    return await asyncio.gather(*(one(p) for p in photo_ids))
```

Цикл подій лишається вільним: поки потоки чекають на старе сховище, сервер обслуговує інші запити.

## Процеси: обчислення

```python
from concurrent.futures import ProcessPoolExecutor

def make_thumbnail(image: bytes) -> bytes:           # функція на рівні модуля
    ...

if __name__ == "__main__":
    with ProcessPoolExecutor(max_workers=4) as pool:
        thumbnails = list(pool.map(make_thumbnail, images))
```

- Аргументи й результати передаються між процесами через **pickle** — функція має бути на рівні модуля (не lambda, не вкладена), дані — серіалізовані. Пересилати гігабайти туди-сюди дорого.
- На Windows (і в macOS за замовчуванням) процеси стартують способом **spawn**: дочірній процес заново імпортує твій модуль. Код, що створює пул у скрипті, ховають під `if __name__ == "__main__":`, інакше кожен процес почне створювати нові процеси.
- Запуск процесу — це десятки чи сотні мілісекунд: для дрібних задач процеси повільніші за звичайний цикл.

З asyncio: `await loop.run_in_executor(process_pool, make_thumbnail, image)`.

## Як обрати

| Робота | Інструмент |
|---|---|
| багато одночасних мережевих запитів, тисячі з'єднань | **asyncio** |
| блокувальна бібліотека (старий SDK, `requests`) | **потоки** (`ThreadPoolExecutor`, `asyncio.to_thread`) |
| важкі обчислення, які можна розбити | **процеси** (`ProcessPoolExecutor`) |
| кілька швидких операцій у скрипті | звичайний код — паралельність лише ускладнить |

## Типові помилки

| Помилка | Наслідок |
|---|---|
| Потоки для обчислень у звичайному CPython | не швидше (GIL), іноді повільніше |
| Процеси для дрібних задач | запуск і pickle «з'їдають» увесь виграш |
| lambda чи вкладена функція в `ProcessPoolExecutor` | `PicklingError` |
| Пул процесів без `if __name__ == "__main__"` на Windows | процеси плодять процеси, помилка `RuntimeError` про bootstrapping |
| Спільна змінна між процесами | у кожного процесу своя пам'ять — зміни не видно |

> [!QA]
> Конкурентність ускладнює відтворення багів: гонки, взаємні блокування, «іноді не той порядок». Чим простіша модель (звичайний код → asyncio → потоки → процеси), тим легше її тестувати. Тому спершу доводять вимірюванням, що паралельність потрібна, і лише потім її додають.

## Підсумок

- I/O-bound — asyncio або потоки; CPU-bound — процеси.
- GIL: один потік виконує Python-код за раз; очікування I/O його звільняє.
- `asyncio.to_thread` — блокувальний виклик з async-коду без блокування циклу.
- `ProcessPoolExecutor`: функції на рівні модуля, pickle, `if __name__ == "__main__"` для spawn.
- Найпростіша модель, що розв'язує задачу, — найкраща.
