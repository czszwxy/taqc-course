# Резюме, LinkedIn і GitHub

Рекрутер дивиться на резюме **15–30 секунд**. За цей час він має побачити: хто ти (Trainee QA Automation), що вмієш (TypeScript, Playwright, тест-дизайн, SQL, API) і **доказ**, тобто проєкти з посиланнями. Без комерційного досвіду проєкти і GitHub і є твоїм досвідом.

## Структура резюме (1 сторінка, англійською)

1. **Ім'я + посада**: `Trainee / Junior QA Automation Engineer`, місто або remote, контакти, LinkedIn, GitHub.
2. **Summary** (2–3 речення): хто ти, що вмієш, що шукаєш.
3. **Skills** — групами: Testing (test design, test cases, bug reports, API testing), Automation (TypeScript, Playwright, Page Object), Tools (Git, GitHub Actions, DevTools, Postman, SQL).
4. **Projects** — 2–3 проєкти з посиланнями й пунктами.
5. **Experience** — попередня робота, навіть не з IT. Підкресли переносні навички: уважність, комунікація, процеси.
6. **Education / Courses**, **Languages** (рівень англійської чесно, наприклад B1).

## Сильний пункт = дія + що + інструмент + результат

| Слабко | Сильно |
|---|---|
| Responsible for testing | Designed 40 test cases for a demo shop checkout using EP and BVA |
| Knowledge of Playwright | Automated 30 UI and API tests with Playwright + TypeScript (Page Objects, fixtures) |
| Found bugs | Reported 15 bugs with steps, severity and evidence; 3 of them critical |
| Worked with CI | Set up GitHub Actions: smoke on every PR, full run nightly, HTML report as an artifact |

> [!WARNING]
> Ніколи не вигадуй досвід, компанії чи рівень. На співбесіді про кожен рядок резюме можуть спитати «розкажи детальніше». Чесне «навчальний проєкт» звучить краще за вигадку, що розвалюється на другому питанні.

## Чого уникати

- фото, дата народження, сімейний стан, повна адреса (не потрібні і не мають впливати);
- «відповідальний, комунікабельний, стресостійкий» без доказів;
- список із 30 технологій, з якими ти «знайомився»;
- друкарські помилки (для QA це особливо промовисто);
- 3 сторінки і дрібний шрифт.

> [!TIP]
> Підлаштовуй резюме під вакансію: якщо в ній «API testing, Postman, SQL», ці слова мають бути в Skills і в проєктах (якщо це правда). Багато компаній фільтрують резюме за ключовими словами (ATS).

## LinkedIn

- **Headline**: не «Looking for job», а `Trainee QA Automation Engineer | TypeScript · Playwright · API testing`.
- **About**: 3–5 речень, як summary, плюс посилання на GitHub.
- **Open to work**: увімкни (можна видимим лише рекрутерам).
- **Skills**: Playwright, TypeScript, Test Design, API Testing, SQL, Git.
- **Активність**: короткі пости «що я дізнався» про тест-дизайн, flaky-тести чи свій проєкт. Рекрутери це помічають.

## GitHub як портфоліо

- **Закріпи (pin)** 2–3 найкращі репозиторії: фінальний проєкт (модуль 20), тестове завдання, міні-фреймворк.
- У кожного — **README**: що тестується, стек, як запустити, структура, скріншот звіту.
- **Зелений бейдж CI** (GitHub Actions) показує, що тести справді проходять.
- Осмислені коміти, `.gitignore`, жодних секретів і `node_modules`.
- Profile README (репозиторій з твоїм ім'ям користувача): 3–4 рядки про тебе і посилання.

> [!QA]
> Перевір свій GitHub як тестувальник: відкрий профіль у приватному вікні, склонуй проєкт і запусти за README. Рекрутер і тімлід зроблять саме це.

## Підсумок

- Резюме: 1 сторінка англійською, Summary → Skills → Projects з посиланнями → Experience → Education.
- Пункти: дія + що + інструмент + результат (з числами); жодних вигадок.
- LinkedIn: конкретний headline, About, Open to work, навички, трохи активності.
- GitHub: закріплені проєкти з README, CI-бейджем і чистою історією.
