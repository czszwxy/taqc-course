# Візуальні порівняння

Кнопка на місці, текст правильний, усі перевірки зелені, але на телефоні заголовок обрізаний, а таблиця вилазить за екран. Функціональні тести таке пропускають: вони перевіряють **що** на сторінці, а не **як** вона виглядає. Для цього є **візуальне регресійне тестування**: знімок сторінки порівнюється з еталоном.

## toHaveScreenshot

```ts
test('product page on mobile', async ({ page }) => {
  await page.setViewportSize({ width: 375, height: 800 });
  await page.goto('/playground/responsive');
  await expect(page).toHaveScreenshot('product-mobile.png', { fullPage: true });
});

// знімок одного елемента
await expect(page.getByTestId('cart-summary')).toHaveScreenshot('cart-summary.png');
```

Як це працює:

1. **Перший запуск**: еталону ще немає, тест падає і **записує** фактичний знімок як еталон (`*-snapshots/` поряд з тестом).
2. Людина переглядає еталон і **комітить** його.
3. **Наступні запуски** порівнюють новий знімок з еталоном. Різниця більша за допустиму — тест падає, а у звіті три картинки: Expected, Actual і Diff.
4. Зміна дизайну навмисна? Оновлюємо еталони: `npx playwright test --update-snapshots`, переглядаємо і комітимо.

`toHaveScreenshot` сам чекає, поки сторінка «заспокоїться» (два однакові знімки поспіль), і вимикає CSS-анімації.

## Допуск і маскування

```ts
await expect(page).toHaveScreenshot('dashboard.png', {
  maxDiffPixels: 100,                      // допустимо до 100 різних пікселів
  mask: [page.getByTestId('current-time')],// закрити динамічні частини
  fullPage: true,
});
```

Також є `threshold` (наскільки інший колір вважається різницею) і `maxDiffPixelRatio`.

## Чому візуальні тести «шумлять»

| Джерело шуму | Що робити |
|---|---|
| інша ОС / шрифти / згладжування | знімати еталони і тести в одному середовищі (часто Docker на CI) |
| дати, час, лічильники, реклама | `mask`, фіксовані тестові дані, мок відповіді |
| анімації, курсор | вимикаються за замовчуванням |
| різні розміри вікна | явно задавати `viewport` |

> [!WARNING]
> Еталони залежать від платформи: знімок з Windows не збігається з Linux на CI. Тому еталони генерують там, де йдуть тести, а локально запускають у тому самому Docker-образі.

## Коли візуальні тести доречні

- верстка на різних розмірах екрана (responsive, модуль 07);
- компоненти дизайн-системи (кнопки, картки, форми);
- сторінки, які рідко змінюються, але важливі (лендінг, чек-аут).

Не варто знімати кожну сторінку: тоді будь-яка зміна дизайну «ламає» сотні тестів.

> [!QA]
> Візуальний тест — доповнення, а не заміна. «Кнопка Add to cart видима» краще перевірити функціонально (`toBeVisible`): це точніше і стабільніше. А те, що важко описати локаторами (обрізаний текст, наїзд блоків, вилізла таблиця), ловить скріншот.

## Підсумок

- `await expect(page або locator).toHaveScreenshot('name.png', { fullPage })` порівнює знімок з еталоном.
- Перший запуск записує еталон, людина його переглядає й комітить. Навмисні зміни оновлюють через `--update-snapshots`.
- Допуск задають `maxDiffPixels` і `threshold`, динамічне закривають через `mask`, розмір — через `viewport`.
- Еталони залежать від ОС і шрифтів, тому знімай у стабільному середовищі.
- Візуальні тести доповнюють функціональні там, де важливий вигляд.
