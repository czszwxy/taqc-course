# Основи HTML

**HTML** (HyperText Markup Language) описує, **що** є на сторінці: заголовки, поля, кнопки, таблиці. Тестувальнику не потрібно верстати сайти, але треба вміти **читати** HTML: так ти знаходиш причини багів, перевіряєш доступність і пишеш стабільні селектори для автотестів.

## Елемент, тег, атрибут

```html
<button type="submit" class="btn btn-primary" data-testid="login-submit" disabled>Log in</button>
└──┬──┘ └─────────────────────── attributes ──────────────────────────┘└─ text ─┘└──┬───┘
opening tag                                                                     closing tag
```

- **Елемент** — усе разом: відкривальний тег, вміст, закривальний тег.
- **Атрибути** — додаткова інформація: `type`, `class`, `id`, `data-testid`, `disabled`.
- Деякі елементи не мають закривального тегу: `<input>`, `<img>`, `<br>`.
- Елементи вкладаються один в одного й утворюють **дерево** (про нього — в уроці про DOM).

## Структура сторінки

```html
<!DOCTYPE html>
<html lang="uk">
  <head>
    <title>Gadgetly — Login</title>   <!-- tab title, not visible on the page -->
    <link rel="stylesheet" href="styles.css">
  </head>
  <body>
    <header>…</header>
    <main>…</main>
    <footer>…</footer>
  </body>
</html>
```

## Елементи, які тестувальник бачить щодня

| Елемент | Для чого | Що перевірити |
|---|---|---|
| `<a href="…">` | посилання | куди веде `href`, чи відкривається в новій вкладці (`target="_blank"`) |
| `<button>` | дія | `type="submit"` / `"button"`, стан `disabled` |
| `<input type="…">` | поле вводу | тип: `text`, `email`, `password`, `number`, `checkbox`, `radio`, `date` |
| `<label for="id">` | підпис поля | клік по підпису ставить фокус у поле |
| `<select>` + `<option>` | випадаючий список | значення за замовчуванням, усі варіанти |
| `<form>` | група полів, що відправляється разом | відправка через Enter, валідація |
| `<img src alt>` | картинка | `alt` — текст для незрячих і коли картинка не завантажилась |
| `<table>`, `<tr>`, `<td>` | таблиця | заголовки `<th>`, порожні клітинки |

## Атрибути валідації

HTML сам уміє перевіряти поля: `required`, `maxlength="20"`, `min="18"`, `max="65"`, `type="email"`, `pattern`.

> [!WARNING]
> Валідація в HTML — лише **зручність** для користувача. Її легко прибрати через DevTools. Сервер мусить перевіряти дані сам. Тест «прибрати `maxlength` у DevTools і відправити 500 символів» часто знаходить серйозні баги.

## Семантика і доступність (a11y)

**Семантичний** HTML використовує правильні елементи за призначенням: `<button>` для кнопок, а не `<div onclick>`; `<label>` для підписів, а не `<span>`.

Це важливо, бо:

- **екранні читалки** (для незрячих) розуміють лише правильні елементи;
- кнопкою-`<button>` можна користуватися **з клавіатури** (Tab + Enter), а `<div>` — ні;
- Playwright шукає елементи **за роллю й підписом** (`getByRole('button', { name: 'Log in' })`) — з поганою семантикою такі локатори не працюють.

> [!QA]
> Атрибут `data-testid` додають спеціально для автотестів: він не змінюється, коли дизайнер міняє класи чи текст. Якщо в команді є така домовленість — проси розробників додавати `data-testid` до важливих елементів.

## Підсумок

- Елемент = теги + атрибути + вміст; елементи вкладаються в дерево.
- Найважливіші для QA: `a`, `button`, `input` (різні `type`), `label`, `select`, `form`, `img`, `table`.
- HTML-валідацію легко обійти — сервер має перевіряти дані сам.
- Семантичний HTML = доступність + клавіатура + стабільні локатори.
