# Cookies, localStorage, сесії і кеш

HTTP **не пам'ятає** попередніх запитів: кожен запит для сервера — «новий знайомий». Щоб сайт знав, що ти увійшла в акаунт, що лежить у кошику і яку тему ти обрала, дані треба десь зберігати. Тестувальник має знати **де**, бо звідси беруться баги «вийшла з акаунта, а дані залишились», «після оновлення сайту все зламалось», «у мене працює, а в колеги ні».

Практика — на сторінці [DevTools Lab](/playground/devtools), розділ «4. Application». У DevTools відкрий вкладку **Application** (у Firefox — **Storage**).

## Чотири місця зберігання

| | Cookies | localStorage | sessionStorage | Серверна сесія |
|---|---|---|---|---|
| Де живе | у браузері | у браузері | у браузері, **у вкладці** | на сервері (у браузері лише її id в cookie) |
| Надсилається на сервер | **автоматично з кожним запитом** | ні | ні | — |
| Скільки живе | до `Expires`/`Max-Age` або до закриття браузера | поки не видалять | поки відкрита **вкладка** | поки сервер не завершить |
| Розмір | ~4 KB | ~5 MB | ~5 MB | будь-який |
| Типові дані | id сесії, мова, згода на cookies | тема, чернетки, налаштування | крок майстра, дані форми | кошик, профіль, права доступу |

> [!NOTE]
> Цей застосунок зберігає твій прогрес у **localStorage** з ключем `qa-academy:progress`. Тому прогрес живе лише в цьому браузері, а Export / Import у Settings переносить його на інший комп'ютер.

## Атрибути cookies

| Атрибут | Значення | Що перевірити |
|---|---|---|
| `Expires` / `Max-Age` | коли cookie зникне | без них — «сесійний» cookie, зникає після закриття браузера |
| `HttpOnly` | JavaScript **не може** прочитати cookie | cookie сесії мають бути HttpOnly — захист від крадіжки через XSS |
| `Secure` | надсилається лише через HTTPS | для всього, що стосується входу |
| `SameSite` | чи надсилати з інших сайтів (`Strict`, `Lax`, `None`) | захист від CSRF |
| `Domain`, `Path` | для яких адрес діє | cookie staging не мають потрапляти на production |

## Що тестувати

- **Log out**: cookie сесії видалено, особисті дані з localStorage/sessionStorage прибрано, кнопка «Назад» не повертає в акаунт.
- **Remember me**: з галочкою — сесія переживає закриття браузера (cookie з `Expires`), без неї — ні.
- **Кілька вкладок**: вийшла в одній — що в іншій?
- **Чистий старт**: режим **інкогніто** або «Clear site data» в Application — як бачить сайт новий користувач.
- **Приватність**: у localStorage не повинно бути паролів, номерів карток, токенів з повним доступом.

## Кеш

Браузер **кешує** файли (CSS, JS, картинки), щоб не завантажувати їх щоразу. Після релізу частина користувачів може бачити **старі** файли — звідси баги «у мене працює, у тебе ні».

| Дія | Що робить |
|---|---|
| **Ctrl+F5** або **Ctrl+Shift+R** | перезавантажити без кешу |
| DevTools → Network → **Disable cache** | не використовувати кеш, поки відкрито DevTools |
| Application → **Clear site data** | видалити все: кеш, cookies, storage цього сайту |
| Вікно **інкогніто** | чистий браузер без старих даних |

> [!QA]
> Перед тим як заводити баг «після релізу нічого не працює», зроби жорстке перезавантаження (Ctrl+F5) або відкрий інкогніто. Якщо там працює — проблема в кеші. Це теж може бути баг (сайт мав правильно оновлювати файли), але його треба описати саме так.

## Підсумок

- HTTP без стану; стан зберігають cookies, localStorage, sessionStorage і серверні сесії.
- Cookies автоматично йдуть на сервер; storage — ні. sessionStorage живе лише у вкладці.
- Cookies сесії: `HttpOnly`, `Secure`, `SameSite`.
- Тестуй Log out, Remember me, кілька вкладок, чистий старт, приватність даних.
- Кеш: Ctrl+F5, Disable cache, Clear site data, інкогніто.
