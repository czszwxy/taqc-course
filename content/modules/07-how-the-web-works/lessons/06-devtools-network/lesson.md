# DevTools: Network

Інтерфейс може «брехати»: показати «Saved ✓», хоча на сервер пішли не ті дані, або тихо підставити заглушку замість картинки, яка не завантажилась. Вкладка **Network** показує правду: **кожен запит** сторінки і **кожну відповідь** сервера.

Практика — на сторінці [DevTools Lab](/playground/devtools), розділ «3. Network».

## Список запитів

Відкрий DevTools → **Network** і виконай дію на сторінці. Кожен рядок — один запит:

| Колонка | Що показує |
|---|---|
| **Name** | адреса запиту (path + query) |
| **Status** | статус-код: `200`, `201`, `404`, `500`… (червоні — помилки) |
| **Type** | `fetch` / `xhr` (дані), `document`, `script`, `stylesheet`, `img` |
| **Size** | розмір відповіді |
| **Time** | скільки тривав запит |

**Фільтри** зверху: `Fetch/XHR` залишає лише запити даних (найчастіше саме те, що потрібно), `Img` — картинки, рядок пошуку — фільтр за адресою.

## Деталі запиту

Клікни на рядок:

- **Headers** — URL, метод (`GET`, `POST`…), статус, заголовки запиту й відповіді (наприклад, `X-Request-Id`).
- **Payload** — query-параметри і **тіло запиту**: що саме фронтенд надіслав на сервер.
- **Preview / Response** — що повернув сервер (зазвичай JSON).
- **Timing** — з чого складається час запиту.

> [!QA]
> Порівнюй **три речі**: що показує інтерфейс, що пішло в **Payload** і що прийшло в **Response**. Якщо в формі стоїть галочка «Subscribe», а в payload `"newsletter": false` — це баг фронтенду, який неможливо побачити без DevTools.

## Корисні перемикачі

| Налаштування | Для чого |
|---|---|
| **Preserve log** | не очищати список під час переходу на іншу сторінку (наприклад, після відправки форми) |
| **Disable cache** | завантажувати все заново, як новий користувач |
| **Throttling** (No throttling → Slow 4G / 3G) | імітувати повільний інтернет: перевірити спінери, таймаути, подвійні кліки |
| **Offline** | що бачить користувач без мережі |
| Правий клік → **Copy → Copy as cURL** | скопіювати запит, щоб повторити його в терміналі чи Postman |
| **Export HAR** | зберегти всі запити у файл і прикласти до бага |

## Типові баги, які знаходять у Network

- Форма відправляє **не ті дані** або не всі поля.
- Фільтр в інтерфейсі вибрано, а в query-параметрах — інше значення.
- Запит повертає **4xx/5xx**, а інтерфейс мовчить або показує заглушку.
- **Зайві** або **дубльовані** запити (подвійний клік відправив замовлення двічі).
- Дуже **повільний** запит без індикатора завантаження.
- У відповіді є **зайві дані** (паролі, чужі email) — баг безпеки.

> [!TIP]
> У баг-репорт додавай: метод і URL запиту, статус-код, фрагмент payload або response, а для серверних помилок — значення заголовка `X-Request-Id` (за ним розробник знайде запис у логах).

## Підсумок

- Network показує всі запити: метод, URL, статус, тип, розмір, час.
- Payload = що надіслали; Response = що повернули. Порівнюй з інтерфейсом.
- Fetch/XHR-фільтр, Preserve log, Disable cache, throttling, Copy as cURL, HAR.
- Багато багів видно **лише** в Network: неправильні дані, приховані 404/500, дублікати.
