# Клієнт, сервер, URL і DNS

Кожен баг вебзастосунку живе або в **браузері** (клієнт), або на **сервері**, або «між ними» — у запиті чи відповіді. Тестувальник, який розуміє цю схему, пише точніші баг-репорти: «форма не відправляє поле», «сервер повертає 500», «сторінка не оновлює дані з кешу» — і розробник одразу знає, де шукати.

## Клієнт і сервер

```text
 Browser (client)                       Server
 ───────────────                        ──────
 1. You type a URL      ── request ──▶  2. Finds the page / data
 4. Renders the page    ◀── response ── 3. Sends HTML, JSON, images…
```

- **Клієнт** — програма, що *просить*: браузер, мобільний застосунок, Postman, автотест.
- **Сервер** — програма, що *відповідає*: віддає сторінки, зберігає дані, перевіряє паролі.
- Розмова йде через протокол **HTTP**: клієнт надсилає **request**, сервер повертає **response**.

> [!NOTE]
> Цей застосунок працює саме так: команда `npm run dev` запускає маленький **сервер** на твоєму комп'ютері, а браузер — **клієнт** — відкриває `http://localhost:5173`.

## Частини URL

```text
https://staging.gadgetly.com:8443/catalog/phones?sort=price&page=2#reviews
└─┬─┘   └────────┬─────────┘ └┬─┘└──────┬──────┘ └───────┬────────┘ └──┬──┘
protocol       domain (host) port      path            query        fragment
```

| Частина | Що означає | Приклад |
|---|---|---|
| **Protocol** (scheme) | як говорити з сервером | `https` (шифровано), `http` |
| **Domain / host** | ім'я сервера | `staging.gadgetly.com`, `localhost` |
| **Port** | «двері» на сервері; часто прихований | `443` для https, `80` для http, `5173` у нас |
| **Path** | який ресурс | `/catalog/phones` |
| **Query** | параметри після `?`, через `&` | `sort=price`, `page=2` |
| **Fragment** | місце на сторінці після `#`; **не** надсилається на сервер | `#reviews` |

> [!QA]
> Query-параметри — чудове місце для тестів: змінюй їх прямо в адресному рядку. `page=0`, `page=-1`, `page=abc`, `sort=unknown` — сайт має обробити це акуратно, а не впасти з помилкою.

## DNS — «телефонна книга» інтернету

Комп'ютери знаходять один одного за **IP-адресами** (наприклад, `93.184.215.14`). Людям зручніше імена. **DNS** перетворює `gadgetly.com` на IP-адресу. `localhost` — особливе ім'я, яке завжди означає «цей самий комп'ютер» (`127.0.0.1`).

## Що відбувається, коли вводиш URL

1. Браузер з'ясовує IP-адресу через **DNS**.
2. Встановлює з'єднання з сервером (для HTTPS — ще й шифроване, TLS).
3. Надсилає **HTTP-запит**: `GET /catalog/phones?sort=price`.
4. Сервер обробляє запит і повертає **відповідь**: статус (200, 404…) і HTML.
5. Браузер читає HTML, догружає CSS, JavaScript, картинки (це окремі запити!) і **малює** сторінку.

## HTTP vs HTTPS

**HTTPS** = HTTP + шифрування. Без нього паролі й картки передаються відкритим текстом. Для тестувальника: форми входу й оплати мають працювати **лише** через HTTPS, а браузер не повинен показувати попередження про сертифікат.

## Середовища

| Середовище | Для чого | Приклад URL |
|---|---|---|
| **Local / dev** | розробка на своєму комп'ютері | `http://localhost:5173` |
| **Staging / QA / test** | тестування перед релізом, копія production | `https://staging.gadgetly.com` |
| **Production (prod)** | справжні користувачі | `https://gadgetly.com` |

> [!WARNING]
> Завжди перевіряй, **де** ти тестуєш. Тестове замовлення на production — це справжнє замовлення. А в баг-репорті вказуй середовище: баг на staging може не відтворюватися на production.

## Підсумок

- Клієнт просить (request), сервер відповідає (response) через HTTP.
- URL = protocol + domain + port + path + query + fragment.
- DNS перетворює ім'я на IP-адресу; `localhost` — цей комп'ютер.
- Сторінка = багато запитів: HTML, CSS, JS, картинки.
- Розрізняй середовища: dev, staging, production.
