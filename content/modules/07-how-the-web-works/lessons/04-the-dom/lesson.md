# DOM — дерево сторінки

Коли браузер читає HTML, він будує в пам'яті **DOM** (Document Object Model) — дерево об'єктів, де кожен тег стає **вузлом**. Саме з DOM працюють JavaScript на сторінці, DevTools і автотести. Playwright не «читає HTML-файл» — він шукає елементи в **живому DOM**.

## Дерево і зв'язки

```text
ul.products                     ← parent (батько) для li
├── li.product-card             ← child (дитина) ul; sibling (сусід) іншим li
│   ├── h3  "Wireless Mouse"    ← descendant (нащадок) ul
│   └── span.price "499 UAH"
└── li.product-card
    ├── h3  "Gaming Mouse"
    └── span.price "1,299 UAH"
```

| Зв'язок | Значення |
|---|---|
| **parent** | безпосередній «власник» елемента |
| **child** | безпосередньо вкладений елемент |
| **sibling** | елементи з тим самим батьком |
| **ancestor / descendant** | будь-який рівень вище / нижче |

## HTML-код ≠ DOM

**View page source** (Ctrl+U) показує HTML, який прийшов із сервера. Вкладка **Elements** у DevTools показує **поточний DOM**: після того як JavaScript додав товари, відкрив модальне вікно, показав помилку.

> [!QA]
> Якщо в «View source» елемента немає, а в Elements він є — його додав JavaScript. Такі елементи з'являються **не одразу**: автотест має дочекатися їх (Playwright робить це автоматично), а ручний тестувальник — перевірити стан «ще завантажується».

## Видимий, прихований, відсутній

| Стан | Приклад | Є в DOM? | Бачить користувач? |
|---|---|---|---|
| Видимий | звичайна кнопка | так | так |
| Прихований CSS | `display: none`, `visibility: hidden`, атрибут `hidden` | так | ні |
| Службовий | `<input type="hidden" value="…">` | так | ні |
| Відсутній | модалка, яку ще не відкрили (не відрендерена) | **ні** | ні |

Прихований елемент можна знайти селектором, але клікнути не можна. Це часта причина помилок в автотестах: «елемент знайдено, але він не видимий».

## XPath — ще один спосіб шукати елементи

**XPath** описує шлях у дереві. Він складніший за CSS, але вміє те, чого CSS не вміє: шукати **за текстом** і ходити **вгору** по дереву.

| XPath | Значення | CSS-аналог |
|---|---|---|
| `//h3` | усі `h3` будь-де | `h3` |
| `//li[@class='sale']` | `li` з атрибутом class **рівним** `sale` | `li[class="sale"]` |
| `//li[contains(@class,'sale')]` | class **містить** `sale` | `li.sale` (приблизно) |
| `//input[@name='q']` | за атрибутом | `input[name="q"]` |
| `//button[text()='Checkout']` | за **точним текстом** | — |
| `//button[contains(text(),'Add')]` | текст **містить** | — |
| `//ul[@id='cart']/li` | прямі діти (`/`) | `#cart > li` |
| `//h3[text()='Sport Earbuds']/..` | **батько** елемента | — |
| `//h3[text()='Gaming Mouse X7']/following-sibling::span` | **наступні сусіди** | `h3 ~ span` (без умови на текст) |

> [!TIP]
> `//` — «будь-де нижче», `/` — «прямий дочірній», `@` — атрибут, `[...]` — умова, `..` — батько. У DevTools: Elements → `Ctrl+F` приймає і CSS, і XPath; у Console — `$x("//h3")`.

> [!WARNING]
> `@class='sale'` спрацює, лише якщо class **рівно** `sale`. Для `class="product-card sale"` потрібен `contains(@class,'sale')`. Пам'ятай: `contains(@class,'sale')` знайде також `class="wholesale"`.

## Підсумок

- DOM — живе дерево вузлів; DevTools і автотести працюють із ним, а не з HTML-файлом.
- Зв'язки: parent, child, sibling, ancestor, descendant.
- Елемент може бути в DOM, але прихованим; або ще не існувати.
- XPath: `//tag[@attr='v']`, `contains()`, `text()`, `/..` (батько), `following-sibling::`.
