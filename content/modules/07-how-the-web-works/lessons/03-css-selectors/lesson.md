# CSS і селектори

**CSS** (Cascading Style Sheets) відповідає за те, **як** виглядає сторінка: кольори, розміри, відступи, розташування. Для тестувальника CSS важливий з двох причин:

1. Багато візуальних багів — це помилки CSS: текст виходить за межі, кнопку не видно, елементи накладаються.
2. **CSS-селектори** — мова, якою автотести знаходять елементи на сторінці. Ти користуватимешся нею постійно.

## CSS-правило

```css
.btn-primary {            /* selector: WHICH elements */
  background: #f97316;    /* property: value — HOW they look */
  color: white;
  display: none;          /* the element is not shown at all */
}
```

## Базові селектори

| Селектор | Що знаходить | Приклад |
|---|---|---|
| `tag` | усі елементи з цим тегом | `button`, `h3`, `li` |
| `.class` | елементи з класом | `.product-card` |
| `#id` | елемент з id (має бути один) | `#email` |
| `[attr]` | елементи з атрибутом | `[disabled]` |
| `[attr="value"]` | атрибут з точним значенням | `[data-testid="submit"]`, `[name="q"]` |
| `[attr^="v"]` | значення **починається** з | `a[href^="https://"]` |
| `[attr*="v"]` | значення **містить** | `[class*="error"]` |
| `tag.class` | обидві умови разом (без пробілу!) | `li.sale`, `.product-card.sale` |

## Комбінатори: зв'язки між елементами

| Селектор | Значення | Приклад |
|---|---|---|
| `A B` (пробіл) | B **десь усередині** A (нащадок) | `.product-card .price` |
| `A > B` | B — **прямий** дочірній елемент A | `ul > li` |
| `A + B` | B **одразу після** A (сусід) | `label + input` |
| `A, B` | A **або** B | `h1, h2` |

## Псевдокласи

| Селектор | Значення |
|---|---|
| `:first-child`, `:last-child` | перший / останній серед братів |
| `:nth-child(2)` | другий серед братів |
| `:not(.old)` | усі, **крім** тих, що з класом `old` |
| `:disabled`, `:checked` | вимкнені поля / відмічені чекбокси |

> [!TIP]
> Пробіл у селекторі має значення! `.product-card.sale` — **один** елемент з обома класами. `.product-card .sale` — елемент `.sale` **всередині** картки.

## Який селектор хороший для автотесту?

Найкращі селектори **стабільні**: вони не ламаються, коли дизайнер змінює вигляд сторінки.

| Надійність | Приклад | Чому |
|---|---|---|
| ✅ найкраще | `[data-testid="add-to-cart"]` | атрибут спеціально для тестів |
| ✅ добре | `#email`, `[name="email"]` | ідентифікатори й імена полів змінюються рідко |
| ⚠️ обережно | `.btn-primary` | класи змінюються при редизайні |
| ❌ погано | `div > div:nth-child(3) > span` | будь-яка зміна верстки ламає тест |

> [!QA]
> Перевірити селектор можна прямо в DevTools: вкладка **Elements** → `Ctrl+F` → введи селектор, і браузер підсвітить збіги та покаже їх кількість. У Console: `document.querySelectorAll('.product-card').length`.

## Практика

У завданнях цього уроку ти пишеш селектори для фрагмента сторінки, а застосунок одразу **підсвічує** знайдені елементи. Селектор правильний, якщо знаходить **рівно** потрібні елементи: не більше й не менше.

## Підсумок

- CSS керує виглядом сторінки; багато візуальних багів — це проблеми CSS.
- Базові селектори: `tag`, `.class`, `#id`, `[attr="value"]`, `^=`, `*=`.
- Комбінатори: пробіл (нащадок), `>` (дитина), `+` (сусід), `,` (або).
- Найстабільніші селектори — `data-testid`, `id`, `name`; уникай довгих ланцюжків і `nth-child`.
