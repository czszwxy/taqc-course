# DevTools: Elements і Console

**DevTools** (інструменти розробника) вбудовані в кожен браузер. Для тестувальника це «рентген»: ти бачиш, що насправді відбувається під інтерфейсом. Половина фраз у хороших баг-репортах — «у Console помилка…», «у DOM поле має атрибут…» — береться саме звідси.

Практика — на сторінці [DevTools Lab](/playground/devtools).

## Як відкрити

| Дія | Клавіші (Windows) |
|---|---|
| Відкрити DevTools | **F12** або **Ctrl+Shift+I** |
| Вибрати елемент на сторінці | **Ctrl+Shift+C**, потім клік по елементу |
| Відкрити Console | **Ctrl+Shift+J** |
| Пошук у DOM (текст, CSS, XPath) | у вкладці Elements: **Ctrl+F** |

Те саме є в Firefox, Edge і Safari (у Safari спершу ввімкни меню Develop у налаштуваннях).

## Elements: DOM і стилі

- **Інспектувати**: клацни правою кнопкою на елементі → *Inspect*. Побачиш його в дереві DOM з усіма атрибутами.
- **Знайти приховане**: поля `type="hidden"`, елементи з `display: none` видно в Elements, хоч на сторінці їх немає.
- **Редагувати**: подвійний клік по тексту чи атрибуту. Корисно, щоб перевірити довгий текст, інший статус або **прибрати `disabled`/`maxlength`** і подивитися, чи захищає сервер.
- **Styles / Computed**: які CSS-правила діють, звідки береться колір, чому елемент прихований.
- **Перевірити селектор**: Ctrl+F у Elements → введи `.product-card` → побачиш «1 of 6».

> [!WARNING]
> Зміни в Elements існують лише у твоєму браузері до перезавантаження. Це інструмент дослідження, а не спосіб «полагодити» сайт.

## Console: повідомлення і команди

Console показує повідомлення сторінки:

| Тип | Колір | Що означає для QA |
|---|---|---|
| `error` | червоний | JavaScript-помилка або невдалий запит — **кандидат у баг** |
| `warn` | жовтий | попередження (застаріле API, повільний код) |
| `info` / `log` | звичайний | службова інформація (номер збірки, налагодження) |

А ще Console — це місце, де можна виконати JavaScript:

```text
document.title                              → title of the page
$$('.product-card').length                  → how many elements match a CSS selector
$x("//button[text()='Checkout']")           → elements found by XPath
document.querySelector('[name=email]').value → current value of a field
localStorage                                 → saved data (more in lesson 7)
```

> [!QA]
> Класичний баг: натискаєш кнопку — **нічого не відбувається**, або з'являється «Something went wrong». Відкрий Console: там часто є точна причина, наприклад `TypeError: Cannot read properties of undefined`. Скопіюй **текст** помилки в баг-репорт — розробник знайде проблему за хвилини.

## Disabled ≠ захищено

Якщо кнопка вимкнена атрибутом `disabled`, її можна ввімкнути в Elements. Якщо після цього дія **спрацьовує**, перевірка була лише на клієнті — це баг безпеки: сервер мав відхилити запит.

## Підсумок

- F12 → Elements (DOM і CSS) і Console (повідомлення і команди).
- Elements показує приховані елементи й атрибути; там можна тимчасово редагувати сторінку.
- Ctrl+F у Elements і `$$()` / `$x()` у Console перевіряють селектори.
- Червоні помилки в Console — важливий доказ для баг-репорту.
- Обмеження в інтерфейсі (`disabled`, `maxlength`) має дублювати сервер.
