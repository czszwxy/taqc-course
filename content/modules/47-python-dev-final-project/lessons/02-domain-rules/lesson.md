# Доменні правила на чистому Python

Перший крок — правила з брифу: хто й куди може перевести заявку, коли дедлайн, скільки коштує ремонт. Жодного FastAPI, жодної бази — лише функції, що приймають значення й повертають значення. Такий код найпростіше тестувати: на межу дедлайну не треба піднімати сервер, створювати таблиці й підміняти залежності.

> [!NOTE]
> Приклади в теорії — з іншої системи: **бібліотеки**, де книжки бронюють і видають. Правила Gadgetly Repairs ти напишеш сам(а) в задачах.

## Машина станів як дані

Переходи зручно зберігати **даними**, а не ланцюжком `if`. Таблиця з брифу перетворюється на словник «(звідки, куди) → хто може»:

```python
from enum import StrEnum


class Loan(StrEnum):
    RESERVED = "reserved"
    ON_LOAN = "on_loan"
    RETURNED = "returned"
    CANCELLED = "cancelled"


READER = "reader"
LIBRARIAN = "librarian"

MOVES = {
    (Loan.RESERVED, Loan.ON_LOAN): {LIBRARIAN},
    (Loan.RESERVED, Loan.CANCELLED): {READER, LIBRARIAN},
    (Loan.ON_LOAN, Loan.RETURNED): {LIBRARIAN},
}
```

`StrEnum` — це водночас enum і рядок: `Loan.ON_LOAN == "on_loan"` дає `True`, тому значення з бази чи JSON порівнюються без перетворень. А `Loan("lost")` кидає `ValueError`: невідомий статус — це помилка програміста або зламані дані, а не бізнес-правило.

## Дві різні помилки

«Не можна» буває двох видів, і клієнту API важливо їх розрізняти:

| Ситуація | Код помилки | HTTP пізніше |
|---|---|---|
| перехід існує, але не для твоєї ролі | `forbidden` | `403` |
| такого переходу немає взагалі | `invalid_transition` | `409` |

Доменна помилка несе **машинно-читаний код**, а не лише текст:

```python
class LoanError(Exception):
    def __init__(self, code):
        super().__init__(code)
        self.code = code


def move(current, new, role):
    roles = MOVES.get((Loan(current), Loan(new)))
    if roles is None:
        raise LoanError("invalid_transition")
    if role not in roles:
        raise LoanError("forbidden")
    return Loan(new)
```

`MOVES.get(...)` повертає `None` для відсутнього ключа — це «переходу немає». Порядок перевірок важливий: спершу «чи існує перехід», потім «чи можна тобі».

> [!TIP]
> Той самий словник відповідає й на питання інтерфейсу «які кнопки показати?»: пройди всі статуси в порядку оголошення enum і залиш ті, куди ця роль може перейти. Правило живе в одному місці, і кнопки ніколи не розійдуться з перевіркою.

## Дати в робочих днях

`date.weekday()` повертає 0 для понеділка … 4 для п'ятниці, 5 і 6 — субота й неділя. Свята — множина дат, яку передають параметром (так тест сам вирішує, які дні святкові):

```python
from datetime import date, timedelta

SATURDAY = 5


def is_open(day, holidays=frozenset()):
    return day.weekday() < SATURDAY and day not in holidays


def return_by(lent_on, days, holidays=frozenset()):
    day = lent_on
    while days > 0:
        day += timedelta(days=1)
        if is_open(day, holidays):
            days -= 1
    return day
```

Крок по одному дню з лічильником — простий і надійний спосіб: цикл сам пропустить вихідні, свята і кінець місяця. Головне питання брифу — **чи рахується перший день**. Тут — ні: спершу `day += 1`, потім перевірка.

| Видано | Днів | Крок за кроком | Повернути до |
|---|---|---|---|
| пн 16.11 | 2 | вт (1), ср (2) | ср 18.11 |
| чт 19.11 | 2 | пт (1), сб, нд, пн (2) | пн 23.11 |
| сб 21.11 | 1 | нд, пн (1) | пн 23.11 |

«Прострочено» — окреме правило з двома умовами: дата **і** стан. Порівняння `today > due` означає, що в сам день дедлайну ще вчасно, а `>=` — уже ні. Це рішення з брифу, і саме його найчастіше ламають.

## Гроші: цілі числа й округлення

Гривні — цілі числа (`int`), без `float`: `0.1 + 0.2 != 0.3`, а сума кошторису має бути точною. Коли платять «за кожен розпочатий блок», потрібне округлення **вгору**:

```python
import math

math.ceil(16 / 15)   # 2 — розпочато другий блок
16 // 15             # 1 — ділення націло округлює вниз
```

Для результату розрахунку зручний незмінний `@dataclass(frozen=True)`: його не змінить випадково ні API, ні тест, а `==` порівнює всі поля одразу:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Fine:
    days_late: int
    amount: int
```

## Тести на межі

Для кожного числового правила перевіряй **пару** значень по обидва боки межі:

| Правило | Пара |
|---|---|
| день дедлайну | `today == due` (вчасно) і наступний день (прострочено) |
| блок 15 хвилин | 15 → 1 блок, 16 → 2 блоки |
| перший день не рахується | прийом у понеділок, а не в п'ятницю |
| вихідні | прийом у середу з дедлайном після вихідних |

Значення «посередині» (30 хвилин, дедлайн через тиждень) проходять і на правильному, і на зламаному коді, тому багів не ловлять.

> [!QA]
> Останнє завдання уроку — тести в режимі мутацій: твої тести мають «впасти» на кожній зламаній версії правил. Мутанти — типові помилки з код-рев'ю: `>=` замість `>`, забуте свято, `//` замість `ceil`.

## Підсумок

- Машину станів зберігай даними: словник «(звідки, куди) → ролі»; ним же будуються кнопки інтерфейсу.
- Розрізняй `forbidden` (перехід є, роль не та) і `invalid_transition` (переходу немає); помилка несе `code`.
- Робочі дні: крок по одному дню, `weekday() < 5`, свята — параметром; явно виріши, чи рахується перший день.
- Гроші — `int`; «за кожен розпочатий блок» — `math.ceil`; результат — `frozen` dataclass.
- Тести на межі — парою значень з обох боків.
