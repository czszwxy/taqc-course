# JavaScript і TypeScript: як виконується код

Автотест — це **програма**, яка замість людини відкриває сторінку, клікає, вводить дані й перевіряє результат. Щоб писати такі програми, потрібна мова програмування. У сучасній автоматизації вебтестування найпопулярніша зв'язка — **TypeScript + Playwright**. З цього уроку починається шлях до неї.

## JavaScript — мова вебу

**JavaScript (JS)** — мова, яку розуміє кожен браузер. Саме JS робить сторінки «живими»: показує помилки під полями форми, відкриває меню, надсилає дані на сервер.

JS виконується у двох основних місцях:

| Де | Що це | Приклад |
|---|---|---|
| **Браузер** | Chrome, Firefox, Edge мають вбудований «рушій» JS | код сайту, який ти тестуєш |
| **Node.js** | програма, що запускає JS на комп'ютері, без браузера | автотести, скрипти, сервери |

Playwright-тести запускаються саме в **Node.js** і звідти керують браузером.

## TypeScript = JavaScript + типи

**TypeScript (TS)** — це JavaScript, до якого додали **типи**. Тип описує, яке значення може зберігатися: рядок (`string`), число (`number`), так/ні (`boolean`) тощо.

```ts
const testsPassed: number = 42;   // ✅ число — все добре
const testsFailed: number = 'три'; // ❌ TypeScript підкреслить помилку ще ДО запуску
```

Браузер і Node.js не розуміють TS напряму. Тому TS-код спершу **компілюється** (перекладається) в звичайний JS:

```text
твій код .ts  →  компілятор TypeScript (tsc)  →  код .js  →  виконується
                       ↑
              тут знаходяться помилки типів
```

> [!QA]
> Для тестувальника TypeScript — це як автоматична перевірка твоїх же автотестів. Опечатку в назві змінної або число замість рядка компілятор знайде ще до запуску, а не через годину у звіті CI.

### Чому саме TypeScript для автоматизації

- Playwright написаний на TypeScript, і в його документації всі приклади на TS.
- Редактор (VS Code) **підказує** доступні методи та їхні параметри, бо знає типи.
- Більшість вакансій Trainee/Junior QA Automation з JS-стеком вимагають саме TS.

## Як виглядає програма

Програма — це послідовність **інструкцій** (statements), які виконуються зверху вниз:

```ts
// Це коментар: його бачить людина, а комп'ютер ігнорує
console.log('Test run started'); // виводить текст у консоль
console.log(2 + 3);              // виведе 5

/*
  Багаторядковий коментар.
  Зручний для довгих пояснень.
*/
```

- `console.log(...)` — виводить значення в **консоль**. Це головний інструмент, щоб «підглянути», що відбувається в коді.
- Текст береться в лапки: `'одинарні'` або `"подвійні"` — це **рядок** (string).
- `;` у кінці інструкції не обов'язкова, але в цьому курсі ми її ставимо: так код однозначніший.

## Функція: перший погляд

У задачах ти постійно бачитимеш **функції**. Детально їх розберемо в уроці «Functions». Поки достатньо знати, що функція — це іменований шматок коду, який можна викликати:

```ts
export function getStatus(): string {
  return 'PASSED';
}
```

Розберімо по частинах:

| Частина | Значення |
|---|---|
| `export` | робить функцію доступною ззовні: так її бачать **тести** |
| `function getStatus()` | оголошення функції з назвою `getStatus` |
| `: string` | функція **повертає** рядок |
| `{ ... }` | тіло функції — код, що виконується |
| `return 'PASSED';` | повернути значення тому, хто викликав функцію |

> [!IMPORTANT]
> Не прибирай `export` і не перейменовуй функції в задачах: приховані тести шукають їх саме за цими іменами.

## Як працюють задачі в цьому застосунку

Кожна задача з кодом має редактор (той самий Monaco, що й у VS Code) і дві кнопки:

- **▶ Run** — просто запускає твій файл. Усе, що ти виведеш через `console.log`, з'явиться у вкладці **Console**. Зручно, щоб експериментувати.
- **✓ Check** (або `Ctrl+Enter`) — справжня перевірка:
  1. **компілятор TypeScript** шукає помилки типів у strict-режимі;
  2. **приховані тести** викликають твої функції з різними даними й порівнюють результат з очікуваним.

Задача зарахована, коли немає помилок компіляції і всі тести зелені. Для кожного проваленого тесту ти побачиш, що очікувалось, що вийшло, і підказку автора.

> [!TIP]
> Червоні хвилясті підкреслення в редакторі — це TypeScript підказує проблему. На початку задачі вони нормальні: наприклад, функція ще нічого не повертає. Наведи мишку на підкреслення, щоб прочитати повідомлення.

Якщо застрягнеш:

1. Відкрий **Hint 1**, потім **Hint 2**: підказки відкриваються по одній і з кожною стають конкретнішими.
2. Після невдалої спроби з'являється блок **How to approach it** з поясненням підходу.
3. Кнопка **Try a similar task** дасть схожу задачу на ту саму тему, щоб закріпити навичку.
4. Рішення автора відкривається після 3 спроб. Твоє рішення може відрізнятися й бути правильним.

## (Необов'язково) Запуск TS на своєму комп'ютері

Усі задачі цього модуля виконуються прямо в браузері. Але щоб звикати до реального інструментарію, можна запускати код і локально:

```bash
# 1. Перевір, що Node.js встановлено
node -v

# 2. Створи файл hello.ts з рядком: console.log('Hello, QA!');
# 3. Запусти його без окремої компіляції за допомогою tsx
npx tsx hello.ts
```

Редактор для реальних проєктів — **VS Code** (безкоштовний). До Playwright ми повернемося в треку автоматизації, і там знадобиться саме локальне середовище.

## Підсумок

- **JavaScript** виконується в браузері та в Node.js; **TypeScript** — це JS з типами, який компілюється в JS.
- Компілятор TypeScript знаходить помилки **до запуску** коду.
- `console.log` виводить значення, коментарі (`//`, `/* */`) — для людей.
- `export function name(): type { return ...; }` — шаблон, який ти бачитимеш у задачах.
- **Run** — запустити, **Check** — перевірити компілятором і тестами.
