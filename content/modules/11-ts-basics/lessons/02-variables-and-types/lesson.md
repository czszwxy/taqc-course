# Змінні та примітивні типи

Тест майже завжди працює з **даними**: email для реєстрації, очікувана сума кошика, кількість товарів, статус-код відповіді API. Щоб зберігати й використовувати ці дані, потрібні **змінні**.

## Що таке змінна

Змінна — це іменована «коробка» зі значенням. В TypeScript змінні оголошують словами `const` або `let`:

```ts
const userEmail = 'qa@example.com'; // const: значення не змінюватиметься
let failedTests = 0;                 // let: значення змінюватиметься

failedTests = failedTests + 1;       // ✅ можна, бо let
userEmail = 'other@example.com';     // ❌ помилка: Cannot assign to 'userEmail' because it is a constant
```

| Слово | Коли використовувати |
|---|---|
| `const` | **за замовчуванням**: значення задається один раз |
| `let` | лише коли значення справді треба перезаписувати (лічильники, накопичення) |
| `var` | застарілий спосіб, у сучасному коді **не використовуємо** |

> [!TIP]
> Правило: пиши `const`, а на `let` міняй тоді, коли TypeScript скаже, що треба перезаписати значення. Так менше випадкових змін даних.

### Як називати змінні

- **camelCase**: перше слово з малої, наступні з великої: `loginAttempts`, `isUserBlocked`, `expectedTotal`.
- Назва має пояснювати зміст: `maxRetries` краще, ніж `x` або `n2`.
- Регістр важливий: `total` і `Total` — **різні** змінні.
- Логічні змінні часто починаються з `is`, `has`, `can`: `isVisible`, `hasErrors`.
- Не можна починати з цифри та використовувати пробіли чи дефіси: `2fa`, `test case`, `max-retries` — помилки.

## Примітивні типи

**Примітивні** (базові) типи описують одне просте значення:

| Тип | Що зберігає | Приклади |
|---|---|---|
| `string` | текст | `'Login'`, `"admin@test.com"`, `''` (порожній рядок) |
| `number` | будь-які числа: цілі й дробові | `42`, `-1`, `19.99`, `0` |
| `boolean` | логічне так/ні | `true`, `false` |
| `null` | «значення навмисно відсутнє» | `null` |
| `undefined` | «значення ще не задано» | `undefined` |

Є ще `bigint` (дуже великі цілі числа) і `symbol`, але в тестах вони майже не трапляються.

> [!WARNING]
> `'25'` і `25` — це різні значення: перше рядок, друге число. Так само `'true'` не дорівнює `true`. На цьому ламається багато форм та API, тому TypeScript і перевіряє типи.

## Анотації типів і виведення типів

Тип можна вказати явно через двокрапку. Це **анотація типу** (type annotation):

```ts
const baseUrl: string = 'https://staging.example.com';
const timeoutMs: number = 30000;
const headless: boolean = true;
```

Але найчастіше TypeScript **сам виводить тип** зі значення (type inference):

```ts
let retries = 3;     // TypeScript знає: retries має тип number
retries = 'three';   // ❌ Type 'string' is not assignable to type 'number'
```

Коли писати анотацію явно?

- коли змінна оголошується **без значення**: `let status: string;`
- у **параметрах функцій**: там TypeScript не може здогадатися (це буде в уроці Functions);
- коли хочеш показати намір, як у задачах цього уроку.

### Літеральні типи коротко

Для `const` TypeScript виводить ще точніший тип — саме значення:

```ts
const env = 'staging'; // тип: 'staging' (літеральний тип)
let env2 = 'staging';  // тип: string
```

Поки просто запам'ятай, що так буває. До літеральних типів повернемося в модулі «Types & Data».

## Оператор typeof

`typeof` повертає **назву типу** значення у вигляді рядка. Зручно, щоб перевіряти дані:

```ts
console.log(typeof 'hello'); // 'string'
console.log(typeof 42);      // 'number'
console.log(typeof true);    // 'boolean'
console.log(typeof undefined); // 'undefined'
console.log(typeof null);    // 'object'  ← історична дивина JavaScript
```

## Склеювання рядків

Оператор `+` з рядками **склеює** їх (конкатенація):

```ts
const name = 'Login';
const count = 5;
console.log(name + ' tests: ' + count); // 'Login tests: 5'
```

Якщо один з операндів рядок, число автоматично перетворюється на рядок. Зручніший спосіб, шаблонні рядки, буде в уроці Strings.

## Обчислення зі змінними

Змінні можна використовувати у виразах, і результат зберегти в нову змінну:

```ts
const totalTests = 120;
const passedTests = 114;
const failedTests = totalTests - passedTests; // 6

let bugsOpen = 10;
bugsOpen = bugsOpen - 3; // 7 — перезаписуємо, тому let
```

> [!QA]
> Не «хардкодь» результати, які можна обчислити. Якщо `failedTests = 6` записано вручну, а потім хтось змінить `totalTests`, дані розійдуться. В автотестах те саме: очікуване значення краще рахувати з тестових даних.

## `any`: чого уникати

Тип `any` вимикає перевірку типів: туди можна покласти що завгодно. Здається зручно, але так ти втрачаєш головну перевагу TypeScript. У цьому курсі `any` **не використовуємо**. Для «невідомого» значення є безпечніший `unknown`, про нього пізніше.

## Підсумок

- `const` за замовчуванням, `let` коли треба перезаписувати, `var` не використовуємо.
- Примітиви: `string`, `number`, `boolean`, `null`, `undefined`.
- Анотація `: type` задає тип явно, інакше TypeScript **виводить** його зі значення.
- `typeof value` повертає назву типу рядком.
- `'5'` — не те саме, що `5`.
