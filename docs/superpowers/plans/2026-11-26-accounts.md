# User accounts (Supabase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Personal accounts (sign up with email or login only, sign in with login or email) whose progress and settings sync to Supabase, while signed-out use stays as today.

**Architecture:** localStorage stays the working copy. A new `src/features/account/` adds a lazily loaded supabase-js client, sign up / in / out, and an account sync that reuses the gist sync's merge (`combine` moves to merge.ts) with an optimistic `rev` check. One SQL migration holds tables, row level security, a sign-up trigger and two lookup functions.

**Tech Stack:** React 19 + zustand (existing), `@supabase/supabase-js` 2.x, Supabase CLI (`supabase` devDependency) + Docker Desktop for the local stack, Playwright Test for end to end.

**Spec:** `docs/superpowers/specs/2026-11-26-accounts-design.md`

## Global Constraints
- UI English; QA Notebook style (`.page`, `.card`, `.btn*`, `.input`, `Callout`, `font-display`, one `.hand` note at most); ink icons from `components/icons.tsx`, no emoji in chrome.
- Code style hook: no nested ternaries, no magic numbers (named consts), prefer map/filter/reduce.
- Stand-in auth address: `${login}@users.my-university.invalid`.
- Login: lowercase after trim, `^[a-z0-9][a-z0-9._-]{2,29}$`. Names: trimmed, 1–50 chars. Password: ≥ 8 chars. Email: optional, trimmed + lowercased, unique.
- Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` in committed `.env`; empty → accounts off, no account UI.
- supabase-js only via dynamic `import()`.
- Never rename content folders; never change the dev port 5173 (tests use another port).
- Works at 375 px; nothing wider than the screen.
- Commit only files this work touches (other sessions have uncommitted work in the tree).

## Review Focus
1. Two devices / tabs save at the same moment → neither change is lost (rev conflict → re-read, merge, retry). Pinned in Task 5.
2. The account is deleted in the dashboard or its session ends while signed in → the app keeps the local progress and asks to sign in again. Pinned in Task 5.
3. Signing out while offline → a warning before unsynced work is dropped from this browser. Pinned in Task 5.
4. Login typed as `  Anna_K ` at sign-in or sign-up → treated as `anna_k`. Pinned in Task 1.
5. Supabase unreachable (paused project) at start → the app opens and works signed out / with local progress. Pinned in Task 5.

### Task 3: Client, sign up / in / out, account sync

**Files:**
- Create: `src/features/account/client.ts`, `src/features/account/auth.ts`, `src/features/account/accountSync.ts`
- Modify: `src/features/progress/store.ts` (settings `updatedAt` set by every setter; `importSettings(s: SyncedSettings)`), `src/features/sync/sync.ts` (`useAutoSync` and `isSyncConnected` false while signed in), `src/pages/SettingsPage.tsx` (Import / Reset call `accountSyncNow('replace')` when signed in), `src/app/Layout.tsx` (mount `useAccountSync()`)

**Interfaces:**
- client.ts: `ACCOUNTS_ENABLED: boolean`, `getSupabase(): Promise<SupabaseClient>` (one cached client).
- auth.ts: `class AccountError extends Error { field?: keyof FieldErrors }`; `signUp(form: SignUpForm, addDeviceProgress: boolean): Promise<void>`; `signIn(identifier: string, password: string, addDeviceProgress: boolean): Promise<void>`; `signOut(force?: boolean): Promise<'done' | 'unsynced'>`. Messages: login taken → "This login is taken. Try another one." (field login); email taken → "An account with this email already exists. Sign in instead." (field email); wrong credentials (unknown email too) → "Wrong login/email or password."; 429 → "Too many attempts. Wait a minute and try again."; fetch failure → "No connection. Check the internet and try again."
- accountSync.ts: persisted store `useAccount` (key `my-university:account`): `{ user?: { id, login, firstName, lastName, email? }, rev?: number, epoch?: string, savedHash?: string, lastSyncedAt?: string, status: 'idle'|'syncing'|'ok'|'error', error?: string }`; guest stash key `my-university:guest` (`{ progress: ProgressData, settings: SyncedSettings }`); `accountSyncNow(mode?: SyncMode): Promise<void>`; `useAccountSync(): void`; `isSignedIn(): boolean`.
- Sync step: read `rev`; equal to stored rev and `hashText(stableStringify({data, epoch, settings}))` equals `savedHash` → done; equal but changed → `update … eq('rev', rev)` with `rev + 1`; different (or first sync) → read the row, `combineProgress` (first sync: local epoch := remote epoch), `newerSettings`, apply locally, write with the read rev; 0 rows updated → retry, at most 3 times.
- Synced settings also carry the Workdesk daily goal (`src/features/workdesk/goal.ts`, key `my-university:goal`, `{ goal: 1 | 3 | 5 }`, built by the design session). Never sync `my-university:workdesk-seen` (per-device animation state).
- Sign in / up: stash guest progress + settings; working copy := guest (if adding) or empty; then `accountSyncNow()`. Sign out: `accountSyncNow()`; on error return `'unsynced'` unless `force`; then `auth.signOut()`, restore stash, clear `useAccount`.
